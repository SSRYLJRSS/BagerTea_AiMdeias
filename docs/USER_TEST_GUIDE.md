## TL;DR

1. **这份文档怎么用**：把自己当成「刚下载了茶包素材的真实用户」，按第三节的画像挑一个角色代入，然后照着第四节的 8 条旅程剧本一步一步点。每一步都写了**预期现象**和**异常判定**——只要实际表现和「异常判定」对上号，就是一个 Bug，立刻记进第六节的模板。
2. **与 TEST_STRATEGY.md 的分工**：那边管「代码层怎么测」（147 个自动化用例、回归矩阵、性能探针、fixtures 数据集），这边管「人肉怎么测」。技术细节一律引用对方章节不再展开：
   - 格式/边界/历史 Bug 的来龙去脉 → TEST_STRATEGY.md §二、§3.1
   - 性能量化指标出处 → PERFORMANCE.md（本文只做口语化转译，见第五节）
   - 测试数据样本清单 → TEST_STRATEGY.md §5.1
   - 手工走查的功能点全集 → TEST_STRATEGY.md §四（本文的旅程剧本是它的「串起来的故事版」）
3. **核心覆盖**：8 条端到端旅程（约 130 个检查步骤）+ 16 条手滑/异常场景 + 9 条体感验收标准。全部基于产品现有功能编写，不含未交付功能（网盘导出为二期置灰、音频/语义搜索不存在）。
4. **执行顺序建议**：①首次安装 → ②批量入库 → ③浏览检索 是主干必跑；④⑤打标两条选一条主线（有 API Key 走④，没有走⑤）；⑥⑦⑧任意穿插。全程约半天。
5. **一句话纪律**：测试中产生的所有「意外」都要记录，哪怕你不确定是不是 Bug——真实用户的崩溃和困惑不会自己区分严重度。

## 二、用户画像与典型场景

> 测试时挑一个角色代入，用 TA 的心态和节奏操作：小白会乱点，摄影师没耐心，自媒体人手速飞快。

### 画像 1：阿伟 · 婚礼摄影师（重度用户）

- **特征**：周末拍一场婚礼回来 2000 张 RAW+JPG，硬盘乱成一锅粥；只想要「快入库、找得到、能交片」。
- **一天的使用旅程**：早上把两张 SD 卡的内容拖进入库页 → 填分库名「0621 婚礼」套改名模板 → 开始入库顺便泡咖啡 → 回来看成功/失败统计 → 在素材库里按时间倒序粗筛废片 → 双击大图逐张过 → AI 打标跑一批「人物/场景」建议快速确认 → 下午把精修候选 80 张按 by_date 导出给修图师。
- **最在意**：RAW 缩略图出得快不快？2000 张拖进去会不会卡死？导出 CSV 客户能不能打开？

### 画像 2：小鹿 · 自媒体图文博主（中度用户）

- **特征**：手机+电脑双端截图狂魔，素材全是 `Screenshot_20260822_103455.png` 这种鬼名字；想靠 AI 打标 + 中文搜索救自己的素材库。
- **一天的使用旅程**：中午批量导入上周截图 → 给几张关键图手动挂标签 → 配好 API Key 让云端 AI 批量打标 100 张 → 逐张确认建议（拒绝掉离谱的，误拒了一张赶紧恢复）→ 下午写稿时搜「咖啡店 桌面」秒出图 → 选中 6 张导出到公众号素材文件夹。
- **最在意**：中文搜索准不准？AI 标签离谱吗？误拒了还能反悔吗？

### 画像 3：老周 · 数码小白（新手用户）

- **特征**：儿子帮忙装的软件，自己只会双击和拖拽；不知道什么是 API Key 和 Ollama，但对「一键」两个字有好感。
- **一天的使用旅程**：第一次打开应用看到空库不慌（有空状态提示）→ 把桌面文件夹整个拖进入库 → 看到重复文件提示能看懂 → 点底栏三个按钮到处逛逛 → 尝试设置页里的「本地 AI 一键部署」跟着向导走完 → 用默认推荐模型给自己的猫照片打了标签 → 最后试着删了一张不要的图并去回收站找了找。
- **最在意**：每一步都有没有人告诉我该干嘛？出错的时候说的是人话吗？删错了还能找回吗？

## 三、端到端用户旅程测试剧本

> **格式说明**：每条旅程 = 编号步骤 → ✅预期现象（正常应该看到的）/ ⚠️异常判定（出现这种情况就是 Bug）。执行时边操作边勾选，发现 ⚠️ 立即记入第六节模板。

### 旅程①：首次安装启动（空库第一印象）

前置：干净环境（无旧数据目录）、本机未装 Ollama。

| # | 步骤 | 预期现象 ✅ | 异常判定 ⚠️ |
|---|---|---|---|
| 1-1 | 双击安装包完成安装，首次启动应用 | 窗口正常打开，黑白灰极简风格，无明显卡顿 | 白屏超过 3 秒 / 闪退 / 报错弹窗带错误码堆栈 |
| 1-2 | 观察空库状态 | 底部仅 3 个纯文字按钮：「入库」「素材库」「AI 打标」，当前页高亮；内容区有空状态引导文案，不是一片死白 | 底栏多于/少于 3 个入口；空白页无任何提示让人不知所措 |
| 1-3 | 依次点三个底栏入口 | 每页都能进且空状态友好：入库页有大拖拽区；素材库页空网格；打标页工作台空批次 | 任一页面报错 / 卡加载动画不放 / JS 白屏 |
| 1-4 | 点左上角设置按钮 | 进入设置页，左侧分组导航齐全（AI 打标 / 入库与总库 / 网盘 / 通用外观 / 数据与缓存）；保存按钮在最后一项之后 | 分组缺失；网盘分组显示为可用状态（应为置灰/标注二期）；保存按钮位置突兀 |
| 1-5 | 设置 → 入库与总库，配置总库位置到 `D:\BagerLib`（新建） | 保存成功；数据与缓存页能看到数据目录并可「打开所在文件夹」 | 保存后无反馈 / 再进来配置丢了 / 打不开文件夹 |
| 1-6 | 设置 → 通用外观，依次切 light / dark / system | 主题立即切换无重启；system 跟随系统深浅色 | 切换后局部区域颜色错乱（漏网的硬编码色块） |
| 1-7 | 关闭应用重新打开 | 总库配置、主题等设置保留 | 任何设置静默丢失（⚠️ 高优先） |

### 旅程②：第一次批量入库（两段式确认是灵魂）

前置：完成旅程①；素材包 A + B + E 就绪。

| # | 步骤 | 预期现象 ✅ | 异常判定 ⚠️ |
|---|---|---|---|
| 2-1 | 从资源管理器框选 30 张图拖进入库页拖拽区 | 文件进入**待入库清单**，左侧任务栏统计图片数/总大小正确；**此时素材库和磁盘没有任何变化** | 拖进去就直接入库了（违反两段式设计）/ 统计数字错误 |
| 2-2 | 清单右上角切列表/网格双视图 | 列表模式纯文字行；网格模式缩略图懒加载 | 网格视图一次全量渲染导致卡顿 |
| 2-3 | 左侧填分库名「旅行」，用占位符按钮构造器点 `{分库}` `{序号}` 并把序号位数改成 4 | 模板按点击顺序以 `_` 拼接，实时预览首文件名形如 `旅行_0001.jpg`；再点已选中的 token 可取消 | 预览不刷新 / 位数输入无效 / token 无法取消选中 |
| 2-4 | 点「开始入库」 | 进度可见，每张卡片**立即**有占位缩略图；结束后汇总「成功 N、失败 M、重复 K」 | 占位图长时间空白 / 页面冻结无法取消 / 统计与实际不符 |
| 2-5 | 入库中途点取消 | 提示类似「用户取消（已导入 N 条，重复 M 条）」；库内记录与磁盘托管文件一一对应（不多不少） | 取消后出现「库里有记录但文件不存在」或反之的悬空状态 |
| 2-6 | 到 `D:\BagerLib\旅行\` 查看磁盘 | 文件已按改名模板重命名复制至此，**源文件仍在原位**（托管复制） | 源文件被移走了 / 改名模板没生效 / 文件名出现非法字符原样保留 |
| 2-7 | 再次拖入同一批文件并开始入库 | 全部识别为「重复 K」，不产生新库记录 | 重复文件被二次入库 |
| 2-8 | 拖入捣乱包 E（exe/pdf/txt/0字节jpg/截断jpg） | exe/pdf/txt 被白名单拦下不入库或有明确不可入库提示；0 字节/截断 jpg 单条计失败且错误明细可读，其余文件不受影响 | 应用崩溃 / 损坏文件被静默吞掉计数为成功 / 一个坏文件卡住整批 |
| 2-9 | 两份内容相同的图（异名）一起入库 | 后者识别为重复（哈希去重），两条不都落库 | 内容相同文件双双入库 |
| 2-10 | 入库完成后点跳转素材库 | 网格展示全部新素材，占位缩略图即显 | 跳转后网格为空 / 需手动刷新才出现 |
| 2-11 | （加分项）用 U 盘上的文件走一遍 2-1，开始入库中途直接拔掉 U 盘 | 该批失败项计入 failed 且明细可读，其余成功项完好；应用不崩溃 | 应用假死 / 成功计数虚增（把没拷完的算成功） |

### 旅程③：日常浏览检索（搜索是这个产品下功夫最多的地方）

前置：旅程②已完成；素材包含 `海边日落.jpg`、`IMG_2024_001.jpg`、`进度100%.jpg`。

| # | 步骤 | 预期现象 ✅ | 异常判定 ⚠️ |
|---|---|---|---|
| 3-1 | 快速滚动素材库网格（F 大库包更佳） | 滚动跟手不发飘；占位图即时显示，高清图淡入替换且闪白 ≤1 秒；快速滚动停止后画面无长期白块 | 滚动一顿一顿像拉风箱 / 白块超过 1 秒不补 / 内存随滚动持续暴涨 |
| 3-2 | 搜「海边」 | 命中 `海边日落.jpg` 且命中词高亮 | 无高亮 / 结果错 |
| 3-3 | 搜「海边日落」四字短语 | 命中同一张；且**不**误伤不相邻组合（若库里有 `上海湖边.jpg`，搜「海边」不应命中它） | 出现相邻字误命中（经典坑，详见 TEST_STRATEGY.md §3.1） |
| 3-4 | 搜 `202`、搜 `photo` | 命中 `IMG_2024_001.jpg` 等数字字母混合名（ASCII 子串搜索） | 搜 `202` 没结果（历史 BUG-A 已修复，此处是回归防线） |
| 3-5 | 对 `进度100%.jpg` 分别搜 `100%`、`度` | 都命中（中文与数字字母粘连搜索） | 任一不命中（BUG-B 回归线） |
| 3-6 | 搜纯标点 `!!!`、含引号的词、超长短语（粘贴一整句） | 返回空或合理结果，绝不崩溃、绝不报 FTS 语法错 | 弹出数据库错误 / 应用卡死 |
| 3-7 | 连续快速输入「海边日落的特写」逐字打 | 输入停顿后才查询（防抖），界面不闪烁不连发请求 | 每敲一个字就全屏刷新一次 |
| 3-8 | 左侧类型区依次切 全部/图片/视频/未打标 | 计数与实际分布一致；筛选切换流畅 | 计数对不上 / 「未打标」入口点了没反应 |
| 3-9 | 标签树：点父标签「风景」 | 连带筛出自身+子标签全部素材，父标签数量 = 合计值；▸/▾ 折叠展开正常且折叠不丢当前筛选 | 点父标签只出部分子标签素材 / 计数虚高 |
| 3-10 | 多标签筛选 any/all 各试一遍 | any=任一命中，all=全部命中；调换勾选顺序结果一致 | all 表现得像 any / 结果随勾选顺序变化（BUG-D 回归线） |
| 3-11 | 排序按 时间/大小/分辨率 各升降序切一遍 | 顺序正确稳定，来回切换不抖动 | 排序无效 / 同值素材每次刷新位置乱跳 |
| 3-12 | 选中交互全套：单击→再击同张→Ctrl 加减选→Shift 范围选→Ctrl+A→Ctrl+I→Esc | 独占选中再击取消；范围选连续正确；全选/反选正确；Esc 与点空白清空选中；顶栏「已选中 N 项」数字始终准确 | Shift 锚点漂移 / 反选后计数错误 / 快捷键在搜索框聚焦时抢触发 |
| 3-13 | 右键卡片 / 右键空白处 | 卡片菜单含 打标(AI/手动)/导出/删除/复制路径/打开所在文件夹；空白菜单含 全选/反选/取消选择；Esc 关菜单；点击菜单内部按钮菜单不提前消失 | 菜单项缺失 / 点菜单内按钮菜单先关了导致操作丢失 |
| 3-14 | 双击一张 JPG 进查看器 | 全屏淡入缩放进场；Alt+滚轮以光标为锚缩放（0.2~10×）；中键拖拽平移；右键按住临时放大松开恢复；←→ 过片近尾自动翻页；Esc 退回网格 | 缩放中心漂移 / 过片越界 / Esc 无响应 |
| 3-15 | 双击 H.264 mp4 | 内嵌播放器直接播放，原生 controls 可控 | 黑屏无提示 |
| 3-16 | 双击 HEVC mp4 | 降级调起系统播放器（或明确提示），不崩不黑屏卡死 | 无任何反应也无提示 |

### 旅程④：云端 AI 打标全流程（人机协作，用户握控制权）

前置：旅程②完成；已申请一个 OpenAI 兼容中转站的 base_url + API Key。

| # | 步骤 | 预期现象 ✅ | 异常判定 ⚠️ |
|---|---|---|---|
| 4-1 | 设置 → AI 打标 → 新增档案：填名称、选 API Mode（OpenAI 兼容）、base_url、API Key，模型自动拉取下拉 | 模型列表自动拉出可选；保存后档案出现在列表且可点选激活；重进设置回显完整（Key 明文回显为已知问题不算新 Bug） | 模型拉取失败时无手输兜底 / 保存后配置丢失 |
| 4-2 | 故意把 Key 改错一位再保存并跑一次打标 | 单条/批次失败有明确错误信息（401 类），UI 不卡死；改回正确 Key 可继续 | 错误无提示像「成功」/ 应用假死 |
| 4-3 | 回素材库选中 10 张图，顶栏操作条点「打标 → AI」 | 自动跳转打标页**并立即建批次展示图片**（大图+胶片条），但 **AI 不自动开跑** | 跳转后白屏等半天 / AI 自作主张开始跑 |
| 4-4 | 观察工作台三栏 | 左侧数据栏（模式/档案/批次统计）；右侧大图 + 胶片条（状态角标 待打标/已建议/已确认）+ EXIF 只读行 + 分类标签面板（一排两个分类） | 三栏布局错乱 / EXIF 行显示乱码 |
| 4-5 | 点「开始打标」，盯着进度 | 进度持续推进，期间 UI 仍可交互（网络在后台跑）；跑完每张出现按分类分组的标签建议 JSON 结构（如 场景:公园 / 色彩风格:胶片感） | 进度卡死不动 / 打标期间整个界面冻结 |
| 4-6 | 对某张的建议点「拒绝」 | 状态变已拒绝；再点恢复按钮，**误拒可一键恢复为待确认**（防手滑） | 拒绝后无法反悔 |
| 4-7 | 逐张「确认写入」若干张，最后点「全部确认」 | 确认的分类自动建为父标签、建议词建为子标签，写入库中；全部确认批量生效 | 确认后素材库标签树看不到新标签 |

## 五、体感验收标准（口语化 ↔ 量化对照）

> 给真人测的口径：先按左边的人话感受判断，拿不准再对右边的量化指标（出处 PERFORMANCE.md / PRD R-04）。
