## 0. 最终结论

本轮只处理以下三个问题：

| 编号 | 问题 | 最终修复方向 | 优先级 |
|---|---|---|---|

## 5. 后端数据设计

### 5.1 色板 JSON 单一解析函数

在 `src-tauri/src/db/assets.rs` 抽取：

```rust
fn parse_palette_json(raw: Option<String>) -> Option<Vec<PaletteSegmentDto>>
```

语义必须统一：

- `NULL` -> `None`
- 空字符串或全空白 -> `None`
- `[]` -> `None`
- 损坏 JSON -> `None`
- 合法但空数组 -> `None`
- 合法且非空数组 -> `Some(Vec<PaletteSegmentDto>)`

`from_row` 必须改为调用该函数，不再内联一份 `serde_json::from_str`。后续状态统计、缺失列表和 patch 查询都必须复用同一解析语义，避免“页面说已完成，但实际渲染为空”。

若测试模块需要直接验证，可将其设为模块内可访问函数；不要把 JSON 解析复制到命令层。

### 5.2 候选范围单一事实源

保留 `PALETTE_CANDIDATE_PRED` 的现有含义：

- 活跃图片；
- 有真实 `hd_thumbnail_path` 封面的视频；
- 排除已删除素材；
- 排除只有通用占位图的视频，防止把 UI 占位色写入颜色搜索索引。

状态查询、`list_ids_needing_palette` 和 `list_all_ids` 必须使用同一个候选谓词，不允许在命令文件复制 SQL 字符串。

### 5.3 PaletteStatus

新增后端 DTO：

```rust
#[derive(Debug, Clone, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct PaletteStatus {
    pub total_assets: i64,
    pub eligible: i64,
    pub ready: i64,
    pub missing: i64,
    pub unavailable: i64,
}
```

字段定义：

| 字段 | 精确定义 |
|---|---|
| `totalAssets` | `deleted_at IS NULL` 的全部素材数 |
| `eligible` | 满足 `PALETTE_CANDIDATE_PRED` 的素材数 |
| `ready` | 候选素材中，经 `parse_palette_json` 得到非空色板的数量 |
| `missing` | `eligible - ready` |
| `unavailable` | `totalAssets - eligible` |

实现要求：

1. SQL 只取计数所需字段，候选行只查询 `palette_json`，不要构造完整 `Asset`。
2. `ready` 必须在 Rust 侧逐行调用 `parse_palette_json` 精确统计，不能只用 `IS NOT NULL` 近似。
3. 新增 db 函数，例如 `get_palette_status(conn)`；Tauri 命令只负责拿锁和返回 DTO。
4. 新增命令 `get_palette_status`，注册到 `src-tauri/src/lib.rs`。

当前 259 条数据量极小；即使未来数万条，只读取一个 TEXT 列并解析也比拉完整 Asset 安全。不要为了“纯 SQL”牺牲损坏 JSON 的正确识别。

### 5.4 修正 missing 范围

当前 `list_ids_needing_palette` 只判断 `palette_json IS NULL`，必须改为：

1. 查询所有符合 `PALETTE_CANDIDATE_PRED` 的 `(id, palette_json)`；
2. 用 `parse_palette_json` 过滤；
3. 返回解析结果为 `None` 的 id。

这样“生成缺失色条”才能修复以下全部情况：

- NULL
- 空字符串
- `[]`
- 损坏 JSON

禁止出现状态显示 `missing > 0`，但点击 missing 回算却得到 `total = 0` 的语义分叉。

### 5.5 AssetPalettePatch

新增轻量 DTO，只同步色板相关字段：

```rust
#[derive(Debug, Clone, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct AssetPalettePatch {
    pub id: i64,
    pub palette: Option<Vec<PaletteSegmentDto>>,
    pub dominant_hue: Option<i64>,
    pub dominant_sat: Option<i64>,
    pub dominant_lum: Option<i64>,
}
```

新增 db 查询和 Tauri 命令：

```text
get_asset_palette_patches(ids: Vec<i64>) -> Vec<AssetPalettePatch>
```

契约：

- 空 ids 直接返回空数组。
- 单次最多 1000 个 id；超过上限返回明确 `AppError`，前端负责分批。
- SQL 必须参数化，复用仓库已有 placeholder 工具，不拼接用户输入。
- 只返回数据库中存在的 id。
- `palette` 使用 `parse_palette_json`。
- 不返回文件路径、标签、缩略图等无关字段。
- 不修改任何数据库记录。

### 5.6 回算结果必须包含成功更新的 id

元数据回填现有 `RescanResult` 保持不变。色板命令使用独立返回类型：

```rust
#[derive(Debug, Clone, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct PaletteRescanResult {
    pub total: i64,
    pub success: i64,
    pub failed: i64,
    pub skipped: i64,
    pub updated_ids: Vec<i64>,
}
```

`updatedIds` 只包含本轮成功执行 `set_palette` 的素材 id，不包含失败、跳过或仅被扫描的 id。

实现方式：

- 给内部 `RefillSummary` 增加 `updated_ids: Vec<i64>`；
- 仅在 `set_palette` 成功后 push 当前 id；
- 元数据命令忽略该内部字段；
- `rescan_asset_palette` 转换成 `PaletteRescanResult`。

不要把“resolved ids”直接冒充“updated ids”，否则失败和跳过素材会被错误声明为更新成功。


将 `rescanAssetPalette` 返回类型改为 `Promise<PaletteRescanResult>`。页面禁止直接调用 Tauri `invoke`。

### 6.2 libraryStore 定向同步

在 `src/stores/libraryStore.ts` 新增：

```ts
refreshPaletteFields: (updatedIds: number[]) => Promise<void>;
```

算法必须按以下顺序：

1. 去重 `updatedIds`。
2. 与调用时当前 `items` 的 id 求交集；没有交集立即返回，不发 IPC。
3. 每批最多 1000 个 id 调用 `getAssetPalettePatches`。
4. 把返回 patch 建成 `Map<number, AssetPalettePatch>`。
5. 使用 Zustand 函数式 `set`，在提交瞬间基于最新 `s.items` 按 id 合并五个色板字段。
6. 未命中的素材对象保持原引用；命中的素材只替换色板相关字段。

必须保持不变：

- `items` 顺序
- `items.length`
- `total`
- `filter`
- `loading` 和分页请求代际
- 选择集
- `viewerOpen`
- 当前 Viewer 的 `currentId`
- `gridScrollTops`

不要复用 `patchLocal(ids, onePatch)`，因为不同素材的色板不同。也不要先清空 palette 再填充，避免色条闪烁。

并发要求：

- patch IPC 返回时，素材可能已翻页、过滤或被删除；最终函数式 set 只能更新仍存在于最新 `s.items` 的 id。
- 定向同步不递增 `requestSeq`，不得干扰正在进行的 refresh/loadMore。
- 某批请求失败时向调用方抛错，由设置页显示；已成功批次不回滚。

### 6.3 手动生成流程

`src/pages/SettingsPage.tsx` 沿用现有 appearance route 的状态和 `media_refill://progress` 订阅方式，新增本文件内函数 `refreshPaletteStatus()`。

进入通用外观路由时读取状态；总开关开关变化不需要重复触发扫描。执行“生成缺失色条”时：

```text
读取/确认 missing > 0
  -> rescanAssetPalette([], "missing")
  -> refreshPaletteStatus()
  -> libraryStore.refreshPaletteFields(result.updatedIds)
  -> 展示完成摘要
```

硬性要求：

- 手动回算不发 `palette://updated` 全局事件。
- resolve 后不得调用 `libraryStore.refresh()`。
- `refreshPaletteStatus()` 和 `refreshPaletteFields()` 即使其中一个失败，也要保留回算结果摘要并显示具体错误。
- 同一互斥闸已有任务时，沿用后端明确错误，不创建轮询或自动重试循环。
- Settings 页卸载后不得 setState；沿用项目现有 effect 清理方式。

### 6.4 导入后置事件

只允许导入后置色板任务发送全局事件：

```rust
#[derive(Debug, Clone, Serialize)]
#[serde(rename_all = "camelCase")]
struct PaletteUpdatedEvent {
    source: &'static str, // 固定 "import"
    total: i64,
    success: i64,
    failed: i64,
    skipped: i64,
    updated_ids: Vec<i64>,
}
```

事件名：

```text
palette://updated
```

发送条件必须同时满足：

- 由 `import_cmd.rs` 的后台后置任务触发；
- 成功抢到 refill gate；
- 后台任务实际执行并返回 `Ok(summary)`；
- `updatedIds` 非空。

以下情况不发事件：

- 手动设置页回算；
- 候选 id 为空；
- refill gate 已被占用并返回 `None`；
- 扫描返回错误；
- 扫描成功但没有任何色板写入。

闸被占用时静默跳过是现有设计内正常路径。不要增加后台重试循环；遗漏素材由设置页“生成缺失色条”兜底。

### 6.5 App 级订阅

在 `src/App.tsx` 使用现有 `useTauriEvent` 与 `on<T>` 订阅 `palette://updated`：

```ts
interface PaletteUpdatedEvent {
  source: "import";
  total: number;
  success: number;
  failed: number;
  skipped: number;
  updatedIds: number[];
}
```

收到事件后只执行：

```ts
void useLibraryStore.getState().refreshPaletteFields(payload.updatedIds);
```

禁止执行：

```ts
useLibraryStore.getState().refresh();
```

App 级监听的原因是用户可能在素材库、查看器、入库页或设置页之间切换；监听不应依赖某个页面当前是否挂载。订阅失败由现有 `useTauriEvent` 统一记录，不得阻塞应用首屏。

## 9. 代码与 UI 开发规范

### 9.1 TypeScript / React

- 页面和组件不得直接 `invoke`，统一通过 `src/api/*`。
- Zustand 更新使用函数式 `set`，异步返回后必须基于最新 state 合并。
- 不把服务端状态复制成多个互相独立的前端事实源。
- 不用 `any` 绕过 DTO；事件、命令和 store 方法必须有明确类型。
- effect 必须清理订阅，复用 `useTauriEvent`。
- 按钮必须使用 `button type="button"`，图标按钮必须有 `aria-label` 和 `title`。
- 使用已有 `lucide-react` 图标，不手写 SVG。
- 只在非自解释逻辑前写短注释，删除过时的“双排胶片条”注释。
- 不新增无必要依赖或全局状态库。

### 9.2 CSS / Tailwind

- 使用现有 CSS 变量，不引入新的一次性颜色。
- 固定格式控件必须有稳定尺寸，避免动态内容导致布局跳动。
- 所有两栏 grid 子项使用 `min-w-0`。
- 需要滚动的层明确写出 x/y 方向，不依赖浏览器默认 overflow。
- 不用负 margin、绝对定位遮盖、额外 z-index 或透明遮罩修复侧栏漏字。
- 不在页面区块外再套装饰卡片；沿用当前紧凑工具界面。
- 不用 `height:auto` 替代本规格的 128px 标签区。
- 文本过长优先截断或在本栏换行，不允许撑破侧栏和标签栏。

### 9.3 Rust / SQLite

- DB 锁只用于短查询和短写入；图像解码继续在锁外完成。
- SQL 参数化；动态 id 列表复用现有 placeholder 工具。
- JSON 解析只有一个 helper；错误数据安静降级并纳入 missing。
- Tauri DTO 使用 `#[serde(rename_all = "camelCase")]`。
- 单条坏数据不能使整个状态查询或补算批次失败。
- 不新增 migration，不改变现有色板列含义。
- 导入后置任务失败仍不得影响入库主结果。
- 不在 gate 被占用时重置取消标志、发成功事件或创建重试风暴。

### 9.4 用户文案

- 使用“色条”“生成”“可生成”“暂不可生成”等用户语言。
- UI 不展示 `palette_json`、candidate predicate、回算 scope、dominant hue 等实现术语。
- “算法主色色条”的解释必须明确“本机计算、不调用 AI”。
- 错误文案说明用户下一步可以做什么，不能只显示 `failed` 或错误码。
