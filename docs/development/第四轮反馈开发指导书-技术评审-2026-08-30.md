## 0. 总体结论

指导书质量较高，**三个问题的根因定位全部与代码实际情况吻合**（逐条核实记录见第 2 节），第 3 节工作区保护点、第 10 节禁止方案、第 7 节单一事实源约束均准确且必要。整体方案方向正确，可以施工。

但存在 **3 个会导致施工结果不达标或引入回归的实质问题（P0/P1）**，以及若干规格含糊处。核心是：

1. 标签区高度 96→128 被写成"建议"，实际是硬性前提，不改则验收必挂；
2. `palette://updated` → `libraryStore.refresh()` 的整页刷新会截断已加载分页、在查看器打开时可能把当前素材顶回初始素材；
3. §6.6 的默认值方案自相矛盾且留了产品决策口子，施工 AI 无法自行决定。

## 1. 问题清单

### P0-1｜§5.2/§6.1：标签区高度调整是"建议"，但实际是验收的硬性前提

**证据**：当前 `ViewerTagBar.tsx:48` 展开总高固定 `96`px，正文 `h-16`（64px）。指导书 §5.2 写"建议展开高度：标题 32px + 正文 96px，总高约 128px"，§6.1 施工动作只写"正文改为 `grid-cols-2`"，**没有明确把 96 改成 128**。

**后果**：两栏布局下每个分面组一行约 22–24px，13–20 个标签分布在 4–6 个组时每栏需要约 3 行 ≈ 70–100px 正文。64px 正文必然纵向滚动，直接违反 §5.2 硬性要求"正常 13-20 个标签时不应出现纵向滚动"和 §9.1 验收项。施工 AI 若按 §6.1 字面执行（只加 `grid-cols-2`、保留 `height: 96`），验收必挂，然后大概率"擅自"改成 `height:auto`——又踩中 §5.2 明令禁止的无限高度。

**修改建议**：把 §6.1 施工动作第 5 条改写为强制条款：
- `ViewerTagBar.tsx:48` 的 `style={{ height: collapsed ? 32 : 96 }}` 必须改为 `collapsed ? 32 : 128`；
- 正文容器由 `h-16` 改为约 96px（如 `h-24`）+ 保留 `overflow-y-auto` 兜底；
- §5.2 中"若实测 128px 仍经常滚动，可把正文上限提高到 112px"保留为后备，但 128 是本轮流量的默认值，不是可选项。

### P0-2｜§6.5/§6.4：整页 `refresh()` 刷新策略有两个未评估的回归面

**证据**：`libraryStore.ts:129-144` 的 `refresh()` 语义是"重置回第一页（PAGE_SIZE=200）整体替换 items"。指导书 §6.5 让前端订阅 `palette://updated` 后无条件 `useLibraryStore.getState().refresh()`。

**回归面 1——分页截断**：用户在素材库通过 `loadMore` 加载了 200+ 条并滚到深处时，一次后台色板完成事件会把 items 截断回前 200 条，网格塌缩、滚动位置跳变。这不是理论场景：259 个素材的库正好会触发。

**回归面 2——查看器跳素材**：`ViewerPage.tsx:40-44` 的 `current = items.find(id) ?? initial`。若查看器打开时当前素材在第 200 条之后，refresh 截断后 `find` 落空，`current` 静默回落到 `initial`（打开查看器时的那张），用户正在看的图会跳走。§6.5 的 payload 允许 `source: "manual"`，意味着手动回算也会发事件，此时用户刚从设置页返回库页/查看器的概率不低。

**修改建议**（按优先级）：
1. `palette://updated` 只从**导入后置链路**（`import_cmd.rs` 的 `try_rescan_palette_exclusive` 完成后）发出，`source` 固定 `"import"`；手动回算（`rescan_asset_palette` 命令本身）不发事件——SettingsPage 已在命令 resolve 后自行刷新（§6.4 步骤 5），避免双刷新和查看器场景。
2. 监听器侧加护栏：事件到达时若 `useLibraryStore.getState().items.length > PAGE_SIZE`，降级为不整页刷新（或仅 `patchLocal` 色板字段），宁可用户手动刷新也不截断列表；至少把该权衡写进指导书让施工方知情。
3. §8.5 测试补一条：手动回算完成后**不得**触发第二次 library refresh。

### P1-1｜§6.6：默认值方案自相矛盾，且留给施工 AI 一个它无权做的产品决策

**证据**：三处现默认值一致为 `showInLibraryGrid=false`（`settingsStore.ts:36`、`normalizeSettings.ts:162`、`settings.rs:363`）。指导书 §6.6 一边建议新装机默认 `true`，一边说"也可以保留 false"，同时要求"不得在升级时把用户已经明确保存的 false 强行改成 true"。

**矛盾点**：`normalizeSettings` 对**缺失键**回落默认值。对"自色板功能上线以来从未保存过设置"的老用户，其存储 JSON 里可能根本没有 `colorStrip` 键——升级后 normalize 会按新默认 `true` 渲染，效果上就是把一批存量用户的 false 翻成了 true，且代码层面**无法区分**"显式存的 false"和"没存过"。指导书的要求自身不可实现。

**修改建议**：二选一，但必须写死，不留"如果产品不希望…"的口子：
- **推荐：保持 `showInLibraryGrid=false` 不变**。本轮 FB4-03 的真正痛点是"看不到原因 + 没有生成入口"，§6.4 的状态提示 + 生成按钮已解决；翻转默认值收益小、存量回归风险实打实。
- 若产品坚持默认 true：则要求仅对"settings 表为空/全新安装"生效（例如后端 get_settings 判断是否首次初始化），并补一条迁移测试：存量用户缺失 colorStrip 键时升级后仍为 false。

另外 §6.6 的默认值清单**漏了 `showInImportGrid`**（`settingsStore.ts:36`、`settings.ts:121`、`settings.rs:365` 均存在，当前无 UI 消费方）。应显式写明"保持 false 不变"，防止施工 AI 同步改默认时四处漂移。

### P1-2｜§4.3.1/§5.5 对现有设置页的描述失真，可能导致不必要的拆除重建

**证据**：`SettingsPage.tsx:542-556` **已经存在**独立的位置开关"素材库网格显示 / 查看器显示"（总开关开启时逐行展示），并非 §5.5 暗示的"只展示一个看似打开就会显示的总开关"。现有缺口只有两个：色板状态展示（0/259）和就近的"生成缺失色条"入口。

### P1-3｜§6.3：`PaletteStatus.ready` 的"损坏 JSON 计未就绪"在纯 SQL 里做不到，规格不可实现

**证据**：`PALETTE_CANDIDATE_PRED`（`assets.rs:1079-1081`）与 `list_ids_needing_palette`（`assets.rs:1084-1090`）都只用 `palette_json IS NULL`。指导书 §6.3 要求 NULL、空串、空数组、**损坏 JSON** 都计为未就绪，但损坏 JSON（如 `"{oops"`）无法用 SQL 谓词识别；且 `from_row`（`assets.rs:259`）在读取时已把损坏 JSON 安静降级为 None。

**修改建议**：把 ready 的 SQL 语义定为
`palette_json IS NOT NULL AND palette_json != '' AND palette_json != '[]'`，
并在文档中注明：损坏 JSON 计入 ready 属于已知近似（实际渲染时 `from_row` 已降级为空，不产生假色条，符合 §5.5 第 7 条）；如确要精确，须在 Rust 侧逐行 parse（259 行量级可接受，但应写明这是 app 层实现而非 SQL）。同时建议把 `PALETTE_CANDIDATE_PRED` 提为 `pub` 或抽成共享函数的要求写得更具体（§7.1 已有原则，§6.3 缺落点：新命令应调用 `assets.rs` 内新函数，而不是复制谓词字符串）。

### P2-1｜§6.1 "按钮使用稳定 `size-14`" 指代含糊

`ViewerFilmstrip` 里有两种按钮：缩略图按钮（当前 `style={{width: THUMB}}` + `h-full`）和左右切换按钮（当前 `size-9`）。"按钮使用稳定 size-14" 可被误读为切换按钮也要改 56px。建议改写为："缩略图按钮固定 56×56（`size-14`），左右切换按钮保持现有 `size-9` 不变。"（另注：外层 `h-20`=80px、`py-2` 后内高 64px，容纳 56px 缩略图居中没问题，尺寸自洽。）

### P2-2｜§5.2 未指定"+ 添加标签"按钮在新布局中的位置

当前按钮在滚动正文末尾（`ViewerTagBar.tsx:76-82`）。两栏 grid 中它应明确为：放在 grid **之后**、正文容器内的独立行（不进入任何一栏），或标题栏右侧。§8.2 已要求"添加回调仍可触发"，但位置不写清会出现按钮被塞进右栏当作一个"组"的实现。

### P2-3｜§6.5 建议补一句已知行为说明

`import_cmd.rs:76-78` 的 `try_rescan_palette_exclusive` 在互斥闸被占用时**静默跳过**整批补算（也不该发 `palette://updated`）。这是设计内行为，但施工 AI 若不知情，可能"顺手"加重试循环或发一个 success=0 的事件。建议在 §6.5 加一句："闸被占用跳过时不发事件，属正常路径，缺失部分由设置页'生成缺失色条'兜底。"

### P2-4｜§6.2 "必要时对深层级最大缩进做上限" 无量化标准

建议给出触发条件和上限值，例如："仅当 224px 侧栏内实测溢出时，将 `TagTree.tsx:73` 的 `paddingLeft: depth * 14` 改为 `Math.min(depth, 6) * 14`；不溢出则不动。"避免施工 AI 预防性地改缩进逻辑。

### P2-5｜杂项

- §8.6 命令块标注 powershell，但仓库约定 shell 是 Git Bash（`cd src-tauri && cargo test` 两者皆可）；建议去掉 shell 标注或写两种均可。
