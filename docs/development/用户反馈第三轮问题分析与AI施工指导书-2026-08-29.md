- 日期：2026-08-29
- 适用项目：`bagertea_ai_media_v2`（Tauri 2 + React 19 + Rust + SQLite）
- 用途：本文件是可以直接外派给其他 AI 开发 agent 的施工合同，不是泛泛的产品建议。

## 0. 使用方式

外派任务必须按以下顺序执行：

1. 先阅读本文件、`docs/ARCHITECTURE.md`、`docs/DEVELOPMENT.md`、最近一轮指导书和当前 `git diff`。
2. 先复现并记录基线，再修改代码。不能因为单元测试通过就宣称桌面行为已修复。
3. 每个问题单独提交，提交信息包含问题编号，例如 `fix(viewer): restore two-row filmstrip (FB3-02)`。
4. 不删除测试来让测试变绿；行为改变时必须改写断言并说明新旧语义。
5. 每个阶段结束必须跑：
   - `npm run typecheck`
   - `npm run test:unit -- --run`
   - `npm run build`
   - `cargo check --manifest-path src-tauri/Cargo.toml`
   - `cargo test --manifest-path src-tauri/Cargo.toml`
6. 真实 Tauri/WebView2 行为必须用 `npm run tauri dev` 或打包程序验收，特别是 `asset://`、Fullscreen API、视频 Range、滚轮和 keyring。

## 3. FB3-01：启动时色带导致素材库错位

### 3.1 证据和根因

当前 `AssetGridView` 用以下逻辑估算每一行高度：

```ts
stripPx = colorStrip.enabled && colorStrip.showInLibraryGrid
  ? HEIGHT_PX[colorStrip.height]
  : 0;
rowHeight = cellWidth * (rh / rw) + stripPx + GAP;
```

但是 `AssetCard` 只有在 `asset.palette?.length` 为真时才渲染色条。也就是说，同一行可能出现：

- A 卡片实际高度 = 媒体容器 + 色条；
- B 卡片实际高度 = 只有媒体容器；
- Virtualizer 却给整行统一加 `stripPx`。

启动阶段素材列表、色板回算和缩略图是异步到达的，Virtualizer 初次测量可能发生在数据未完整到达时。切换“打标 → 素材库”会重新挂载并重新测量，所以症状暂时消失。这解释了“刚进入错位，切页后正常”，不应把切页当修复方案。

“一条一条”的视觉也可能被空色板卡片和行高累计误差放大。另一个需要加入诊断的候选是坏 `ratio`（NaN、负数、总和为 0），但它通常造成色带段宽异常，不是主要的纵向错位根因。

### 3.2 推荐方案：恒定几何，不依赖色板是否到达

采用“每张卡片永远预留色条槽位”的方案：

1. `AssetCard` 在开关打开时始终渲染固定高度的 wrapper。
2. 没有 palette 时渲染空槽，使用 `visibility:hidden` 或透明背景，不显示假色带，但保留高度。
3. `AssetGridView.rowHeight` 使用同一个 `HEIGHT_PX` 常量，卡片实际高度和 Virtualizer 估算严格一致。
4. `ColorStrip` 内部对 palette 做运行时归一化：过滤非有限 ratio，截断到 `[0,1]`，总和为 0 时回退等宽；非法 hex 使用安全背景色。
5. 色板数据更新后只触发内容更新，不改变卡片外框几何。
6. 对 `rowHeight`、列数、比例和色条高度变化调用 `virtualizer.measure()`；必要时用 `ResizeObserver` 观察网格宽度。

不推荐的替代方案是“等所有色板加载后再打开色条”。它会让启动首屏继续跳动，而且大库永远可能存在缺色板素材。

### 3.3 施工文件和测试

- 修改：`src/components/library/AssetCard.tsx`
- 修改：`src/components/library/AssetGridView.tsx`
- 修改：`src/components/library/ColorStrip.tsx`
- 可新增纯函数：`src/utils/palette.ts`
- 单测：
  - 有 palette/无 palette 混排时每个卡片 wrapper 高度相同；
  - ratio 异常不会产生 `NaN%`；
  - 开关关闭时不占色条高度；
  - 启动异步补齐 palette 后网格不发生累计位移。
- 真机验收：20 张图片，随机只给一半写入 palette，冷启动后滚动到第 5、10、20 行，卡片不能重叠、不能出现越来越大的空白。

## 4. FB3-02：大图底部胶片条改为双排

### 4.1 现状问题

`ViewerFilmstrip` 当前是 `flex + overflow-x-auto` 的单行结构。缩略图越多，横向区域越长；在宽窗口里右侧出现大面积空白，在窄窗口里只能横向滚动，用户描述的“上下滑”也会在外层高度不足时出现。

### 4.2 推荐布局

把胶片条定义为固定高度的“两行缩略图带”：

- 外层固定 `height`，桌面端约 `128px`，由两行 `56px` 缩略图 + 间距 + 内边距组成。
- 内层使用 `display:grid`、`grid-template-rows: repeat(2, minmax(0, 1fr))`、`grid-auto-flow: column`、固定 `grid-auto-columns`。
- 两行填满当前宽度；素材超过可视宽度时只允许横向滚动，不允许纵向滚动。
- 上一张/下一张按钮固定在左、右侧；缩略图区 `min-width:0`，避免按钮把网格挤出容器。
- 小窗口缩略图可降为 44px，但仍保持两行；不要用随 viewport 任意缩放字体。

“双排”指缩略图胶片条，不是把标签 chip 强行拆成两排。真正的标签区 `ViewerTagBar` 仍可在内容过多时内部纵向滚动；两者必须在代码和文案中使用不同名称。

### 4.3 验收

1. 1、2、3、20、200 个素材都保持两行结构。
2. 窄窗口无横向溢出到标题栏，宽窗口不出现空白占位列。
3. 点击缩略图、左右按钮、键盘左右键都仍定位同一素材。
4. `ViewerFilmstrip.test.tsx` 增加 `grid-template`/无纵向滚动语义断言；Playwright 截图验收布局。

## 5. FB3-03：视频控制条和进度条恢复

### 5.1 根因

`VideoControls` 组件本身存在，测试也能找到“播放进度” range。因此“完全不见”不是控件 JSX 被删除，而是布局高度链高概率把它裁掉：

```text
StageFrame: flex-1 + overflow-hidden
  └─ VideoPlayer: max-h-full/max-w-full + flex-col
       ├─ video: intrinsic height, 只写 max-h/max-w
       └─ controls: shrink-0
```

当 video 的固有高度先占满舞台时，控制条被推到舞台下方，外层 `overflow-hidden` 直接裁剪。切换到某些尺寸的视频可能“看起来有控件”，造成误判。

### 5.2 推荐结构

将播放器改成明确的可测量布局：

- `VideoPlayer` 根节点：`h-full w-full min-h-0 min-w-0 flex flex-col`。
- 媒体区：`min-h-0 flex-1 flex items-center justify-center`，视频元素使用 `max-h-full max-w-full w-full h-full object-contain`，必要时包一层保持原始比例的 frame。
- 控制条：`shrink-0 w-full`，永远在可视舞台内。
- 普通查看器控制条可以是底部实心条；全屏浏览模式改为底部渐变 overlay，但不能与视频尺寸争夺未定义高度。
- 不按 `durationKnown` 隐藏整条控制器，只在 duration 未知时禁用 range 并显示 `--:--`。
- 视频切换时清理旧事件和旧 duration；`loadedmetadata` 后同步 currentTime/duration。

该结构与 Immich 的 `VideoNativeViewer` 做法一致：媒体元素使用 full-height，底部 control bar 和 time range 是同一 media-controller 内部区域，而不是媒体外面再追加一个可能溢出的兄弟节点。

### 5.3 功能验收

- 播放/暂停、后退 5 秒、前进 5 秒、range 拖动、倍速、静音、音量、全屏全部可见且可用。
- `loadedmetadata` 前 range 禁用；之后 `max=duration`、拖动立即更新画面。
- WebView2 真机检查 H.264 MP4；不兼容编码仍走现有代理生成流程。
- 增加真实浏览器测试：给 `<video>` mock `duration/currentTime` 并派发 `loadedmetadata/timeupdate`，断言 range 可用；增加截图检查控制条没有被裁剪。

## 6. FB3-04：把“详情”改成“全屏浏览”

### 6.1 语义必须改变

当前“详情”按钮实际控制左侧 `ViewerInfoSidebar`，这不是用户理解的详情，也不是用户要的功能。按钮应改名为“全屏浏览”，职责改为查看器级全屏：图片和视频都占满屏幕，缩略图胶片条、标签栏、属性栏和应用底部栏不显示。

属性信息若仍需要，放入独立的“信息”图标或侧栏快捷键；不要让“详情”继续承担全屏入口。

### 6.2 推荐实现

1. `ViewerPage` 最外层增加 `viewerRootRef` 和 `isFullscreen` 状态。
2. 点击“全屏浏览”调用 `viewerRootRef.current.requestFullscreen()`；监听 `fullscreenchange`，系统退出时同步状态。
3. `ViewerShell` 接收 `fullscreen`/`onExitFullscreen`，全屏时只保留媒体舞台和视频控制条。
4. `ViewerToolbar` 全屏时可以隐藏；若保留退出按钮，按钮必须叠在媒体舞台上且不遮挡主要画面。
5. `ViewerFilmstrip`、`ViewerTagBar`、属性 sidebar 在全屏状态下 `display:none`，不能只是透明，否则仍占布局空间。
6. Escape 优先退出浏览器全屏，第二次 Escape 才关闭查看器。
7. 视频播放器内部的“全屏”按钮可以保留为播放器级全屏，但顶部“全屏浏览”是统一的查看器级入口；两者都必须有清楚的 aria-label。

Fullscreen API 在纯浏览器预览或测试环境可能不存在，必须捕获 rejected promise，退化为应用内 `data-viewer-fullscreen` CSS 状态并给出提示，不能抛出页面级错误。

### 6.3 验收

- 图片和视频均可进入全屏；视频仍有播放控制条。
- 全屏时看不到缩略图、标签、属性栏、应用底栏。
- 退出全屏后恢复原滚动位置、当前素材和侧栏开关。
- `ViewerToolbar.test.tsx` 断言文案为“全屏浏览”，不得再出现“详情”作为该按钮名称。

## 7. FB3-05：统一缩放和快捷键管理

### 7.1 当前问题

当前 `MediaViewport` 有 Alt+滚轮和双击代码，但存在三个风险：

- wheel 只支持 Alt，不支持产品需要的统一修饰键策略，也没有集中定义。
- 双击逻辑依赖 `pointerdown` 的 `e.detail === 2` 和时间窗口；在 Tauri WebView2、触摸板、点击被子节点截获时容易失效。
- ViewerPage、VideoPlayer、Workbench、AssetGridView 各自绑定键盘监听，优先级和 Escape 语义不一致。

### 7.2 推荐的统一快捷键注册表

新增 `src/hooks/useShortcuts.ts` 或 `src/utils/shortcuts.ts`，集中声明：

| 作用域 | 快捷键 | 行为 |
|---|---|---|
| viewer/image | Alt+滚轮 | 以指针为锚点缩放，步进 1.15，范围 20%–800% |
| viewer/image | 双击 | 1x ↔ 2x；再次双击回 1x，offset 清零 |
| viewer/image | 拖拽 | scale > 1 时平移；pointer capture/pointercancel 必须清理 |
| viewer | ←/→ | 上一张/下一张 |
| player | Space/K | 播放/暂停 |
| player | ←/→ | 后退/前进 5 秒，阻止冒泡到 viewer |
| player | M/F | 静音/播放器全屏 |
| viewer | Escape | 先退全屏，再关闭查看器 |
| library | Ctrl/Cmd + `+`/`-` | 网格档位变化 |
| library | Alt+滚轮 | 网格档位变化；必须 `passive:false + preventDefault` |

注册表要有 scope priority：modal > player > viewer > page > global。输入框、select、textarea、contentEditable 和打开的菜单默认不接收页面快捷键。

### 7.3 双击和 wheel 实施要求

- 使用真正的 `onDoubleClick` 处理双击，避免手工依赖 `detail`；统一调用同一个 `zoomAt()` reducer。
- wheel 监听仍使用原生 `{ passive:false }`；只有命中修饰键时 `preventDefault()`。
- `zoomAt()` 只接受 `clientX/clientY`，通过 `getBoundingClientRect()` 转舞台坐标；禁止重新引入 `offsetX/offsetY` DOM 读取。
- 每次素材/源切换递增 generation，旧回调丢弃；这是已有正确方向，不能回退。

### 7.4 测试

- 单测覆盖双击 1x→2x→1x、Alt wheel、pointercancel、快速切图旧回调丢弃。
- Playwright 真机覆盖按住 Alt 滚轮、双击图片、拖拽、全屏 Escape。
- 播放器焦点内按左右键不能切换素材，只能 seek；播放器外左右键才能过片。

## 8. FB3-06：超级搜索折叠逻辑和空白区域

### 8.1 正确产品语义

- 下滚超过阈值：详细条件收起。
- 收起状态下继续上滑，但尚未到顶部：保持收起。
- 只有滚动容器回到 `scrollTop <= minScrollTop` 才自动展开。
- 用户点击“展开详细条件”时立即展开；展开后不因同一段滚动事件马上收回。

当前 `useScrollDirection` 在任意上滑累计达到 `expandThreshold` 时就展开，必须改掉。

### 8.2 推荐修改

在 `useScrollDirection` 的 up 分支中增加顶部条件：

```ts
if (dir === "up") {
  if (y <= minScrollTop.current) setState("expanded");
  return;
}
```

保留非对称阈值和 suppress window，但不要让 `moved >= expandThreshold` 在非顶部直接展开。

“只展开下面的框”要求：

- 摘要栏、搜索框和 chips 保持固定。
- 只有 `QueryBuilder` 所在的 detail panel 做 grid-template-rows 折叠动画。
- detail panel 外层不绘制一个占满全宽的假卡片；边框和背景只属于中间的 `QueryBuilder`。
- 删除旧的“快速编辑条件”重复条（若在未提交分支中仍存在）。
- QueryBuilder 自身应使用 `w-full max-w-4xl mx-auto`，两侧只是页面留白，不渲染空白列。

### 8.3 验收

自动化测试必须覆盖：`scrollTop=300` 上滑 20px 不展开；滚到 40px 以下展开；点击手动展开后 300ms 内不被 scroll 覆盖。真机连续惯性滚轮不能闪烁。

## 9. FB3-07：“执行分块大小”改成小白能懂的设置

### 9.1 真实含义

它不是“总共处理多少张”，也不是“同时开多少个 AI”。真实含义是：

- 一个大批次仍保留全部已选素材；
- 云端执行层每次从待处理列表取一小段，顺序处理、限流、失败重试；
- 分块之间不增加数据库 chunk 表；
- 云端当前有效范围是 10–50；
- 本地模型执行层固定使用 15，当前设置不会改变本地分块大小。

### 9.2 推荐文案和 UI

将标签改为“每批处理数量（云端）”，说明改为：

> 一次 AI 请求任务中，云端每轮处理多少张素材。它不会减少你选中的总数量；例如选了 120 张、设置 20，仍会处理 120 张，只是分 6 轮完成。数字越大速度可能更快，但占用内存和失败重试成本也更高。

建议：

- 云端显示 stepper/range，最小 10、最大 50、默认 20 或 30，与 Rust 完全一致。
- 当前服务为本地时隐藏该字段，或显示只读说明“本地模型固定每轮 15 张”。
- 不允许 UI 继续写入 1–9 这种运行时必被 clamp 的值。
- 设置迁移时把历史 500 归一到 30，不要让用户看到一个实际永远不会生效的 500。

## 10. FB3-08：AI 服务连接失败的代码诊断和修复

### 10.1 已确认的代码缺陷

`AiConnectionManager.test()` 只拿到 `AiConnectionView` 的 `hasKey`，然后把空字符串传给 `aiListModels`。因此在线服务的 Bearer/API key 测试必然可能返回 401/403，即使 keyring 中已经保存了正确密钥。

另外，统一调用 `/models` 不能测试 Anthropic Messages：Anthropic 的核心验证应是带 `x-api-key` 和 `anthropic-version` 的最小 `/messages` 请求。对本地 Ollama，通常不需要 key，`GET /v1/models` 或 `/api/tags` 才合理。

### 10.2 推荐 API 契约

新增后端命令 `test_ai_connection(connection_id)`，由 Rust 完成：

1. 从数据库读取 deployment/protocol/base_url/model。
2. 从 keyring 读取密钥，绝不通过前端回显明文。
3. 根据协议选择测试：
   - OpenAI 兼容：`GET {baseUrl}/models`，Bearer；若服务不提供 models，再用最小 text chat 请求。
   - Anthropic：`POST {baseUrl}/messages`，`max_tokens=1`，短文本；不要假设 `/models`。
   - 本地：优先无鉴权探测 `/v1/models`，再检查指定模型是否存在。
4. 返回结构化结果：`ok/statusCode/latencyMs/protocol/model/message`，错误信息脱敏。
5. 前端按钮显示“测试中 → 成功/失败”；成功信息包含延迟和实际协议，失败信息包含 HTTP 状态、超时、DNS、TLS、鉴权、路径建议。

### 10.3 对用户当前连接的判断边界

用户提到的 “agents / age...” 服务名无法从仓库代码确定，当前没有拿到其真实地址、协议、模型或 key，因此不能凭空宣称外部连接已经测试成功。按现有代码，最可能的失败顺序是：

1. 在线 key 没有从 keyring 带入测试请求；
2. Base URL 已经包含 `/v1` 或 `/chat/completions`，程序再次拼路径；
3. 服务实际是 Anthropic/自定义协议，却选择了 OpenAI 兼容；
4. 模型名称不是该服务真正可用的 vision 模型；
5. 本地服务未启动或端口被防火墙拦截。

施工者必须先修复测试命令，再让用户点击测试并记录脱敏结果；不得要求用户把 API key 发到聊天中。

### 10.4 本机当前配置的安全连通性证据

在不读取密钥内容的前提下，从本机数据库只读查询到 3 个连接：

| 名称 | 地址 | 模型 | 密钥状态 |
|---|---|---|---|
| 默认配置 | `https://opencode.ai/zen/go/v1` | `mimo-v2.5` | 已配置 |
| 本机 Ollama | `http://localhost:11434/v1` | `gemma3:4b` | 未配置 |
| agenes | `https://api.agnes-ai.cn/v1` | `agnes-2.5-flash` | 已配置 |

只读网络探测结果：

- `https://api.agnes-ai.cn/v1/models` 不带密钥返回 `401 Unauthorized`：DNS、TLS、域名和路径均可达，不能据此判断地址填错；它反而证明服务在等待鉴权。
- `http://localhost:11434/v1/models` 返回 `200` 并列出 `gemma3:4b`：本机 Ollama 服务正常响应。
- `https://opencode.ai/zen/go/v1/models` 返回 `200` 并列出模型：该服务的 `/models` 路径可用。

因此，agenes 的第一修复动作不是改 URL，而是让后端连接测试从 keyring 读取该连接密钥，并把 `Bearer` 认证带到请求中；随后再用指定模型做一次最小视觉/文本请求。密钥内容、数据库 `api_key_ref` 和完整响应不得写入报告或日志。

## 11. FB3-09：标签与分类字段统一解释

### 11.1 唯一语义表

| UI 文案 | 数据字段 | 给谁看 | 是否进入 AI prompt | 例子 |
|---|---|---|---|---|
| 分类名称 | `tag_facets.display_name` / 可选 `aiFacetConfigs.displayName` | 人和 AI | 是，作为可读标题 | “物体” |
| 给人的分类说明 | `tag_facets.description` | 人 | 是，作为背景说明 | “识别画面中可辨认的主体物件” |
| 给 AI 的识别规则 | `aiFacetConfigs.hint` | AI 为主，设置页可编辑 | 是，作为执行约束 | “只写可观察到的主要物体，不写推测身份” |
| 参与 AI 打标与搜索 | `enabledForAi` | 人 | 控制是否进入 prompt | 开/关 |
| 在打标工作台显示 | `visibleInWorkbench` | 人 | 否 | 开/关 |
| 基本规则 | `selectionMode/maxItems/appliesTo` | 人和后端 | 是，限制输出 | 单选、最多 3 个、仅图片 |
| 画面中的关键物体 | 默认“物体”分面的 description/hint 示例 | 不应单独再建一套字段 | 随 description/hint 进入 | 不能把它误显示成 AI 输出结果 |

当前“第一行名字、第二行介绍、第三行 AI 行为”的正确解释是：第二行应该拆成“给人的说明”，第三行才是“给 AI 的识别规则”。“画面中的关键物体”是旧默认分类的提示语，不是另一类用户说明，也不是必须展示给最终用户的 AI 解释。

### 11.2 UI 改造

在 `FacetDetail` 中按以下顺序呈现：

1. 分类名称（可编辑；稳定 `facetKey` 只读显示为高级信息）。
2. 给人的说明（placeholder：这类标签描述什么）。
3. 基本规则：单选/多选、数量上限、适用媒体。
4. AI 行为：参与 AI 打标与搜索、给 AI 的识别规则、工作台显示。
5. 分类词条：进入“分类词条：物体”的二级编辑器。

保存语义必须清晰：数据库结构规则即时保存；AI 行为随设置页“保存设置”统一保存，或者全部改为显式保存，但不能一半即时、一半静默而没有说明。

## 12. FB3-10：悬停预览、色调和网格开关

### 12.1 悬停自动播放

当前代码已具备 `useHoverIntent`、`AssetCardVideoLayer` 和短片段循环，但必须真机确认三层开关都为真：

1. `appearance.hoverPreview.enabled`
2. `appearance.hoverPreview.inLibraryGrid`
3. 对应页面是否真的挂载 video layer

此外，Tauri `asset` scope 必须放行用户选中的原视频路径；导入页路径和素材库路径不能混为一谈。播放失败应显示可解释状态，并按现有代理策略重试。

设置文案改为：

> 鼠标停在视频卡片上约 300 毫秒后，在卡片内部静音播放片段；移开鼠标立即停止，不会打开大浮层。

如果产品决定素材库不启用悬停预览，则隐藏“素材库也启用悬停预览”，不要保留一个用户能打开但产品不支持的开关。导入页和素材库必须分别写清适用范围。

### 12.2 色调/色条

当前“显示色条”总开关和“素材库网格显示”默认关闭，所以用户打开总开关后仍可能看不到色条。更严重的是“查看器显示”虽可开，但 `ViewerPage` 尚未接入 `ColorStrip`，属于设置与实现脱节。

推荐处理：

- 若当前版本暂不支持查看器色条：隐藏“查看器显示”，不要显示一个无效开关。
- 若要支持：在 `ViewerTagBar` 上方或舞台底部接入 `ColorStrip`，并纳入全屏隐藏规则。
- “色调”统一改名为“算法主色色条”；说明“由本地算法从缩略图/封面估算，不调用 AI，不代表摄影师手工调色”。
- 入库前没有色板时，隐藏“入库网格显示”，不要显示永久 disabled 的控件；或者明确写“入库完成后才可用”。

### 12.3 网格两个开关的定义

- “素材库网格显示”：已入库素材卡片下方显示主色色条。
- “入库网格显示”：待入库清单卡片下方显示主色色条。当前入库前通常还没有 palette，默认不可用。

不能用“网格显示”这种没有页面范围的简称；每个设置标签必须写清页面。

## 13. FB3-11：数据与缓存设置的白话说明

### 13.1 媒体元数据回填

白话：重新读取文件本身的技术信息，不改变原文件和标签。例如分辨率、编码、时长、帧率、音频编码、拍摄参数。适用场景：旧素材导入时读取失败、程序升级后增加了新字段、视频时长显示为空。

按钮：

- “只补缺失信息”：只处理空字段，速度快，风险低。
- “重新读取全部视频”：覆盖视频技术信息，耗时更长。

必须显示总数、成功、失败、跳过和取消；失败记录原因，不阻塞其他素材。

### 13.2 算法色板回算

白话：用本地算法从图片或视频封面估算主色，生成色条和按颜色筛选所需的色相/饱和度/明度索引。不调用 AI，不会创建标签。

按钮：

- “只补缺失色板”：只处理还没有色板的素材。
- “全部重新计算”：覆盖旧色板，适用于更换算法版本或结果明显不准。

视频没有封面时应显示“跳过：请先生成视频封面”，不能把占位图误当成真实画面。

### 13.3 其他缓存

- 高清缩略图缓存：删除后会按需重新生成，不影响原文件。
- 视频代理缓存：原视频编码不兼容时生成 H.264/AAC 临时副本；清理代理不删除原视频。
- Ollama 安装包缓存：用于离线重装，删除后下次需要重新下载。

设置页每个危险按钮都必须写清“会删除什么、不会删除什么、是否可重新生成”。

## 14. UI 和代码开发规范

### 14.1 UI 信息架构

- 设置页使用“分组标题 + 用户语言说明 + 控件”的三段结构。
- 复杂技术字段放“高级设置”；普通用户先看到服务名称、地址、模型、是否已配置密钥和测试结果。
- 不使用内部术语作为主标签：`batchLimit` 不直接显示“执行分块大小”，`facetKey` 不当作分类名称。
- 无效、尚未实现或只对某部署生效的设置必须隐藏或明确标注，不做永久 disabled 噪音。

### 14.2 布局和响应式

- 所有固定格式组件给出稳定尺寸：播放器、胶片条、网格卡片、控制条、按钮。
- flex 子项涉及滚动时补 `min-w-0/min-h-0`；滚动容器必须只有一个明确 owner。
- 禁止用 `height:auto` 做折叠动画；超级搜索继续使用 `grid-template-rows: 0fr/1fr`。
- 不用负 margin 把说明文字压到边框线上。
- 页面区块不套多层装饰卡片；卡片只用于重复条目、弹窗和真正需要框定的工具。

### 14.3 媒体和事件

- 图片和视频共用舞台尺寸契约；媒体内容 `object-contain`，不能拉伸。
- 原生 wheel 需要 `passive:false`；事件清理必须成对。
- 所有异步媒体回调带 asset generation 或取消标记。
- 媒体协议失败显示“路径/编码/权限/代理”层面的可读错误，不把裸 Rust 栈展示给用户。

### 14.4 安全

- API key 只进系统凭据，前端只看 `hasKey`。
- 连接测试日志绝不打印 key、完整 URL query token 或 base64 图片。
- asset scope 只放行用户明确选择的媒体和必要缓存目录；不能为了预览重新放开整个数据目录。
