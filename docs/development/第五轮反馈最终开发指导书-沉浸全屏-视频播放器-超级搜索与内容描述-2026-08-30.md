本轮以下产品决定已经写死，施工 AI 不得自行更改：

1. “全屏浏览”是媒体内容沉浸模式，不是简单把窗口最大化。
2. 图片沉浸背景固定纯白，不随深色主题变黑；视频沉浸背景固定黑色。
3. 沉浸图片中不常驻工具栏、标签、属性、色条、胶片条或退出按钮；按 `Esc` 退出。
4. 视频控制条必须叠加在视频画面内，禁止继续占用视频下方的独立白色区域。
5. “一句话描述”要显示在大图浏览的标签区域，但它仍是独立素材字段，不是标签分面：不得进入素材库左侧智能标签树、可删除的标签 chips、标签管理页或标签统计。
6. 一句话描述最多 20 个 Unicode 字符，作为素材字段保存，并加入全文搜索。
7. AI 搜索结果以后端返回的 `QueryExpr` 为唯一执行事实源，前端不得从扁平 query 再猜一棵 AND 树。
8. 模型列表发现失败不能阻止用户手动填写模型名称。

## 2. 当前代码根因分析

### 2.1 FB5-01：当前所谓全屏仍是“带工具栏的查看器”

直接证据：

- `src/components/viewer/ViewerShell.tsx`
  - `fullscreen` 分支仍然渲染 `{toolbar}`；
  - 背景固定 `bg-black`，图片也被放在黑色环境；
  - 只隐藏属性栏、标签区和胶片条，没有做到“只剩图片”。
- `src/components/library/ViewerPage.tsx`
  - `isFullscreen` 使用 `Boolean(document.fullscreenElement) || fsFallback`；
  - 它把“任何元素进入 Fullscreen API”都当成查看器全屏，包括 VideoPlayer 自己的 fullscreen；
  - 真全屏与应用内降级共用一个布尔值，无法准确区分退出路径和渲染层级。
- `src/components/media/VideoPlayer.tsx`
  - 播放器还有自己独立的 `boxRef.requestFullscreen()`，与 ViewerPage 的全屏入口形成两个事实源。
- `src/components/viewer/StageFrame.tsx`
  - 始终使用主题背景和 `p-4`，没有图片沉浸白底语义。
- `src/components/viewer/MediaViewport.tsx`
  - 左键只有在 `scale > 1` 时才能平移；沉浸模式下 1 倍图片不能自由移动。

结论：Fullscreen API 本身不是问题。问题是应用把“请求系统全屏”和“沉浸内容布局”混成同一个布尔开关，而且沉浸分支仍保留查看器 chrome。

### 2.2 FB5-02：视频控制条丑是结构和原生控件共同造成的

直接证据：

- `VideoPlayer.tsx` 使用 `flex-col`，视频媒体区 `flex-1`，`VideoControls` 是底部 `shrink-0` 兄弟节点。
- `VideoControls.tsx` 根节点使用：

```tsx
border-t
bg-[var(--color-surface-raised)]
```

浅色主题下就是明显的白色整条底板。

- 进度与音量直接使用没有组件样式的原生 `<input type="range">`，WebView2 默认呈现蓝色轨道和系统 thumb。
- 倍速使用原生 `<select>`，与图标按钮的视觉语言不一致。
- 根节点允许 `overflow-x-auto`，控件稍多就会产生横向滚动感，而不是稳定的播放器布局。

结论：只改颜色不能解决。必须把控制条从文档流移入视频画面，统一自定义 range、按钮、菜单和显示时机。

### 2.3 FB5-03：披露按钮位置与信息层级不对

`src/pages/SuperSearchPage.tsx` 当前把文字按钮放在 chips 与结果数同一行的最右侧：

```text
条件 chips -------------------------------- 259项  展开详细条件
```

这使它看起来像一个额外操作命令，而不是“展开下方区域”的空间控制。用户想要的是位于中间的下拉把手。

现有 `useScrollDirection`、header 与结果滚动容器分离、`grid-template-rows` 折叠方式都应保留；本问题只改披露控件的位置和视觉。

### 2.4 FB5-04：模型列表能力存在，但连接管理没有接通

当前仓库已经存在：

- `src/components/common/ModelSelect.tsx`
- `src/api/ai.ts` 的 `aiListModels`
- `src-tauri/src/commands/ai_cmd.rs` 的 `ai_list_models`
- `src-tauri/src/services/ai_cloud.rs` 的 `/models` 解析

但 `src/components/settings/AiConnectionManager.tsx` 仍使用普通文本 input：

```tsx
<input value={form.model} ... />
```

不能直接复用旧 ModelSelect 的原因也已明确：

- 新连接档案把 API Key 放在系统 keyring；
- 编辑连接时前端故意把 `apiKey` 留空，表示保留原密钥；
- 旧 `aiListModels(baseUrl, apiKey, apiMode)` 要求前端提供明文 key；
- 因此前端无法使用已保存密钥拉模型列表。

结论：不是新增一个 select 就结束，而是要把“模型发现”迁移到连接档案命令层，让 Rust 从 keyring 取密钥。

### 2.5 FB5-05：超级搜索同时存在十个逻辑缺陷

用户截图输入：

```text
晚上拍的然后有树还有多人
```

合理结果应是：

```text
光线/时间：夜间
主体/对象：树
人物属性：多人（或人群，二者只能保留一个规范标签）
关系：全部满足
素材类型：全部
```

不应存在整句关键词。

当前实现的具体问题：

#### 问题 A：模型可同时输出 `tags` 和 `concepts`

`SearchIntent` 同时包含：

- `search`
- `tags`
- `excludeTags`
- `concepts`
- `unresolved`
- `relation`

模型可以把“树”放进 tags，又把“树”放进 concepts。`compile_concepts` 再把 concepts 追加到 tags，形成双源。

#### 问题 B：只按文字去重，不按最终 tagId 去重

`compile_concepts` 只比较标准化文字。“人群”和“多人”文字不同，即使它们最终指向同一语义或同一规范标签，也会形成两个条件。

#### 问题 C：unresolved 被无条件拼成一个全文关键词

当前代码：

```rust
let join = intent.unresolved.join(" ");
out.search = Some(...join...);
```

这正是截图中出现 `关键词：晚上拍的然后有树还有多人` 的路径。

#### 问题 D：当前全文索引没有画面描述

`assets_fts` 只有：

- `file_name`
- `tag_names`

搜索整句自然语言，只会去文件名和标签文本中寻找整句或分词组合。素材从未保存过“夜晚树下多人”这样的内容描述，所以零命中是必然结果。

#### 问题 E：relation 只展示，不参与执行

后端返回 `relation`，前端保存它用于 chips，但 `resolve_query` 仍生成扁平 facetFilters；`superSearchStore` 又调用 `resolvedQueryToExpr(result.query)`，固定重建为 AND 树。

因此模型即使正确输出 `relation="or"`，实际数据库查询仍不是 OR。

#### 问题 F：已有标签值可能显示成空选择

QueryBuilder 的 tag select 选项来自当前 `tagStore.tree`。AI 返回的 resolved tagId 如果不在当前树快照里，select 有非空 value 却找不到 option，界面就显示“选择标签”。

当前 `rowsToExpr` 已使用 `isComplete` 过滤手动编辑中的空 `tagIds` 行，因此“空编辑行直接触发后端标签条件不能为空”不是现存根因。后端 `validate_expr` 仍须保留该校验作为防御；本轮前端重点是为已有非空 tagId 注入 synthetic option，不能把真实条件错误显示成“选择标签”。

#### 问题 G：全局 relation 无法表达 OR 子句分组

即使把当前 relation 真正执行，`晚上拍的树或者白天拍的建筑` 也只能得到 `OR(夜间, 树, 白天, 建筑)`，会错误命中只含任意一个概念的素材。用户真正需要的是 `(夜间 AND 树) OR (白天 AND 建筑)`，因此协议必须直接表达 group，不能只修一个 relation 开关。

#### 问题 H：同分面多概念被错误合并为 any

当前 `resolve_query` 会把同一分面的多个概念塞进一个 `ResolvedFacet(mode="any")`。“有树还有花”因此执行成“树 OR 花”，而不是“树 AND 花”。V2 必须为每个概念生成独立 leaf，禁止沿用按分面合并的旧逻辑。

#### 问题 I：FilterChips 与 expr 双源

FilterChips 读取扁平 `query.facetFilters`，执行层却可能使用 expr；OR/NOT 查询会出现“界面显示一套、数据库执行另一套”。删除 chip 又会调用 `setQuery` 清空 expr，造成删除一个条件却丢失整棵 AI 查询。

#### 问题 J：提示词词典实际没有别名

`collect_tag_dictionary` 当前只读取规范标签名，没有 join `tag_aliases`，但旧注释和 prompt 假设模型能看到别名。模型无法仅凭规范名稳定判断“多人/人群”等同义词，本轮必须把可搜索别名真正加入词典，并继续由后端 tagId 去重兜底。

## 3. 最终体验设计

### 3.1 查看器正常模式

正常查看器继续保留：

```text
工具栏
属性栏 | 媒体舞台
         色条
         标签双栏
单行胶片条
```

第四轮已经确定的尺寸和布局不得因本轮全屏改造回归。

### 3.2 图片沉浸模式

进入“全屏浏览”后，DOM 可见内容应等价于：

```text
┌──────────────────────────────────────────────┐
│                                              │
│              纯白媒体画布                    │
│                                              │
│                 当前图片                     │
│                                              │
└──────────────────────────────────────────────┘
```

硬性要求：

- 不渲染 ViewerToolbar。
- 不渲染应用 TitleBar 和 BottomBar。
- 不渲染属性栏、标签区、色条和胶片条。
- 不显示文件名、页码、缩放百分比 badge 或常驻退出按钮。
- 背景固定 `#ffffff`，即使应用主题为深色也不改变。
- 图片保持原始宽高比，不拉伸。
- 初始状态为适应屏幕并居中，桌面安全留白 24px，窄窗口留白 12px。
- 左键可以平移图片，即使当前缩放为 1 倍；中键平移继续兼容。
- Alt+滚轮继续按指针锚点缩放。
- 双击在 1x/2x 间切换；已放大时双击回到适应屏幕状态并居中。
- 平移时至少保留 48px 图片边缘在画布内，防止整张图丢到屏幕外无法找回。
- `Esc` 退出沉浸模式，回到同一素材的正常查看器。

不增加可见使用说明。进入按钮的 `title` 可以写“全屏浏览（Esc 退出）”。

### 3.3 视频沉浸模式

- 同一“全屏浏览”状态机处理视频，不再由 VideoPlayer 单独请求第二套 fullscreen。
- 背景固定黑色。
- 只渲染视频和播放器悬浮控制条。
- 控制条在播放且无操作时自动隐藏；暂停、键盘聚焦、鼠标移动时显示。
- `Esc` 退出回正常查看器。

### 3.4 视频控制条视觉

控制条固定叠在视频底部，不参与视频高度计算：

```text
视频画面

      ┌────────────────────────────────────────┐
      │ ━━━━━━━━━━━━━━━───────────────          │  进度
      │  ▶  ↶5  ↷5   1:24 / 4:18    1x  🔊  ⛶ │  控制
      └────────────────────────────────────────┘
```

尺寸与样式：

- 位置：`absolute bottom-4 left-1/2 -translate-x-1/2`。
- 宽度：`min(760px, calc(100% - 24px))`。
- 最小高度：64px，进度层 20px，按钮层 36px。
- 圆角：8px，不使用大胶囊圆角。
- 背景：`rgba(20, 20, 22, 0.82)`。
- 边框：`1px solid rgba(255,255,255,0.12)`。
- 阴影：轻量黑色阴影，不发光。
- 可使用 `backdrop-filter: blur(18px)`；WebView 不支持时保持不透明深色兜底。
- 图标统一 lucide，16–18px，`strokeWidth=1.75`。
- 图标和时间文字为白色或白色 80%，不使用主题蓝色。
- hover 背景为白色 10%–12%。
- 播放进度已播放部分为白色，未播放为白色 24%，缓存部分为白色 38%。
- thumb 为 10px 白色圆点，hover/focus 扩到 12px。

交互：

- 播放中 1800ms 无鼠标、键盘或触摸操作后隐藏控制条。
- 暂停、loading 结束但未播放、自动播放被拒时始终显示。
- `focus-within` 时始终显示，键盘用户不能失去控件。
- 鼠标移动、pointerdown、focus 立即显示并重置计时器。
- 视频单击仍切换播放/暂停。
- 视频双击切换沉浸模式。
- 进度拖动、音量拖动、倍速菜单点击必须 `stopPropagation`，不得误触视频播放。

响应式：

- 宽度 ≥ 640px：显示全部控件。
- 宽度 < 640px：隐藏常驻音量滑条，只保留静音图标；点击或 hover 图标再弹出音量滑条。
- 宽度 < 480px：隐藏 ±5 秒文字外的非核心信息，但保留播放、进度、时间、静音和全屏。
- 禁止横向滚动控制条。

## 4. 沉浸浏览代码设计

### 4.1 状态机

在 `ViewerPage.tsx` 中删除当前泛化的：

```ts
const isFullscreen = Boolean(document.fullscreenElement) || fsFallback;
```

改成查看器拥有的明确状态：

```ts
type ImmersiveMode = "off" | "native" | "fallback";
```

派生：

```ts
const immersive = immersiveMode !== "off";
```

状态转移：

```text
off --点击全屏--> 尝试 viewerRoot.requestFullscreen()
  成功 -> native
  失败/不可用 -> fallback

native --Esc/fullscreenchange 且 fullscreenElement 退出 viewerRoot--> off
fallback --Esc/再次切换--> off
```

关键约束：

- 只在 `document.fullscreenElement === viewerRootRef.current` 时认定 native viewer fullscreen。
- VideoPlayer 的元素进入 fullscreen 不能改变 ViewerShell 模式；本轮应移除播放器自己的独立 requestFullscreen，统一调用 ViewerPage。
- fallback 模式使用 `createPortal` 把沉浸层挂到 `document.body`，样式为 `fixed inset-0 z-[100]`；不要把 fixed 层留在 `<main>` 的潜在 stacking context 中。当前 BottomBar 为 `z-30`、TitleBar 无显式 z-index，`z-[100]` 留出清晰层级余量。
- fallback 进入后先把焦点移入沉浸媒体画布，再让应用根节点（不含 portal）进入 `inert`；退出、Viewer 卸载或异常时必须移除 `inert`。仅用视觉遮盖而让 TitleBar 控件继续被 Tab 聚焦不合格。
- native 模式依赖 Fullscreen API 覆盖整个显示器；fallback 覆盖整个应用窗口。
- `fullscreenchange` 监听卸载时清理。
- Viewer 关闭或切出页面前，若 native 模式仍在，先请求 `document.exitFullscreen()`，失败也要清本地状态。

### 4.2 ViewerShell

将 prop 从含糊的 `fullscreen?: boolean` 改为：

```ts
immersive: boolean;
```

沉浸分支只能返回 stage：

```tsx
if (immersive) {
  return (
    <div data-viewer-immersive className="flex h-full min-h-0 flex-col">
      <div className="flex min-h-0 min-w-0 flex-1">{stage}</div>
    </div>
  );
}
```

禁止在该分支渲染 toolbar、sidebar、tagBar 和 filmstrip。这里应从结构上卸载，不是用 opacity 或 visibility 隐藏。

### 4.3 MediaViewport 与 StageFrame

新增 props：

```ts
immersive: boolean;
onToggleImmersive?: () => void; // 视频双击或未来触摸使用
```

StageFrame 增加明确 surface：

```ts
surface: "app" | "image-immersive" | "video-immersive";
```

对应样式：

| surface | 背景 | padding |
|---|---|---:|
| app | 当前主题背景 | 16px |
| image-immersive | `#fff` | 24px，窄屏 12px |
| video-immersive | `#000` | 0 |

图片交互改动必须有模式护栏：

```ts
const canLeftPan = immersive || view.scale > 1;
```

正常模式仍保持“未放大时左键不拖拽”，不能因为沉浸需求破坏普通查看器的双击行为。

图片进入/退出沉浸或切换 assetId 时重置为居中适应状态。平移约束单独抽成纯函数并测试，例如：

```ts
clampImmersiveOffset(...)
```

不要在 pointermove 内散落 DOM 尺寸算法。

### 4.4 视频全屏入口统一

`VideoPlayer` 新增：

```ts
immersive: boolean;
onToggleImmersive: () => void;
```

删除：

- `boxRef.current?.requestFullscreen()`
- VideoPlayer 内部 `fs` 事实源
- 监听任意 `document.fullscreenElement` 的播放器全屏状态

`VideoControls` 的全屏图标直接使用父级传入的 `immersive`，点击调用 `onToggleImmersive`。

这样工具栏“全屏浏览”、视频控制条全屏按钮、`F` 快捷键都进入同一个 Viewer immersive 状态。

## 6. AI 模型发现架构

### 6.1 废弃旧的明文 key 模型列表入口

旧 API：

```ts
aiListModels(baseUrl, apiKey, apiMode)
```

与连接档案/keyring 架构冲突。本轮新增统一命令后：

1. 更新所有调用方使用新命令；
2. 确认无调用后删除旧 `ai_list_models` Tauri 命令和旧前端封装；
3. 不允许仓库继续存在两个模型列表协议。

### 6.2 新请求与返回 DTO

前端：

```ts
export interface DiscoverAiModelsInput {
  connectionId?: string | null;
  deployment: "cloud" | "local";
  protocol: "openai_chat" | "anthropic_messages";
  baseUrl: string;
  apiKey?: string | null; // 新连接或用户刚输入的新 key；不回显
}

export interface AiModelOption {
  id: string;
}

export interface DiscoverAiModelsResult {
  models: AiModelOption[];
  discoverySupported: boolean;
  message: string;
}
```

命令：

```text
discover_ai_models(input) -> DiscoverAiModelsResult
```

密钥解析优先级：

1. `input.apiKey` 非空：使用本次临时输入，不记录日志。
2. `connectionId` 存在：从数据库读取连接，再从 keyring 读取密钥。
3. 本地服务且两者都无 key：允许无鉴权请求。
4. 在线服务仍无 key：返回“请先填写或保存 API 密钥”。

### 6.3 协议与 URL

统一抽取：

```rust
fn model_list_url(base_url: &str, protocol: &str) -> AppResult<String>
```

规则：

- 去除尾斜杠，拒绝空 URL、非 http/https 和带明文凭据的 URL。
- OpenAI 兼容：在用户填写的 API 根后追加 `/models`；不擅自替所有中转站增加 `/v1`。
- Anthropic：设置页 placeholder 使用 `https://api.anthropic.com/v1`，在其后追加 `/models`。
- 检测并避免 `/models/models` 与双斜杠。
- 连接测试的 `/messages` 也应复用同一 base join helper，避免模型发现与实际调用路径不一致。
- OpenAI 兼容连接测试或模型列表返回 404 时，错误文案补充“服务地址可能需要补全 `/v1` 路径”；只提供诊断建议，不自动改写用户地址。

鉴权：

- OpenAI 兼容：`Authorization: Bearer ...`
- Anthropic：`x-api-key` + `anthropic-version`
- 本地无 key：不发送 Authorization 空头。

### 6.4 宽容解析与错误分类

解析至少支持：

```json
{"data":[{"id":"model-a"}]}
{"models":[{"id":"model-a"}]}
[{"id":"model-a"}]
```

只接受非空字符串 id，trim、去重、排序。不得把完整原始响应或 API Key写入错误信息。

本轮不额外支持 Ollama 原生 `/api/tags`；Ollama 按其 OpenAI 兼容 `/v1/models` 接入。不要为了“多支持一种格式”扩出第二套协议路由。

错误分类：

| 状态 | 前端表现 |
|---|---|
| 200 且有模型 | 展开可选列表 |
| 200 但无法解析 | `discoverySupported=false`，允许手填 |
| 404/405 | 服务不支持模型列表，允许手填 |
| 401/403 | 密钥或权限错误 |
| timeout/network | 网络或地址错误，可重试 |
| 429 | 请求过于频繁，保留当前输入 |

### 6.5 组件复用

不要把 `ModelSelect.tsx` 整份复制到 AiConnectionManager。重构为：

```text
ModelCombobox             纯展示与输入
ConnectionModelField      负责 discoverAiModels 调用
```

`AiConnectionManager.EditFields` 使用 `ConnectionModelField`。

`AiTaggingPage` 当前仍使用 legacy `ApiProfile`，没有 `connectionId`，不得在迁移旧 `ai_list_models` 时漏掉。新增 `LegacyProfileModelField` wrapper，内部调用同一个 `discoverAiModels`：

```ts
  deployment: profile.kind === "local" ? "local" : "cloud",

  baseUrl: profile.baseUrl,
  apiKey: profile.apiKey,

```

显式映射：

```text

```

这里走 `input.apiKey` 临时密钥路径；不得伪造 connectionId，也不得把 legacy profile 静默迁成新连接档案。只有 `AiConnectionManager`、`AiTaggingPage` 和其他所有调用方都改用新命令且测试通过后，才能删除旧 `ai_list_models` / `aiListModels`。`ModelCombobox` 只负责输入、下拉、键盘和选择，不直接知道 keyring 或 profile。

## 7. 一句话描述数据设计

### 7.1 为什么不是标签分面

一句话描述具有以下特征：

- 每个素材只有一条自由文本；
- 文本组合性强，如“夜晚树下多人合影”；
- 不适合成为树节点或分类 chip；
- 主要价值是全文模糊检索，而不是分面统计；
- 用户明确要求它显示在大图浏览的标签区域，但不出现在素材库左侧智能标签导航中。

因此必须使用素材字段，不得创建 `description` facet，也不得把整句塞进 custom 标签。这里必须区分“展示位置”和“数据类型”：它可以在 `ViewerTagBar` 内展示，但不能因此进入 `TagTree`、`TagChip`、facet 统计或标签增删接口。

### 7.2 V17 数据库迁移

新增列：

```sql
ALTER TABLE assets
ADD COLUMN content_description TEXT NOT NULL DEFAULT '';

ALTER TABLE ai_suggestions
ADD COLUMN suggested_description TEXT NOT NULL DEFAULT '';

ALTER TABLE ai_suggestions
ADD COLUMN confirmed_description TEXT;

ALTER TABLE fts_content
ADD COLUMN content_description TEXT NOT NULL DEFAULT '';
```

迁移必须幂等，使用仓库现有 `add_column_if_missing`。所有对象重建使用明确的 `DROP ... IF EXISTS` / `CREATE ... IF NOT EXISTS`，并保持“全部对象与数据完成后最后写 `user_version=17`”，使中途崩溃后可以重新执行。

FTS5 虚拟表不能直接 ALTER 增加索引列，因此 V17 必须重建 `assets_fts`：

```sql
assets_fts(file_name, tag_names, content_description, ...)
```

迁移顺序：

1. 使用 `add_column_if_missing` 增加实体表与 `fts_content` 列。
2. `DROP TRIGGER IF EXISTS` 删除 `trg_fc_ai/trg_fc_ad/trg_fc_au`，以及需要改定义的 `trg_assets_ai/trg_assets_au`。
3. `DROP TABLE IF EXISTS assets_fts`，按 `file_name/tag_names/content_description` 三列重建虚表。
4. 以三列 old/new 值重建 `trg_fc_ai/trg_fc_ad/trg_fc_au`；delete 命令必须写全旧的三列值，防止幽灵 token。
5. 重建 assets insert/update 触发器：`trg_assets_ai` 同时写入 fileName 与 contentDescription；`trg_assets_au` 必须改为 `AFTER UPDATE OF file_name, content_description`，两列都经 `cjk_bigram` 写入 `fts_content`。
6. 保留 V8 已有“规范标签 + 可搜索别名 + active 状态”的 tag_names 聚合语义，不得退回 V1 的简单 group_concat。
7. 从 assets 回填 `fts_content.content_description`。
8. `INSERT INTO assets_fts(assets_fts) VALUES('rebuild')`。
9. 完成后设置 `user_version=17`。

禁止从旧 `fts_content` 中间值反推描述；描述事实源始终是 assets。

步骤 4、5 必须在步骤 7 回填之前完成，让回填 UPDATE 经过新三列触发器；不得先回填、后换触发器。重复运行 V17 时允许再次 drop/recreate/rebuild，但不能重复丢业务数据。

### 7.3 Asset DTO

Rust `Asset` 与前端 `Asset` 增加：

```text
contentDescription / content_description
```

为了减少固定列索引错误，新列固定追加到当前 palette 字段之后，并同步：

- `ASSET_COLS`
- `from_row`
- list/get 查询
- 测试 fixture
- TypeScript 测试中的最小 Asset 构造器

不得返回 `fts_content` 的 bigram 文本给前端。

### 7.4 AI 分析结果

将 AI 打标内部结果从：

```rust
CategorizedTags
```

升级为：

```rust
pub struct MediaAnalysis {
    pub description: String,
    pub tags: CategorizedTags,
}
```

模型 JSON 协议：

```json
{
  "description": "夜晚树下多人合影",
  "tags": {
    "subject": ["树"],
    "lighting": ["夜间"],
    "people": ["多人"]
  }
}
```

提示词必须明确：

- description 是画面内容的一句话中文描述；
- 最多 20 个字符；
- 不写文件质量、摄影建议或“这是一张”；
- 不堆砌逗号标签；
- tags 仍使用稳定英文 facetKey；
- description 不得复制进任何 tags 数组。

### 7.5 描述规范化

抽取纯函数：

```rust
fn normalize_content_description(raw: &str) -> String
```

顺序：

1. trim。
2. 换行和连续空白折叠为单空格。
3. 去除开头“这是一张/这张图片展示/画面中有”等无信息套话。
4. 取第一个完整句段，去掉句末 `。！？`。
5. 按 Unicode chars 截到最多 20 个字符，不按 UTF-8 bytes。

描述为空不能导致有效标签整条失败；保存空描述并在审核界面显示“未生成描述”。标签为空但描述非空也算一次有效分析，不能因旧 `parse_tags_strict` 规则直接拒绝。

### 7.6 建议审核与确认

`AiSuggestion` DTO 增加：

```ts
suggestedDescription: string;
confirmedDescription: string | null;
currentDescription: string;
```

AI 工作台在标签分面上方增加独立字段：

```text
一句话描述      [夜晚树下多人合影             ]  9/20
```

UI 规则：

- 单行 input，不是 TagChip。
- `maxLength={20}`，字符计数使用 JS 字符迭代语义，不能按 byte。
- 标签分面滚动时描述字段保持在建议编辑区顶部。
- 在 AI 打标审核区显示并允许编辑；在大图浏览的 `ViewerTagBar` 中只读显示。
- 不在素材库左侧 `SideBar` / `TagTree` 中出现，也不参与左侧分类数量、标签筛选或标签管理。
- 大图浏览中的常驻只读展示位置统一为 `ViewerTagBar`；不要再在 `ViewerInfoSidebar` 重复增加同一行，避免一个页面出现两份相同信息。

### 7.6.1 ViewerTagBar 展示规格

`ViewerTagBarProps` 增加：

```ts
contentDescription?: string | null;
```

`ViewerPage` 在正常浏览模式传入当前素材字段：

```tsx
<ViewerTagBar
  assetId={current.id}
  tags={current.tags}
  contentDescription={current.contentDescription}
  onRemoveTag={...}
  onAddTag={...}
/>
```

展开后的标签正文顶部增加一个合成的全宽只读行：

```text
一句话描述 | 夜晚树下多人合影
主体/对象   | 人物  树木          场景/地点 | 夜景  户外
```

硬性规则：

- 描述行放在现有 `viewer-tagbar-body` 内部第一项，使用 `col-span-2` 横跨两栏；后面的真实标签分面继续保持双栏，不能把素材缩略图或整个查看器改成两栏。
- 描述行内部沿用标签分面行的对齐方式，建议 `grid-cols-[76px_minmax(0,1fr)]`；左列固定显示“一句话描述”，右列显示正文。
- 正文是普通只读文本，不渲染 `TagChip`，没有删除按钮、颜色圆点、hover 筛选或点击筛选行为。
- `trim()` 后为空时完全不渲染描述行，不保留空白占位；有描述但没有真实标签时，只显示描述行，不显示“未打标”。
- 标题栏的“标签 N 项”只统计 `tags.length`，一句话描述不计入数量。
- 展开总高度继续固定 128px，标题栏 32px、正文滚动区 96px；不得因增加描述行让查看器舞台跳动。内容超过 96px 时由正文现有 `overflow-y-auto` 统一滚动。
- 描述最多 20 字，优先完整换行展示，不使用横向滚动；不得为了描述另加卡片、背景胶囊或独立面板。
- 折叠 `ViewerTagBar` 时描述随正文一起隐藏；进入沉浸全屏时整个 `ViewerTagBar` 仍不渲染。
- 不把 `contentDescription` 传给 `SideBar`、`TagTree`、`buildWorkbenchFacets` 或标签 store；素材库左侧侧栏必须保持原有真实标签树结构。

确认语义：

- 单条确认：确认标签的同一事务内，把非空 confirmed/suggested description 写入 `assets.content_description`。
- 批量确认：逐条应用各自描述，不得把第一张描述套给整批。
- 建议被拒绝：不修改素材描述。
- 新建议描述为空：保留素材已有 `content_description`，不覆盖为空。
- 用户在审核 input 中修改后的值写入 `confirmed_description` 并落素材表。
- `aiApplyTags` 只用于批量标签套用，不修改描述。

### 7.7 视频描述

- cover 模式：使用封面分析返回的 description。
- frames 模式：每帧返回 `MediaAnalysis`；标签仍按现有频次规则合并；描述选择时间上最接近视频中点的成功帧描述。
- 不为合并描述额外发送第二次 AI 请求，避免每个视频增加不可见费用。
- 所有帧描述为空时保持空描述，不影响标签结果。

## 8. 全文搜索升级

### 8.1 搜索范围

普通全文搜索现在包含：

- 文件名
- 规范标签名
- 可搜索标签别名
- `content_description`

更新 `src-tauri/src/db/search.rs`：

- FTS 谓词默认搜索三列。
- LIKE fallback 增加 `a.content_description LIKE ?`。
- 参数数量与顺序同步测试。
- 中文 bigram 逻辑继续复用，不另写一套描述分词。
- 这是全局行为变化：普通素材库搜索也会开始命中一句话描述，不只超级搜索。必须补普通搜索回归与真机抽查，不能把结果变宽误判成 bug。

### 8.2 Search 叶子增加 scope

为了区分普通全文、AI 未映射的内容概念、精确描述列和文件名，扩展 QueryExpr：

```ts
type SearchScope = "all" | "content" | "description" | "fileName";

{ type: "search"; value: string; scope?: SearchScope }
```

Rust 对应字段使用 `#[serde(default)]`，旧数据缺 scope 时按 `all`。

编译语义：

| scope | 搜索范围 |
|---|---|
| all | 文件名 + 标签 + 描述 |
| content | 文件名 + 描述；AI 未映射的具体画面概念使用此范围 |
| description | 只搜 content_description |
| fileName | 只搜 file_name |

QueryBuilder 字段显示为：

- 关键词（全部文字）
- 内容文字（描述或文件名）
- 内容描述
- 文件名

不得在 UI 展示 FTS、bigram 等实现词。

### 8.3 SQL 编译规格

函数签名改为：

```rust
pub fn build_search_predicate(
    conn: &Connection,
    raw: &str,
    scope: SearchScope,
) -> AppResult<Option<SearchPredicate>>
```

所有普通素材库旧调用显式传 `SearchScope::All`；`LeafCond::Search` 把自身 scope 传入。Rust `SearchScope` 使用 serde camelCase，并为缺省字段实现 `Default::default() == All`。

范围矩阵：

| scope | FTS 列 | LIKE 列/子查询 |
|---|---|---|
| all | 无列限制，搜索三列 | `file_name OR content_description OR 规范标签/可搜索别名` |
| content | `{file_name content_description}` | `file_name OR content_description` |
| description | `content_description` | 仅 `content_description` |
| fileName | `file_name` | 仅 `file_name` |

长度路由继续保持当前语义，但每条路径都必须接收 scope：

| 输入 | 路径 | scope 要求 |
|---|---|---|
| 1–2 字 | LIKE only | 必须使用对应 LIKE 变体；这是“夜景”等两字描述能否命中的唯一入口 |
| 含非 CJK 且 >2 字 | FTS phrase OR LIKE | 两部分使用相同 scope |
| 纯 CJK 3 字 | FTS phrase | MATCH 查询加对应列前缀 |
| 纯 CJK ≥4 字 | bigram chunk AND | 每个 chunk 都加对应列前缀，不能只在整串最前面加一次 |

抽取纯 helper，避免四条路径各自拼列名：

```rust
fn scoped_fts_term(scope: SearchScope, quoted_term: &str) -> String;
fn like_predicate(q: &str, scope: SearchScope) -> SearchPredicate;
```

FTS 产物语义示例：

```text
all:         "银 杏" AND "杏 树"
content:     {file_name content_description}:"银 杏" AND {file_name content_description}:"杏 树"
description: content_description:"银 杏" AND content_description:"杏 树"
fileName:    file_name:"银 杏" AND file_name:"杏 树"
```

列名只能由 `SearchScope` 枚举映射，绝不能来自模型或用户字符串。LIKE 参数数量必须按 scope 精确生成，禁止沿用 all 的固定参数数组去匹配单列 SQL；加入 description 后 all 路径应覆盖 fileName、description、tag name、alias 四类参数。

## 9. 超级搜索 SearchIntent V2

### 9.1 删除多源字段与全局 relation

旧 SearchIntent 中以下字段删除：

- `search`
- `tags`
- `excludeTags`
- `unresolved`
- `relation`

只保留一套分组概念事实源。模型直接输出“组内 AND、组间 OR”的结构，不再让后端从一个全局 relation 猜子句边界：

```rust
pub struct SearchIntentV2 {
    pub groups: Vec<SearchGroupV2>,
    pub exclusions: Vec<SearchConceptV2>,
    pub sort_by: Option<String>,
    pub sort_dir: Option<String>,
}

pub struct SearchGroupV2 {
    pub asset_type: String, // all | image | video
    pub concepts: Vec<SearchConceptV2>,
    pub text_terms: Vec<IntentTextTerm>,
    pub metadata: Vec<MetadataFilter>,
}

pub struct SearchConceptV2 {
    pub text: String,
    pub role: String,
    pub facet_hint: Option<String>,
    pub confidence: f32,
}

pub struct IntentTextTerm {
    pub text: String,
    pub scope: String, // all | content | description | fileName
}
```

语义写死：

- 一个 group 内所有有效条件必须同时满足。
- 多个 group 之间是 OR。
- `exclusions` 对整个正向结果做全局 NOT。
- 没有明确“或/或者/任一”时必须只有一个 group。
- `晚上拍的树或者白天拍的建筑` 必须输出两个 group，最终是 `(夜间 AND 树) OR (白天 AND 建筑)`，禁止展开成 `OR(夜间, 树, 白天, 建筑)`。
- `不要夜景的人像` 输出一个含“人像”的 group，加全局 exclusion“夜景”。

这样模型不再有两种方式表达同一个“树”，也不再有无法表达子句边界的扁平 relation。

### 9.2 Prompt 硬规则

系统提示词必须包含以下规则：

1. 每个 concept 必须是原子化规范名词或短名词短语，中文优先 1–6 字；禁止输出“晚上拍的树”“画面中有很多人”这类句子片段。
2. 连接、方位和语法词不作为 concept。共享停用词至少包含：`然后、还有、有、和、与、并且、再、里面、画面中、上面、中间、旁边、拍的、一个、一些`。
3. 同义概念只输出一次，例如“多人、人群”根据词典选择一个，不同时输出。
4. `assetType` 只有在用户明确说图片/照片/视频时填写；不能因为用户说“拍的”就自动设为 image。
5. “晚上拍的”应解析为“夜间”或“夜景”概念，不保留整句。
6. 能映射为标签或元数据的概念不进入 textTerms。
7. 只有明确文件名片段、引号中的原文、专有名词或无法映射的具体内容才进入 textTerms。
8. 未映射的具体画面词使用 `scope=content`，搜索描述或文件名；不得把整句放进 `all` 或 `description`。
9. 没有明确 OR 词时只输出一个 group；“或/或者/任一”连接的每个完整子句各输出一个 group，组内概念保持 AND。
10. “不要/排除/除了”对应的原子概念放入全局 `exclusions`，不混入正向 group。
11. 不输出 tagId、SQL、分页、空字符串条件或 schema 之外字段。

Prompt 必须包含本轮截图例子及期望 JSON，作为回归基准。

停用词必须在 Rust 定义为单一常量，例如 `SEARCH_CONCEPT_STOPWORDS`；prompt 文本由该常量生成，本地清洗复用同一集合，禁止维护两份会漂移的列表。

### 9.2.1 标签词典必须包含可搜索别名

当前 `collect_tag_dictionary` 只读取规范名，不能继续声称“含别名”。本轮改为：

- 只读取 active 标签和 `tag_aliases.is_searchable=1` 的别名。
- 每个规范标签一行，格式示例：`多人 | aliases: 人群, 多人合影`。
- 每分面最多 50 个规范标签，按已有稳定排序；每个标签最多 5 个可搜索别名。
- 去除换行与控制字符，整体 prompt 词典设置字符上限，超限时按分面公平截断，不能让一个分面占满上下文。
- 后端最终仍按规范名/alias 精确解析 tagId；词典只是帮助模型选规范概念，不是授权模型输出 tagId。

### 9.2.2 V2 严格 JSON Schema

`intent_schema()` 必须随 V2 整体重写，不能只改 Rust struct。根对象和所有嵌套对象都设置 `additionalProperties: false`。

根对象：

```json
{
  "required": ["groups", "exclusions", "sortBy", "sortDir"],
  "properties": {
    "groups": { "type": "array", "minItems": 0, "maxItems": 6 },
    "exclusions": { "type": "array", "maxItems": 20 },
    "sortBy": { "type": ["string", "null"] },
    "sortDir": { "type": ["string", "null"], "enum": ["asc", "desc", null] }
  }
}
```

每个 group 必填 `assetType/concepts/textTerms/metadata`；`assetType` 枚举 `all/image/video`。concept 必填 `text/role/facetHint/confidence`，其中 `facetHint` 为 string 或 null，`confidence` 为 0–1 number。textTerm 必填 `text/scope`，scope 枚举 `all/content/description/fileName`。数组均设置合理 maxItems，文本设置 maxLength；本地守卫仍须再次检查，不能把 schema 当唯一安全层。

Structured Output、JSON Object fallback、Plain fallback 三条解析路径最终都必须归一化为同一个 `SearchIntentV2` 并经过同一守卫。schema 测试必须断言旧字段 `search/tags/excludeTags/unresolved/relation` 不存在。

### 9.3 本地确定性守卫

不要完全相信模型。解析后在 Rust 做：

#### group 与 OR 守卫

- 原文没有“或、或者、任一、二选一”等明确 OR 词时，模型返回多个 group 必须合并为一个 AND group，并给非阻断 warning。
- 原文明确含 OR，但模型只返回一个无法可靠拆分的 group 时，不在本地按词面猜分组；保留一个 AND group并提示“或关系未能准确分组，已按全部满足执行”。
- group 最多 6 个；每个 group 清理空条件后若为空则删除。
- 相同 group 内按标准化概念去重；语义相同的重复 group 去重。

#### assetType 守卫

只有原始输入含明确词时接受：

- image：图片、照片、相片、图像
- video：视频、录像、片段、短片

模型无依据输出 image/video 时把对应 group 改回 all，并给非阻断 warning。

#### concept 清洗

- trim，去除首尾标点。
- 丢弃共享 `SEARCH_CONCEPT_STOPWORDS` 中的连接词和单独语法词。
- 拒绝明显句子化文本：超过 12 个 Unicode 字符，或仍包含多个连接/谓语片段时不作为 concept。
- 按标准化 text + role 去重。
- 所有 group 与 exclusions 合计最多 20 个概念。
- confidence 钳制 0–1。
- exclusions 与正向概念解析到同一 tagId 时，以 exclusion 为准并给 warning，避免生成 `A AND NOT A` 的必空查询。

### 9.4 标签解析策略

硬过滤只能来自可靠映射：

1. 规范名精确匹配。
2. alias 精确匹配。
3. 在 facetHint 范围内只有一个前缀候选，且 confidence ≥ 0.85。
4. 其他包含/模糊多候选不能像当前 `min_by_key` 那样擅自选最短名称。

无法可靠映射时：

- 正向 concept 且 confidence ≥ 0.55：在原 group 内转为 `scope=content` 的单概念 search leaf，搜索“一句话描述 OR 文件名”。它仍是显式硬条件，必须显示成可单独移除的“内容：银杏树”chip。
- exclusion 且 confidence ≥ 0.55：转成全局 `NOT(search scope=content)`；chip 显示“排除内容：银杏树”。
- confidence < 0.55：不进入硬筛选，放入 warnings 的“未采用概念”。

在 tagId 解析完成后再次去重：

- 相同 tagId 只保留一个 leaf。
- “人群/多人”若解析到同一 tagId，只显示一个条件。
- 同义词解析到不同规范标签时，以词典精确匹配优先；无法判断则不同时作为 AND 硬条件。
- 同一 group 内“树 + 花”即使属于同一 facet，也必须生成两个独立 tag leaf 并执行 AND；禁止重新合并成一个 `mode:any` 的同分面数组。

由于 20 字描述不可能覆盖画面全部细节，零结果时若 expr 含自动生成的 `scope=content` leaf，结果区显示非阻断建议：

```text
没有匹配结果。可尝试移除内容条件：银杏树
```

建议按钮必须通过 expr 节点路径只删除对应 leaf 后重新查询；不得自动隐藏条件、不得静默放宽，也不得清空整棵 AI 查询树。

### 9.5 后端直接生成 QueryExpr

`AiSearchParseResult` 增加：

```rust
pub expr: Option<QueryExpr>
pub sort_by: String
pub sort_dir: String
```

并删除 AI 返回对象中的扁平 `query` 执行条件，避免前端同时持有“扁平 query”和“真实 expr”两套 AI 事实源。`ResolvedSearchQuery` 仍可保留给手动/兼容链路，但 AI parse result 只返回 expr、排序、解释、warnings 与 resolvedTags。

执行树生成规则：

1. 每个 group 的 tag、metadata、text、assetType 生成独立 leaves。
2. group 内 0 个 leaf 则删除；1 个 leaf 直接使用；多个 leaf 包成 AND。
3. 只有一个有效 group 时直接使用；多个有效 group 包成 OR。
4. exclusions 各自解析为 `NOT(tag/search leaf)`，对整个正向 root 全局生效。
5. 最终为 `AND(positiveRoot, NOT..., NOT...)`；如果没有正向 root，可只由 NOT 条件组成。
6. 生成后调用统一 normalize：空组删除、单子节点组折叠、连续相同 AND/OR 扁平化、重复 leaf 去重。
7. 没有任何条件时 `expr=None`，不创建空 AND。

排序不塞进 expr；由 `AiSearchParseResult.sortBy/sortDir` 单独返回，前端写入现有 `ResolvedSearchQuery.sortBy/sortDir`。

废弃并删除 `missingFacetKeys` 字段；无法映射的概念已经有 content search/warning，不应伪装成“缺少分面条件”。

### 9.6 前端必须使用返回 expr

当前错误代码：

```ts
const aiExpr = resolvedQueryToExpr(result.query);
```

改为：

```ts
const aiExpr = result.expr;
```

replace 模式：

```text
expr = result.expr
query.sortBy = result.sortBy
query.sortDir = result.sortDir
```

append 模式：

```text
baseExpr = currentExpr ?? buildExprFromFilter(currentQuery)
expr = mergeQueryExpr(baseExpr, result.expr) // 两个完整查询组以 AND 合并
query 只同步 sortBy/sortDir，不从复杂 expr 反推扁平条件
```

`current_query` 后端参数当前完全未使用，且 append 已由前端明确合并 expr。本轮从 `ai_parse_search_query` Tauri 命令、前端 API 和调用处删除该参数；未来若实现“在结果内继续搜”，重新设计明确上下文协议，不保留假参数。

禁止前端根据 intent、groups 或 explanation 再自行拼树。

### 9.6.1 FilterChips 必须以 expr 为唯一条件源

当前 FilterChips 读取 `query.facetFilters` 并在删除时调用 `setQuery`，会造成两类严重错误：OR/NOT 展示与执行不一致；删除一个 chip 会清空整个 expr。必须改为：

```ts
type ExprPath = number[];

flattenExprForDisplay(expr, resolvedTags): ExprChipModel[];
removeExprAtPath(expr, path): QueryExpr | undefined;
normalizeExpr(expr): QueryExpr | undefined;
```

规则：

- chips 递归遍历 expr。AND 组显示“同时满足”，OR 根按组显示“任一组 1 / 任一组 2”，NOT 叶显示“排除：…”。
- `(夜间 AND 树) OR (白天 AND 建筑)` 必须在视觉上分成两个 OR 组，不能只显示“任一：夜间、树、白天、建筑”。
- 每个 chip 保存稳定的 expr path。删除只摘除该 path 节点，然后 normalize；0 子节点组删除，1 子节点组折叠。
- 删除 chip 调用 store 的 `removeExprAtPath` / `setExpr`，禁止调用会把 expr 置空的 `setQuery`。
- sort chip 不属于 expr，可继续来自 query 的 sortBy/sortDir，但使用独立 `setSort` action。
- “清除全部”调用 `clearConditions()`，明确同时清 expr 和兼容扁平筛选；不要通过构造一份旧 defaultQuery 间接清理。
- replace 模式用本次 `result.resolvedTags` 替换名称映射；append 模式按 tagId 合并旧映射与新映射，不能只保留最后一次 AI 结果。
- 用户删除 AI 条件时保留剩余 `resolvedTags` 名称映射，不能立刻把所有标签文案退化成 `标签#123`。可在 expr 更新后只清理已不再引用的映射。

`syncQueryFromExpr` 不再承担复杂树展示。若为了旧接口保留它，只允许对纯顶层 AND 叶子做兼容投影；遇到 OR/嵌套 NOT 必须保留 expr，返回显式 `flattenable=false`，不能静默生成空筛选并覆盖现状。

QueryBuilder 遇到当前无法编辑的嵌套树时：

- 不得将 expr 转成空 rows 后回写。
- 显示紧凑的“复杂条件（N 项）”只读摘要，提示可在上方条件条逐项移除。
- 新增手动条件时，把新 leaf 与整棵现有 expr 以 AND 合并，不破坏内部 OR 分组。

### 9.7 错误与结果保护

在 `superSearchStore` 分离：

```ts
error       // 数据查询错误
aiError     // AI 解析错误
```

AI 解析失败时：

- 保留当前 query、expr、items、total 和选择状态。
- 只设置 `aiError`，不触发 refresh。
- 不生成空标签行。
- 不把原始整句自动执行为全文搜索。
- AiSearchBar 可提供明确命令“按原文搜索”，只有用户点击后才生成 `{scope:"all", value:原文}`。

AI 结果通过后先运行本地 `validate_expr`；验证失败则视为解析错误，不应用部分条件。

### 9.8 QueryBuilder 空值与选项修复

当前 `rowsToExpr/isComplete` 已能过滤大部分不完整行，本轮将它作为回归防御保留。QueryBuilder 本地 row 可以处于编辑未完成状态，但只有完整条件才能提交到 store：

- tag/excludeTag 的 tagIds 为空：不进入 expr，行内显示待选择状态。
- search value 为空：不进入 expr。
- metadata 缺 value/min/max：不进入 expr。
- 用户完成输入或 blur 后再提交有效 expr。

对于已有非空 tagId：

1. 优先从 tagStore options 找名称。
2. 找不到时从 `resolvedTags` 注入 synthetic option。
3. 两边都找不到时显示 `标签 #123`，绝不能退回“选择标签”。

## 12. 代码开发规范

### 12.1 React / TypeScript

- 页面禁止直接调用 Tauri `invoke`，统一走 `src/api/*`。
- Fullscreen API、播放器 controls 和 Viewer shell 只能有一个 immersive 事实源。
- 异步模型发现必须有请求代际或取消保护，旧地址请求不能覆盖新地址结果。
- timer、event listener、fullscreenchange、pointer listener 必须清理。
- 不使用 `any` 绕过 SearchIntent/QueryExpr 协议。
- 超级搜索的条件展示、删除和执行必须共享同一棵 expr；query 只承载排序和明确的兼容字段，禁止把复杂 expr 静默扁平化。
- 表达式节点编辑使用结构路径与纯函数 normalize，禁止通过 `setQuery` 清空 expr 后重建。
- 组件 props 使用行为命名：`immersive`、`onToggleImmersive`，不要继续沿用含糊 `fs`。
- QueryBuilder 编辑 draft 与已执行 expr 分离，不把空表单值发给后端。
- 图标按钮必须有 `aria-label` 和 `title`。
- 使用 lucide 图标，不手绘 SVG。
- 不新增无必要 npm 包。

### 12.2 Rust / SQLite

- 数据库迁移幂等且可中断重入。
- `SearchScope` 由枚举映射到固定 FTS 列名/LIKE SQL，模型文本不能影响列名。
- FTS delete trigger 必须写全旧列，防止幽灵 token。
- AI 网络请求不持 DB 锁。
- keyring 读取在 Rust 完成，保存的 API Key 不回传前端。
- 日志和错误信息不得包含完整 key、Authorization 或带 query 的敏感 URL。
- SearchIntent 必须经过结构校验、本地语义守卫和 QueryExpr 校验三层。
- 所有值参数化；不得把模型输出拼进 SQL。
- 单个描述为空不能使标签批次失败。
- 确认标签和描述在同一事务中完成。

### 12.3 CSS / UI

- 播放器浮层固定 8px 圆角，不做大圆角胶囊。
- 不使用白色页面卡片承载视频控制条。
- 不使用原生蓝色 range 视觉。
- 不使用渐变、发光、彩色装饰或大面积品牌蓝。
- 进度和音量控件必须有稳定尺寸，hover 不改变布局。
- 不把卡片套进卡片；模型下拉是菜单浮层，不是新的设置卡片。
- 文本不能撑破控件；模型 id 使用单行截断并提供 title。
- 动画仅用于 opacity/transform，遵守 reduced motion。
- 图片沉浸白底必须使用明确白色，不复用主题变量。

### 12.4 用户文案

- 使用“全屏浏览”“内容描述”“读取模型列表”“按原文搜索”。
- UI 不展示 SearchIntent、QueryExpr、FTS、facetKey、scope 等实现术语。
- AI warning 说明“哪些条件被采用/未采用”，不要只显示“AI JSON 错误”。

## 15. 真实应用验收清单

### 15.1 图片沉浸

- 深色主题下进入全屏，背景仍为纯白。
- 屏幕上只有当前图片和白色画布，无工具栏、文件名、标签、属性、色条、胶片条。
- 1x 图片能左键拖动。
- Alt+滚轮、双击缩放正常。
- 图片拖到边缘后仍保留可找回部分。
- Esc 退出回同一张图片，第二次 Esc 才关闭查看器。
- Fullscreen API 被拒时仍能覆盖整个应用窗口，不露 TitleBar/BottomBar。
- fallback 沉浸时连续按 Tab 不会聚焦或触发被遮住的 TitleBar/BottomBar 控件，退出后键盘焦点恢复正常。

### 15.2 视频

- 正常查看器中没有视频下方的白色控制条。
- 控制条悬浮在视频底部，颜色为中性黑/白，无蓝色原生滑条。
- 播放后自动隐藏，移动鼠标立即显示。
- 暂停时常显。
- 进度拖动、±5 秒、倍速、静音、音量、全屏全部有效。
- 视频全屏与工具栏全屏进入同一沉浸模式。
- 窄窗口控件不横向滚动、不重叠。

### 15.3 超级搜索 UI

- 展开/收起按钮位于中间，只显示上下 Chevron。
- chips 行右侧不再有旧文字按钮。
- 展开区域仍只占中间内容宽度。
- 滚动收起和顶部恢复行为不回归。

### 15.4 在线模型

- 新建在线服务，填写地址和 key 后可读取模型。
- 编辑已保存服务，key 输入框留空仍能使用 keyring 读取模型。
- 可从列表选择，也可输入列表之外模型。
- 服务不支持模型列表时仍能手动保存。
- 连接测试与模型列表使用一致的 URL/协议。
- OpenAI 兼容地址缺 `/v1` 导致 404 时给出可理解的补全提示，但不擅自改写地址。
- 设置连接页与 AI 打标页都能选择/手填模型，删除 legacy 命令后无功能回退。

### 15.5 描述与搜索

- AI 打标建议中出现独立“一句话描述”，长度不超过 20 字。
- 大图浏览展开标签栏后，第一行能看到“一句话描述 | 具体内容”，后面的真实标签仍按双栏显示。
- 该描述是只读文本，不是可删除的标签 chip，且不计入标题栏的标签项数。
- 素材库左侧智能标签树、分类计数和标签管理中均不出现一句话描述。
- 修改描述并确认后，大图浏览的标签区域能看到新值，查看器属性侧栏不重复显示。
- 用描述中的部分中文关键词可搜到素材。
- 普通素材库搜索框输入描述中的两字词也能命中，文件名和旧标签搜索结果不回归。
- 旧素材没有描述时不报错；重新 AI 打标并确认后可获得描述。

### 15.6 截图问题回归

### 15.7 超级搜索结构化语义

- 输入“晚上拍的树或者白天拍的建筑”，条件 UI 清楚显示两个“任一组”，每组内部为“同时满足”；结果不能退化成命中任意一个词。
- 输入“有树还有花”，必须同时具备树和花，不能因为同属主体分面就变成二选一。
- 删除任意一个 chip 后，仅该条件消失，其他 OR 组、排除项和排序保持不变。
- 输入库中没有规范标签的具体物体时显示“内容：…”条件；零结果可一键只移除该内容条件。
- AI 解析失败时旧结果和旧条件仍在，错误显示在 AI 输入区，不覆盖普通查询错误。

## 16. 禁止实现

以下做法视为不合格：

- 仅把应用窗口最大化，却仍保留 ViewerToolbar。
- 用 CSS opacity 隐藏标签/属性，但仍让它们占布局。
- 图片沉浸背景继续用黑色或主题变量。
- 让 VideoPlayer 和 ViewerPage 各维护一套 fullscreen。
- 视频控制条继续放在视频下方。
- 只把白底改黑，却保留原生蓝色 range 和 select。
- 使用渐变、发光、彩色大按钮模仿“高级感”。
- 把展开按钮改成居中的文字胶囊。
- 为模型选择只做不可输入 select。
- 为读取已保存连接模型而把 keyring 密钥回显给 React。
- 模型列表失败时清空用户当前 model。
- 把一句话描述实现成 description 标签分面或 custom 标签。
- 因为一句话描述显示在 ViewerTagBar，就把它塞进 `tags` 数组、`TagChip`、`TagTree` 或左侧 facet 统计。
- 为显示描述把 `ViewerTagBar` 总高撑大、破坏标签双栏，或把素材缩略图误改成两栏。
- 未确认 AI 建议就直接覆盖素材描述。
- FTS 重建时退回旧标签聚合逻辑，导致别名或 inactive 标签语义丢失。
- 把自然语言整句无条件塞入 query.search。
- 同时保留 tags 与 concepts 两套 AI 语义输出。
- 继续使用一个全局 relation 表达所有 OR，生成 `OR(A,B,C,D)` 而不是 `(A AND B) OR (C AND D)`。
- 前端根据 intent/groups 再重建 expr，或让 FilterChips 读取扁平 query 而不是真实 expr。
- 删除一个 chip 时调用 `setQuery` 导致整棵 expr 丢失。
- 把同一分面的多个概念重新合并为 `mode:any`，将“树和花”错误执行成“树或花”。
- 只给 FTS 路径加 description/scope，却遗漏两字中文必走的 LIKE 路径。
- 对模糊多候选直接选择最短标签名。
- 把空 tag row 写入已执行 expr。
- AI 解析失败后清空当前搜索结果。
- 自动调用付费 AI 给整个旧库生成描述。
- 覆盖或回退当前工作区第四轮修复。
