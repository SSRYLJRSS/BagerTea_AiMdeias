## 2. 需求一：AI 打标进度合并

### 2.1 目标行为

启动 AI 打标后，用户在左侧「当前模型」下方的「当前批次」区块内只看到一条页内任务反馈。该反馈就是现有 `src/pages/AiTaggingPage.tsx` 约第 484 行的 `ProgressBar`，原则上保留原位置，不要搬到别处：

- 确定性进度条：`processed / total`，范围钳制到 `0..1`。
- 进度条下方一行 LED 式滚动提示，始终说明任务仍在运行，例如：
  - `正在连接 AI 服务，请稍候 · 不会卡住`
  - `正在分析第 3 / 120 张素材 · 请勿关闭窗口`
  - `正在保存标签建议 · 已完成 3 / 120`
  - 取消阶段：`取消已受理，当前图片完成后停止`
- 在真正收到第一条后端进度事件前，也要立即显示「准备开始…」或不确定条，避免点击开始后空白等待。
- 任务完成、取消、失败时显示静态最终状态，不继续滚动。
- 底部居中悬浮的「AI 打标中」胶囊不是本页进度条，而是 `taskStore` 的 AI 任务条；本轮必须删除或过滤这一项，避免它与侧栏进度重复。
- 入库和导出任务仍保留在底部全局任务条中，不得因移除 AI 项而受影响。

### 2.2 必须删除/保留的位置

- 保留 `src/pages/AiTaggingPage.tsx` 当前批次卡片内 `running && <ProgressBar value={...} />` 这一整块及其计数说明；它是用户要求保留的第一条进度条。
- 删除底部居中悬浮的 AI 任务条，二选一：
  - 推荐：从 `src/stores/taskStore.ts` 的 `startGlobalTaskWatch()` 移除 `onAiProgress(...)` 订阅及 `upsertGeneric("ai", "AI 打标中", ...)` 路径；
  - 折中：保留 store 中 AI 任务数据，但在 `src/components/layout/BottomBar.tsx` 依据 `current` 过滤 `kind === "ai"`，仅当当前页面不是 `ai` 时显示。打标页内必须隐藏，跨页查看需求由产品决定。
- 不删除 `src/stores/taskStore.ts` 或 `BottomBar.tsx` 的入库/导出任务能力。不要把侧栏进度搬到新的位置来“修复”重复问题，除非确有布局需要。
- `taskStore` 是进度事件订阅方，`BottomBar` 只是渲染方；指导书和实现注释必须保持这一区分，不能写成 BottomBar 订阅 AI 事件。

### 2.3 状态与事件契约

建议在 `src/types/ai.ts` 增加页面展示类型（或在组件内定义并导出）：

```ts
type AiTaggingUiState =
  | { phase: "idle" }
  | { phase: "starting"; processed: 0; total: number }
  | { phase: "running"; processed: number; total: number; currentAssetId?: number }
  | { phase: "cancelling"; processed: number; total: number }
  | { phase: "done"; processed: number; total: number }
  | { phase: "error"; message: string; processed: number; total: number };
```

实现要求：

- `startBatch()` 触发后先进入 `starting`，不要等后端事件才设置 `running` 的视觉反馈。
- `onAiProgress` 仍由现有 `useTauriEvent` 更新 `aiStore.patchProgress`；页面从 store 派生数据，不新增第二个事件监听。
- `processed` 大于 `total` 时按 `total` 处理；`total <= 0` 时使用不确定进度条，不能显示 `NaN%`。
- 进度条使用现有 `ProgressBar`；若要支持不确定状态，扩展 `ProgressBar` 的可选 `indeterminate` 属性并补测试，不复制一套 DOM。
- 当前素材名可从 `suggestions` 按 `currentAssetId` 查找；找不到时只显示计数和阶段文案。
- 文案滚动使用 CSS `@keyframes` + `transform: translateX`，容器 `overflow: hidden`，必须提供 `aria-live="polite"` 的完整静态文案；动画只影响视觉副本，不把字符拆成不可读的无障碍文本。
- 页面卸载或任务结束时清理动画计时器/监听；禁止残留 `requestAnimationFrame` 或 `setInterval`。

### 2.4 文案与视觉约束

- LED 提示不是第二条进度条：不得再出现第二个 `role="progressbar"`。
- 滚动提示高度固定（建议 `20px`），单行省略，不能推动侧栏其他内容跳动。
- 使用现有 `--color-status`/`--color-accent`，不引入霓虹渐变、发光大面积背景或高饱和装饰。
- 动画时长建议 8~12 秒，`prefers-reduced-motion: reduce` 下停止移动但保留完整文案。
- 失败文案用文字和状态色表达，不使用纯红整块背景。

### 2.5 验收测试

新增/修改 `src/pages/AiTaggingPage.test.tsx`、必要时新增 `src/components/ai/AiTaggingProgress.test.tsx`：

1. 点击开始后立即出现唯一一个 `role="progressbar"` 或唯一一个进度组件，不等待后端事件。
2. 运行中页面内只有 `AiTaggingPage` 当前批次区块这一条进度条；底部居中不出现「AI 打标中」胶囊。
3. 收到进度事件后百分比正确，当前素材名/计数文案更新。
4. 取消中显示取消文案，完成后滚动动画停止。
5. `prefers-reduced-motion` 或组件卸载时无计时器/监听泄漏。
6. 入库/导出全局任务条测试继续通过；若采用折中方案，非 `ai` 页面仍能看到 AI 任务，`ai` 页面不可见。

## 3. 需求二：入库缩略图视图 Alt + 滚轮缩放

### 3.1 目标行为

仅在 `PendingList` 的「缩略图视图」中，鼠标位于网格区域时：

- `Alt + 滚轮向上`：缩小卡片数量、增大素材卡片尺寸。
- `Alt + 滚轮向下`：增大卡片数量、减小素材卡片尺寸。
- 同时兼容 `Ctrl/Cmd + 滚轮`，与素材库现有操作习惯一致；普通滚轮仍只滚动列表。
- 缩放是网格卡片档位变化，不是修改原始图片，也不是改变 hover 视频播放速度。
- 使用 `CELL_STEPS` 与 `appearance.grid.importCellStep`，不增加新的尺寸体系。
- 切换档位时保持视口中心附近的素材，避免跳到顶部；边界档位不再继续阻止页面滚动以外的默认行为。

### 3.2 推荐实现位置

- 修改 `src/components/import/PendingList.tsx`，在 `view === "grid"` 的滚动容器上挂载原生 `wheel` listener，`passive: false`。
- 复用 `src/types/settings.ts` 的 `CELL_STEPS`、`useAppearance()` 和 `useSettingsStore.getState().commitAppearanceDebounced`。
- 可抽取 `src/utils/gridZoom.ts`，但只有当与 `AssetGridView` 的 `stepCell` 逻辑存在真实重复时才抽取；优先小范围复用现有模式。
- 在 `PendingList` 内给网格滚动容器加稳定 `ref` 和 `data-testid="pending-grid-scroll"`，不要依赖 `event.target` 的层级。

### 3.3 交互与安全约束

- 只处理 `view === "grid"` 且 `altKey || ctrlKey || metaKey` 的事件；输入框获得焦点时不拦截。
- `preventDefault()` 只对实际会改变档位的事件调用；达到最小/最大档位时允许普通滚动继续。
- 使用 `performance.now()` + `requestAnimationFrame` 做 60ms 最小步进节流，防止触摸板惯性一次跳多档。
- 计算锚点时读取滚动容器 `scrollTop/clientHeight`，切档后用 `requestAnimationFrame` 恢复中心行，不读取 `offsetX/offsetY`。
- 视图切回列表或组件卸载时移除 listener、取消 RAF。
- 入库 `running` 时禁用缩放 listener，不能在正式入库中改变布局。

### 3.4 测试与验收

修改 `src/components/import/PendingList.test.tsx`：

1. 网格视图 Alt/Ctrl/Cmd + wheel 改变 `importCellStep`，普通 wheel 不改档位。
2. 列表视图 wheel 不触发网格缩放逻辑。
3. 触摸板连续事件最多按节流频率改变一档；达到边界时不越界。
4. `running=true` 时 listener 不改变档位，且视频 hover 预览逻辑不回归。
5. 视口中心素材保持在可见区域，至少验证 `scrollTop` 没有被重置为 0。

不允许出现媒体框底部圆角与色条顶部之间的白色缝隙；不改变虚拟滚动的总高度。

## 5. 需求四：素材库侧栏与智能标签展开控制

### 5.1 视觉顺序与“四个字”的准确含义

本轮“你怎么把这四个字放右边”按上下文明确指 `src/components/library/MetadataPanel.tsx` 顶部右对齐的「全部收起」按钮，不是指 segmented control 中的「文件属性」标签。`SideBar` 的「智能标签 / 文件属性」二段切换仍保持两个选项各自居中，不要错误调整为“文件属性必须在左侧”。

两个面板统一采用同一套标题行结构：

- 标题/面板名放左侧：智能标签面板显示「智能标签」，文件属性面板显示「文件属性」。
- 展开控制放右侧：显示「全部展开」或「全部收起」，根据当前状态动态切换。
- 操作按钮不再使用 `justify-end` 将文字孤零零贴在右侧；按钮仍在标题行右侧，但左侧必须有对应标题。
- 不让两个面板共享 collapsed state；智能标签由 `tagStore.expanded` 管理，文件属性继续由 `MetadataPanel` 自己管理。

### 5.2 智能标签全部展开/全部收起

- 修改 `src/components/library/TagTree.tsx`，从 `useTagStore` 取得 `expanded`、`toggleExpand`，并新增 `setExpanded` 或 `expandAll/collapseAll` action。
- 推荐在 `tagStore` 增加：

```ts
expandAll: () => void;
collapseAll: () => void;
```

  由 store 根据当前 `tree` 收集所有拥有子节点的节点 ID；不要在组件内只展开当前一层。
- `TagTree` 顶部增加统一标题行：左侧「智能标签」，右侧按钮根据状态显示「全部展开」或「全部收起」。
- `allExpanded` 的判断必须覆盖所有可展开节点；空树时按钮隐藏或禁用。
- 点击后只改变展开状态，不改变选中筛选、不刷新后端、不重置滚动位置。
- 保留单个节点的箭头展开/收起；全局按钮与单节点操作应立即保持一致。
- `MetadataPanel` 增加左侧「文件属性」标题，并将现有「全部收起/全部展开」按钮放在同一标题行右侧；不要把智能标签和文件属性共用一套 collapsed state。

### 5.3 测试与验收

修改/新增 `src/components/library/TagTree.test.tsx`、`SideBar.test.tsx`：

1. 智能标签有可展开节点时显示「全部展开」。
2. 点击后所有有子节点的节点均出现在 `flattenVisible` 结果中，按钮变为「全部收起」。
3. 再次点击恢复收起状态。
4. 单节点折叠后全局状态文案正确。
5. 点击文件属性后，标题行左侧显示「文件属性」，右侧显示「全部展开/全部收起」；不得出现无标题的右对齐孤立按钮。
6. metadata 面板原有全部收起/展开测试继续通过。

## 6. 需求五：超级搜索页面布局收敛

### 6.1 目标布局

超级搜索页不再显示顶栏中的「返回」按钮和「超级搜索」标题。素材库与超级搜索的返回逻辑统一为：

- 双击底部「素材库」按钮：进入超级搜索。
- 单击底部「素材库」按钮：回到普通素材库。
- 超级搜索页面不再另造返回按钮，不再在顶栏重复显示页面名。

搜索区改为：

```text
                超级搜索
       [ 搜索文件名、标签或描述素材                 搜索 ]
```

「超级搜索」位于搜索框上方，作为品牌/页面标识；不要把它塞进输入框 placeholder，也不要做成大面积 hero 卡片。

### 6.2 实现文件与约束

- 修改 `src/pages/SuperSearchPage.tsx`：删除当前固定顶栏中返回按钮、`h1` 标题及其布局占位；保留结果总数，但放到搜索区域摘要行或工具区。

### 7.2 元数据读取核查与补齐

按以下链路逐层核查，不能只在前端把「未提供」改成假值：

1. `src-tauri/src/services/importer.rs`：入库探测是否将图片尺寸、EXIF、视频 ffprobe 结果写入资产。
2. `src-tauri/src/services/media_refill.rs`：重读媒体属性时是否对单个文件失败隔离，并写入 `metadata_error`。
3. `src-tauri/src/services/exif_meta.rs`：确认 DateTimeOriginal/Model/LensModel/FNumber/ExposureTime/FocalLength/ISO 的读取与 RAW/HEIF 兜底。
4. `src-tauri/src/services/video.rs`：确认 ffprobe 输出映射到 width/height/duration、codec、profile、frame rate、bit rate、color range/space/transfer/primaries、audio 字段。
5. `src-tauri/src/db/assets.rs` 与 migrations：确认列读写、camelCase 返回和旧数据迁移无误。
6. `src/api/assets.ts`、`src/types/asset.ts`：确认字段命名与可空语义一致。
7. `AssetInfoPanel`：`notProvided/notScanned/scanFailed` 必须真实反映探测状态；禁止把缺失数据渲染成「读取成功」。

若视频参数读不出来，优先补 Rust 映射/ffprobe 解析和测试；不要在 React 中从文件名或 MIME 猜测参数。需要检查：

- ffprobe 可执行文件在开发、打包环境中的路径。
- `avg_frame_rate`/`r_frame_rate` 分数转浮点是否除数为零。
- `bit_rate` 单位为 bit/s，UI 格式化不能误标为 MB；建议显示 `Mbps` 或 `kbps`。
- `color_space` 等字段缺失时显示「未提供」，探测失败时显示「读取失败」。
- EXIF 时间时区和非法日期不应阻塞整批导入。

### 7.3 图片悬浮旋转按钮

- 修改 `src/components/viewer/MediaViewport.tsx` 或 `ViewerShell`，仅图片模式显示；视频不显示该按钮。
- 新增 `onRotate?: (direction: "cw" | "ccw") => void` 或使用本地 `rotation` state。若旋转只影响查看器视觉，不写回原文件和数据库，必须明确命名为 viewer rotation。
- 推荐默认显示一个顺时针旋转图标按钮；如产品需要双向，使用两个紧凑 icon button，避免文字按钮占用照片区域。
- 按钮采用绝对定位的半透明深色背景（建议 `bg-black/45`）、`backdrop-blur` 不超过现有设计系统，不能遮挡照片主体；提供 `aria-label="顺时针旋转"`、tooltip。
- 鼠标进入媒体舞台、指针移动、键盘聚焦、点击按钮时显示并重置隐藏计时器；2 秒无操作自动隐藏。
- 使用 `setTimeout` 单一计时器，切图、卸载、进入 fatal 状态时清理；不要使用 interval。
- `prefers-reduced-motion` 下仍可显示/隐藏，但旋转过渡时间降为 0 或极短。
- 旋转不应破坏现有双击缩放、Alt+滚轮锚点、拖拽和代际保护。旋转时重置或重新计算 offset，避免图片被拖出舞台；推荐旋转后回到当前缩放比例的居中状态。
- 图片的 EXIF 方向只用于探测/诊断，不与查看器临时旋转状态混用；不要修改源文件。
