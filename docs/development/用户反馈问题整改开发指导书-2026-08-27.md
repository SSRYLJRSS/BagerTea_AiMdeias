### 0.2 本轮产品决策

用户最新明确要求：**素材库不允许大图预览，也不允许视频悬浮预览**。这是对 2026-08-26 旧指导书中“阶段 F 悬浮预览方案”的需求变更。执行 AI 必须在提交说明中标记：

```text
旧设计：素材库允许图片 popover 和视频 hover overlay。
当前需求：素材库禁止所有大图/视频 hover 预览，双击后进入 Viewer。
差异原因：用户在 2026-08-27 明确提出需求变更。
处理：删除素材库预览入口，Viewer 成为唯一大图/视频预览场景。
```

### 0.3 本轮最重要的顺序修正

独立评判指出，上一份排查报告把“生产资源 `/assets/...` 路径”排成了未经运行时验证的 P0 首因，这是不严谨的。本指导书改为：

1. **5 分钟排除项**：打包后检查资源是否 404、WebView2 控制台是否报错。
2. **白屏真正优先级**：先测 WebView2 首帧、窗口背景、Tauri setup 同步耗时。
3. **只有确认资源错误后，才修改 Vite `base` 或 Tauri 资源配置**；不能为了“看起来保险”直接改生产路径。

同样，删除 hover 预览不是滚动抽搐的充分条件。必须同时验证缩略图本地状态、虚拟列表重挂载、后端生成并发、缓存写入原子性。

### 1.2 评判确认已经修复的旧问题（VERIFY，不要重复制造）

根据外部评判与当前代码核对，以下旧问题已经有修复痕迹，执行 AI 只需补回归测试和运行时验证：

1. 首屏启动关键路径仍然混合了数据库/缓存维护、设置加载、素材刷新和任务监听。

## 2. 目标用户体验与信息架构

### 2.1 全局页面结构

```text
应用窗口
 ├─ TitleBar（始终可见）
 ├─ 主内容区
 │   ├─ LibraryPage（素材库模式）
 │   │   ├─ GridToolbar
 │   │   ├─ SideBar
 │   │   └─ AssetGrid
 │   ├─ ViewerPage（查看器模式，替换 LibraryPage 内容）
 │   │   ├─ ViewerToolbar
 │   │   ├─ ViewerInfoSidebar
 │   │   ├─ MediaViewport
 │   │   └─ ViewerFilmstrip
 │   ├─ ImportPage
 │   ├─ AiTaggingPage
 │   ├─ SuperSearchPage
 │   └─ SettingsPage
 └─ BottomBar（Viewer 模式默认隐藏）
```

Viewer 和 Library 是互斥页面，不允许在同一布局中同时显示。TitleBar 保留，ViewerFilmstrip 取代库页底部导航；关闭 Viewer 后恢复库页上下文。

### 2.2 素材库模式

素材库卡片只承担：

- 占位图/缩略图显示。
- 图片/视频/格式角标。
- 选择、范围选择、右键菜单。
- 文件名轻量 overlay。
- 双击进入 Viewer。

素材库卡片绝对禁止：

- 创建 `<video>`。
- 生成或请求 1024px hover 图。
- `position: fixed` 大图浮层。
- hover 时改变卡片尺寸、行高度或网格定位。
- 通过 hover 播放原视频或代理视频。

### 2.3 Viewer 模式

Viewer 是唯一允许大图/视频预览的区域：

- 图片：高清图、原图兜底、缩放、平移。
- 视频：原文件优先，失败后按需生成兼容代理。
- 左栏：当前素材属性和标签，不出现素材库筛选。
- 底部：当前素材附近的胶片条，不出现全局素材库导航。

### 2.4 设置页目标 IA

```text
设置
 ├─ 入库与总库
 ├─ AI 设置
 │   ├─ 超级搜索
 │   ├─ 自动打标
 │   └─ 服务管理
 ├─ 标签与分类
 ├─ 通用外观
 ├─ 数据与缓存
 └─ 关于
```

“服务管理”是唯一维护服务实体的地方；超级搜索/自动打标页面只选择服务和功能参数。

“标签与分类”是唯一维护分面、AI 行为和分类词条的地方；不再把同一个 facet key 分别放在“封面结构管理”“AI 行为配置”“标签管理”三套顶层入口中。

## 3. UI 设计规范

### 3.1 视觉原则

- 延续现有黑白灰、暖中性色、克制琥珀状态色。
- 所有颜色使用 `var(--color-*)`，禁止新增硬编码颜色；关闭按钮 hover 的系统红色除外。
- 主 CTA 使用近黑实心按钮；次要动作使用幽灵/描边按钮；危险动作使用文字或低饱和危险色。
- 卡片圆角、边框、阴影使用现有 `--radius-*`、`--color-border`、`--shadow-soft`。
- 不使用 emoji 代替功能图标；继续使用 Lucide React。
- 动效短、轻、可取消：160–220ms；禁止使用大范围 scale/position 动效造成内容跳动。
- 支持深色模式；不能把浅色背景写死在组件中。

### 3.2 启动过渡 UI

首屏过渡不是“假装加载”的动画，而是明确状态：

```text
┌──────────────────────────────┐
│  [logo]  茶包素材             │
│                              │
│       正在准备素材库         │
│       ━━━━━━━━━  不定进度     │
│                              │
│       首次启动可能需要一点时间 │
└──────────────────────────────┘
```

要求：

- 背景颜色与 `--color-bg` 一致，不显示纯白闪屏。
- 文案不承诺百分比，除非有真实进度。
- 先显示 TitleBar/骨架，再渐进替换为素材列表。
- 如果采用隐藏窗口，ready 信号必须有超时兜底，最长等待不能无限制。
- 过渡组件不得触发数据库、缩略图或网络请求。

### 3.3 素材库卡片

- 卡片尺寸由网格统一计算，内部内容全部 `absolute inset-0`，不改变外层高度。
- 缩略图使用 `object-cover`；Viewer 使用 `object-contain`。
- 角标位置固定：格式右上，视频时长右下，选中勾选左上。
- hover 只允许边框/文件名透明度变化，不允许创建媒体层。
- 文件名最多一行，使用 `truncate`；不得因为文件名换行改变行高。

### 3.4 Viewer

```text
┌ TitleBar ─────────────────────────────────────────────┐
├ ViewerToolbar ─────────────────────────────────────────┤
│ 当前素材信息 │             媒体舞台                   │
│              │     image/video object-contain          │
│              │                                         │
├──────────────┴────────────────────────────────────────┤
│                 ViewerFilmstrip                       │
└───────────────────────────────────────────────────────┘
```

- Viewer 左栏建议 260–300px，`shrink-0`，内容自身滚动。
- 媒体舞台 `min-w-0 min-h-0 flex-1 overflow-hidden`。
- 图片/视频不能被左栏文本挤压变形。
- Viewer 不使用覆盖 TitleBar 的 `fixed inset-0`。
- Viewer 关闭、Esc、胶片条切换必须有可见反馈。

### 3.5 设置页表单

统一使用“标题 + 说明 + 控件”三段结构：

```text
服务地址                         [https://...        ]
在线服务的 API 地址。普通情况下填写服务商提供的地址。
```

规则：

- 说明文字不能使用负 margin；禁止 `-mt-*` 把文字拉到边框线上。
- 宽屏使用左右两列，窄屏自动变为上下两行。
- 控件拥有明确 label，不能只靠 placeholder 表达含义。
- 普通用户看到“服务名称、服务地址、模型、API 密钥、测试连接”。
- 协议、完整 URL、模型映射、超时和重试放在“高级设置”折叠区。
- 所有异步操作都有加载、成功、失败和重试状态。
- 危险操作说明影响范围，不使用“清除绑定”等内部实现表达。

### 3.6 文案规范

| 不建议作为主文案 | 统一替换 |
|---|---|
| 连接档案 | AI 服务 / 服务配置 |
| 用途绑定 | 此功能使用的服务 |
| 部署方式 | 服务位置：在线服务 / 本机服务 |
| 使用云端 API 识别素材 | 通过在线服务分析素材；素材会按所选服务发送 |
| API 密钥保存到系统凭据 | API 密钥会安全保存在系统凭据中，界面不会显示完整密钥 |
| 接口协议 | API 格式（高级） |
| 分面 | 分类大类（高级信息中可显示“分面”） |
| hint | 给 AI 的分类说明 |
| visible in workbench | 在打标工作台显示 |

技术术语可以在“高级信息”中显示，但不能成为用户完成任务的前置理解成本。

## 5. 阶段 1：启动白屏和首屏性能（P0）

### 5.1 问题模型

必须区分：

```text
A. WebView2/Tauri 创建阶段白闪
B. Rust setup 同步工作导致窗口迟迟不可用
C. React 首屏多个 IPC 同时开始，页面骨架迟迟不稳定
D. 生产资源加载失败
```

四种问题的修法不同，不能全部归结为“加 loading”。

### 5.2 Rust 侧施工要求

#### 保留在关键路径的内容

- 创建数据目录。
- 打开数据库。
- 必要迁移。
- 注册 Tauri 必须的状态和命令。

#### 移出关键路径的内容

- 缩略图 LRU 清理。
- 非关键旧标签整理。
- 历史任务状态修复。
- 可延迟的缓存统计和目录扫描。

这些任务应通过 Tauri 异步 runtime 或受控后台线程启动，且不能持有数据库锁执行磁盘扫描、ffmpeg、ffprobe 或图片解码。

后台任务必须满足：

- 有明确任务名和日志。
- 不影响窗口显示。
- 失败只记录 warning，不阻塞应用。
- 可取消或至少不会无限重试。

#### 窗口策略

先用主题背景和骨架解决视觉白屏；只有运行态证明 WebView2 首帧白闪仍不可接受时，才启用：

```text
tauri.conf.json: visible = false
前端 React 首帧 + 关键资源 ready
调用 getCurrentWindow().show()
```

隐藏窗口必须同时处理：

- `core:window:allow-show` 权限。
- 最大化/窗口状态插件是否覆盖 visible 状态。
- show 失败时的日志和超时兜底。
- 非 Tauri 测试环境的安全降级。

窗口背景色应与主题一致。不要增加独立 splash window，除非真实初始化确实超过骨架可接受时间；Tauri 官方也把 splash 视为产品选择，而不是默认性能修复。

### 5.3 前端启动协调

禁止 App、LibraryPage、ImportPage、SettingsPage 各自无条件触发同一份设置加载。`settingsStore.load()` 必须 single-flight：

```ts
let loadPromise: Promise<void> | null = null;

load: () => {
  if (get().loaded) return Promise.resolve();
  if (loadPromise) return loadPromise;
  loadPromise = doLoad().finally(() => {
    loadPromise = null;
  });
  return loadPromise;
}
```

库页、设置页只调用 store 的安全入口，不自己维护第二套 loading 状态。

首屏渲染顺序：


## 6. 阶段 2：删除素材库大图/视频预览并修复滚动闪烁（P0）

### 6.1 AssetCard 必须达到的最终形态

`AssetCard.tsx` 应只保留：

- `Thumbnail`。
- 角标。
- 选中状态。
- 文件名。
- 单击/双击/右键事件。

必须删除或断开：

- `useHoverIntent`。
- `MediaPreviewPopover`。
- `ImagePreviewContent`。
- `VideoHoverOverlay`。
- `getImageHoverPreview`。
- `convertFileSrc(asset.filePath)` 在卡片中的视频播放用途。

执行顺序：

1. 先删除 AssetCard 的调用入口。
2. 用 `rg` 确认这些组件没有其他业务消费者。
3. 再删除无消费者的文件和 API。
4. 更新测试，断言素材库渲染树中没有 `<video>` 和 fixed popover。

如果这些文件暂时被其他页面使用，不能直接删除，应先把素材库入口与其他页面入口分离，并在报告中列出保留原因。

### 6.2 前端缩略图视觉状态

当前已有模块级 `thumbnailCache`，但 `Thumbnail` 的 `hdUrl/hdReady` 仍是组件本地 state。虚拟滚动重挂载时可能出现：

- 已有 ready URL 重新经历一次 opacity 淡入。
- Promise 尚未完成时重挂载，视觉状态从 loading 重新开始。
- 快速滚动时占位图、旧高清图和新高清图交替出现。

不要用动态整行 key 强制 remount。推荐二选一：

#### 方案 A：缓存层提供稳定快照 + 订阅

把 `Thumbnail` 的显示状态从“初始化读取一次”升级为可订阅资源：

```ts
type ThumbnailResource = {
  status: "idle" | "loading" | "ready" | "failed";
  url: string | null;
  promise?: Promise<string>;
  error?: string;
};
```

缓存层在状态改变时通知订阅者；组件重挂载读取 ready 状态时直接显示，不重复淡入。

#### 方案 B：保留现有 Map，补充稳定显示策略

- ready URL 直接 `opacity: 1`。
- loading 只显示当前素材占位图。
- 只有第一次从 placeholder 切换到 ready 才淡入一次。
- 失败状态在退避窗口内不重复请求。

选择哪种方案由执行 AI 根据当前代码复杂度决定，但必须通过测试证明滚动时不会重复闪烁。

### 6.3 后端缩略图并发与原子写（必须核对，不得回退）

执行 AI 必须检查：

- 同一素材/尺寸是否 single-flight。
- 全局图像解码是否有并发上限。
- 正式文件是否 tmp 写完后 atomic rename。
- 失败是否清理临时文件。
- Windows 目标文件被 WebView/杀毒软件占用时是否有有限重试。
- DB 锁是否在解码期间释放。

如果当前实现已经满足，不得重写，只补并发测试。若发现某条链路仍有旧实现，按以下模板修复：

```text
生成临时路径：{asset}_{size}.{uuid}.tmp
写入并 flush
成功后 rename 到正式路径
失败删除 tmp
正式路径存在时直接复用
```

禁止：

- `File::create(formal_path)` 直接覆盖正式缓存。
- 每个请求无界 `spawn_blocking`。
- 为了“修闪烁”把整个网格全部 remount。

### 6.4 虚拟列表稳定性

- 业务 key 使用稳定 `asset.id`；行容器 key 不能依赖会随列数改变的临时值来重置所有卡片状态。
- columns 变化时只重新测量虚拟器，不销毁所有素材资源。
- `overscan` 先保持当前值，除非有 FPS/请求量数据支持调整。
- 筛选/排序切换时使用 request sequence/generation 丢弃旧响应。
- `items` 中的素材 id 不得重复。

### 6.5 验收

- 快速滚动 30 秒无旧图串入新卡片。
- 上下往返滚动无重复闪烁。
- 改变窗口宽度、列数和排序后，图片与文件名始终对应。
- 素材库 DOM 不存在 `<video>`、`role=dialog` 的大图 popover、`position: fixed` 预览层。
- 同一 asset+size 并发只产生一个后端生成任务。
- 缩略图生成失败不会无限重试，当前卡片保留正确占位图。

- `src/utils/thumbnailCache.ts`

## 7. 阶段 3：Viewer 页面级替换和布局修复（P0）

```tsx
if (preview) {

return <LibraryContent ... />;
```

```ts
type LibraryViewState = {
```

#### 方案 A：Viewer 仍由 LibraryPage 管理

- `App` 通过 `useLibraryStore` 或页面状态知道 Viewer 是否打开。
- Viewer 打开时 `BottomBar` 隐藏。

```ts
type PageKey = TabKey | "settings" | "superSearch" | "viewer";
```

- 地址格式错误。
- 网络不可达。

```text
旧 api_key
```

迁移规则：

## 10. 前端代码规范

### 10.1 React 组件

- Hook 只能在组件顶层调用；所有条件 return 必须放在全部 Hook 之后。
- 页面组件只做编排；业务异步逻辑放 store/api/service。
- `useEffect` 中启动异步任务必须有 cleanup、取消标记或 generation token。
- 不用 Error Boundary 掩盖可预防的状态设计错误。
- `memo` 只用于 props 稳定且有性能证据的组件。
- 组件互斥页面使用条件分支卸载，不用 z-index 覆盖。

### 10.2 状态和异步

- 资源状态优先使用联合类型，不用多个 boolean 拼非法状态。
- 跨卡片共享资源放缓存层；组件 state 只保存视图订阅结果。
- 所有列表请求带 request sequence；旧响应不得覆盖新筛选。
- 所有媒体请求带素材 id + generation；切素材后旧 Promise 不回写。
- loading、success、error、retry 均可见；失败不能静默变成空列表。

### 10.3 TypeScript

- 开启严格类型，不使用无意义的 `as any`。
- API 类型集中在 `src/types` 或对应 api 模块，不在 JSX 中复制结构。
- 单位写入字段名：`durationMs`、`bitRateBps`、`sampleRateHz`。
- `null` 表示“没有值/未绑定”，`undefined` 表示“未提供字段”，语义要统一。
- 媒体类型、分面 key、协议枚举使用 union 类型。

### 10.4 CSS/Tailwind

- 使用现有 CSS 变量。
- 说明文本禁止负 margin 压边框。
- flex 子项需要 `min-w-0` 时显式写出。
- 长文本使用 `truncate` 或 `break-words`，不允许溢出撑大布局。
- 动画只作用于 opacity/transform，不能改变文档流尺寸。
- fixed 元素必须有明确 owner、z-index 和卸载条件；素材库不允许 fixed 预览。

### 10.5 可访问性

- 所有图标按钮有 `aria-label` 和 title。
- Toggle 使用 `role="switch"` 与 `aria-checked`。
- 表单 label 与 input 绑定。
- 错误信息使用 `aria-live="polite"`，不要只用颜色表达。
- 键盘焦点顺序不能因为视觉重排而改变。

## 11. Rust 后端代码规范

### 11.1 分层

```text
commands：参数校验、权限边界、短锁、事件
services：业务流程、耗时任务、并发控制
db：SQL、事务、迁移
utils：纯函数和格式转换
```

commands 不得直接拼 SQL；services 不得把 UI 文案散落在数据库层。

### 11.2 数据库锁与耗时任务

- DB 锁只覆盖查询和短事务。
- 锁外执行 ffmpeg、ffprobe、图像解码、文件扫描和网络请求。
- 后台任务使用有界并发；同素材同变体 single-flight。
- 所有外部子进程有 stdout/stderr、退出码、超时和 kill 后 wait。
- 不使用 shell 拼接用户路径或参数。

### 11.3 文件写入

- 缓存和代理统一 tmp → flush/sync → rename。
- 临时文件失败必须清理。
- Windows rename 失败只允许有限重试，并记录可解释原因。
- 不覆盖原始素材。

### 11.4 错误

- 不对外部输入使用 `unwrap()`。
- 错误保留 source 和上下文（asset id、task id、facet key），不得打印 API key。
- 失败状态进入数据库或事件流，不能只写 tracing 后让前端永远 loading。

## 12. 数据库和配置迁移规范

### 12.1 迁移总原则

- 先查当前 `PRAGMA user_version` 和表结构。
- 每个迁移幂等、可重复执行。
- 迁移只做结构和轻量数据转换，不做 ffprobe/ffmpeg/图片解码。
- 迁移失败不得升级版本，不得覆盖原配置。
- 迁移前备份数据库；迁移后执行 `PRAGMA foreign_key_check`。

### 12.2 媒体元数据迁移（条件新增）

只有在当前 schema 缺字段且真实搜索需要时，才增加 V12 等迁移。候选字段：

```text
media_kind
container_format
video_profile
pixel_format
bit_depth
frame_rate_num / frame_rate_den
video_bit_rate
color_range / color_space / color_transfer / color_primaries
audio_sample_rate / audio_channels
rotation
media_metadata_json
metadata_version
metadata_scanned_at
metadata_error
```

不要为了“未来可能用到”一次性给所有字段建索引。

### 12.3 媒体回填任务

元数据回填必须是可取消、可恢复、可观察的后台任务：

```text
queued → running → done
             ├→ cancelled
             └→ failed
```

每个素材记录 success/failed/skipped 和 last_error。启动时不能同步扫描全部素材。

### 12.4 AI 服务迁移

旧 `settings.ai.profiles`、`active_profile`、旧明文 API key、`aiFacetConfigs` 的映射必须在迁移文档中逐字段列出。迁移期间：

- 旧配置只读兼容。
- 新配置只写新事实源。
- 不允许新旧双写导致两个来源逐渐分叉。
- keyring 失败保留旧 key。
- 迁移完成后普通设置 JSON 不再保存新明文 key。

### 12.5 分面配置迁移

`aiFacetConfigs` 只保留 AI 覆盖：

```ts
type AiFacetConfig = {
  facetKey: string;
  enabledForAi: boolean;
  hint: string;
  displayName?: string;
  visibleInWorkbench?: boolean;
};
```

`selectionMode/maxItems/description/appliesTo` 只来自 `tag_facets`，不得在 AI 配置中再存一份。

## 13. 测试规范与矩阵

### 13.1 必须新增/补齐的测试

#### 启动

- `settingsStore.load()` single-flight：并发调用只产生一个 API 请求。
- 加载失败可重试，且不会写入默认设置覆盖真实配置。
- 启动骨架在非 Tauri 环境不抛异常。

#### 素材库

- AssetCard 不渲染 hover preview。
- AssetCard 不渲染 `<video>`。
- 双击仍调用 `onPreview`。
- Thumbnail ready 缓存重挂载不重复淡入/请求。
- 旧 Promise 不更新新 asset。
- columns 改变后 asset id 与文件名仍对应。

#### 缩略图后端

- 同 asset+size 并发 single-flight。
- tmp 写入失败无正式文件残留。
- rename 成功后正式文件完整可读。
- LRU 清理不持有 DB 锁。

#### Viewer

- Viewer 打开时库页筛选/侧栏不在渲染树。
- BottomBar 按约定隐藏。
- Esc/关闭恢复库页状态。
- 图片缩放、拖拽和素材切换重置。
- 播放器左右键不冒泡成切片。

#### AI 设置

- 在线/本机切换只显示当前模式字段。
- 服务管理只出现一个入口。
- API key 不回显。
- 测试连接 loading/成功/失败可见。
- 旧 profile 迁移幂等。

#### 标签

- 分面 key 创建后不可改。
- 显示名修改不影响历史查询。
- AI 行为配置与分面结构在同一详情内。
- 停用前显示影响范围。
- 合并保留别名和历史关联。
- 未知 facet key 返回 warning，不静默变 custom。

### 13.2 真实媒体样本

至少覆盖：

- H.264 MP4。
- HEVC Main 10 4K60。
- ProRes MOV。
- VP9 WebM。
- AV1。
- 无音轨、多音轨。
- 可变帧率。
- 旋转视频。
- HDR10/HLG。
- 损坏文件。
- 中文路径、空格路径、特殊字符路径。

### 13.3 性能验收

记录以下数据，不允许只说“感觉不卡”：

| 指标 | 目标 |

## 15. 明确禁止的修复方式

1. 把未验证的 `/assets/...` 路径直接判定为白屏首因。
2. 只加 spinner，不测 Rust setup、WebView2 首帧和资源错误。

11. 同时保留“封面结构管理”“AI 行为配置”“标签管理”三套 facet 编辑入口。
12. 在数据库迁移事务里运行 ffprobe、ffmpeg 或全库扫描。
13. 物理删除有历史引用的标签/分面。
14. 为本轮问题顺手升级依赖、全仓库格式化或重排无关代码。
15. 用截图代替真实窗口、真实素材、真实迁移和性能数据。

## 17. 最终完成定义

执行 AI 只有在以下全部满足后，才能说“本轮整改完成”：

### 启动

- 生产包已实测，无资源 404/CSP 错误。
- 已区分 WebView2 白闪、Rust setup 阻塞、React 首屏并发和资源错误。
- 首帧有主题一致的骨架或 hidden window ready show。
- 缓存清理、历史任务整理不阻塞首帧。

### 素材库

- 素材库没有图片大图 popover。
- 素材库没有视频 overlay 或隐藏 `<video>`。
- 快速滚动无串图、错位和重复淡入。
- 前端缓存、后端 single-flight、并发上限、原子写均有证据或测试。

### Viewer

- Viewer 与 Library 页面互斥。
- Viewer 打开后库页侧栏、工具栏和全局 BottomBar 按约定卸载/隐藏。
- TitleBar 保留且不被遮挡。
- 图片缩放/拖拽、视频播放/代理和键盘优先级通过测试。

### AI 设置

- 服务配置只有一个管理入口。
- 超级搜索/自动打标只选择服务和功能参数。
- 普通文案不再以“连接档案/用途绑定”为主操作。
- API key 安全迁移、不可回显，旧配置可回滚。

### 标签与分类

- 分面结构、AI 行为和分类词条在同一详情上下文内完成。
- `tag_facets` 是唯一结构事实源，`tags` 是词条事实源。
- 稳定 key/id 不随显示名修改。
- 停用/合并/迁移显示影响范围并保留历史关联。
- 设置、侧栏、工作台、AI、超级搜索、QueryBuilder 全链路一致。

### 工程质量

- 所有阶段有独立提交、验证命令和回滚方式。
- 前端类型检查、单测、构建和 Rust 检查通过。
- 真实窗口、真实大库、真实视频样本完成手工验收。
- 最终报告写明旧报告结论、当前代码事实、差异原因和剩余风险。
