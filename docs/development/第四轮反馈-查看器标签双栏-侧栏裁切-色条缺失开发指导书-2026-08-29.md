## 4. 已核实的根因摘要

### 4.1 FB4-01：需求被代码和测试一起写反

直接证据：

- `src/components/viewer/ViewerFilmstrip.tsx`
  - 文件注释明确写成“固定高度的两行缩略图带”；
  - 外层使用 `h-32`；
  - 缩略图区使用 `gridTemplateRows: repeat(2, ...)`；
  - `gridAutoFlow: column` 把素材按两行排列。
- `src/components/viewer/ViewerFilmstrip.test.tsx`
  - 测试名称和断言都把“双行缩略图”当成正确行为。
- `src/components/viewer/ViewerTagBar.tsx`
  - 标签分组仍是逐组全宽单行：`groups.map(...)` 下每组都是 `flex`；
  - 标签正文只有 `h-16 overflow-y-auto`，所以左侧堆叠、右侧空白、正常数量也容易出现纵向滚动。

结论：这不是某个 CSS 类写错，而是上一轮需求解释、实现和测试三处同时错误。修复时必须同时改组件注释、布局和测试，否则旧测试会把正确修改判成失败。

### 4.2 FB4-02：sticky 标题和滚动内容共用一个滚动层

当前结构位于 `src/components/library/SideBar.tsx`：

```tsx
<div className="min-h-0 flex-1 overflow-y-auto px-2 py-2">
  <div className="sticky top-0 ...">标签标题和类型切换</div>
  <TagTree />
</div>
```

具体问题：

1. 外层滚动容器有 `py-2`，sticky 标题不能覆盖滚动视口顶部的全部留白。
2. `TagTree` 会在 sticky 标题背后继续滚动，顶部约 8px 区域能看到“未打标”等文字碎片。
3. 同一个滚动容器还会出现横向滚动条；标签层级缩进、计数和可用宽度组合后容易产生横向溢出。

正确方案不是继续叠加 `z-index`，而是让标题和滚动正文成为兄弟节点：标题固定，只有标签列表滚动。

### 4.3 FB4-03：色条渲染链路被两个门控拦住，且旧库没有数据

#### 4.3.1 当前真实设置

已对用户当前数据库进行只读检查：

`C:\Users\33887\AppData\Roaming\bagertea_ai_media_v2\library.db`

结果：

| 设置 | 当前值 |
|---|---:|
| `colorStrip.enabled` | `true` |
| `colorStrip.showInLibraryGrid` | `false` |
| `colorStrip.showInViewer` | `true` |
| `colorStrip.height` | `normal` |
| `colorStrip.count` | `6` |

因此，素材库网格没有色条的第一层原因是：`AssetCard.tsx` 使用

```ts
const stripOn = colorStrip.enabled && colorStrip.showInLibraryGrid;
```

用户只打开总开关并不等于素材库位置已打开。当前设置页面的层级和文案没有让这个区别足够明显。

#### 4.3.2 当前真实色板数据

数据库统计结果：

| 素材总数 | 已有色板 | 缺失色板 |
|---:|---:|---:|
| 259 | 0 | 259 |

用户截图中的 `_1091719.RW2`、`_1091717.JPG`、`Timeline 1.mp4` 的 `palette_json` 都是 `NULL`。

因此，大图浏览虽然 `showInViewer=true`，仍被 `ViewerPage.tsx` 的以下判断拦住：

```ts
const viewerStripOn =
  colorStrip.enabled &&
  colorStrip.showInViewer &&
  !!current.palette?.length;
```

这解释了为什么查看器也完全没有色条。

#### 4.3.3 旧库缺少自动补算入口

现有后端只对**新入库**素材启动异步色板补算：

- `src-tauri/src/commands/import_cmd.rs:52-88`

用户的 259 个素材显然是在该功能落地前入库，应用启动时没有迁移或提示，所以它们会永久保持 `palette_json=NULL`，除非用户自己找到设置页最下方的“算法色板回算”。

#### 4.3.4 新入库还有刷新竞态

现有新入库流程也存在可见性问题：

1. `import_files` 启动后台色板任务后立即返回；
2. `ImportPage.tsx` 随即调用 `refreshLibrary()`；
3. 此时后台任务通常尚未写入 `palette_json`；
4. 后台完成后没有事件通知前端刷新素材对象。

结果是数据库可能已有色板，但当前前端 `libraryStore.items` 仍保留 `palette:null`，必须切页或重新启动才能看见。

## 5. 目标 UI 设计规范

### 5.1 大图浏览整体层级

非全屏查看器从上到下保持：

```text
工具栏
属性侧栏 | 媒体舞台
           主色色条（有数据且位置开关开启）
           标签区（两栏）
单行缩略图胶片条
```

全屏浏览继续只保留工具栏和媒体舞台，不显示属性栏、色条、标签区或胶片条。

### 5.2 标签区两栏规范

标签“两栏”指**分面分组两栏**，不是单个标签强制一左一右，也不是缩略图两行。

推荐结构：

```tsx
<div className="grid grid-cols-2 gap-x-6 gap-y-1">
  {groups.map((group) => (
    <div className="grid min-w-0 grid-cols-[76px_minmax(0,1fr)] gap-2">
      <span>{group.name}</span>
      <div className="flex min-w-0 flex-wrap gap-1">...</div>
    </div>
  ))}
</div>
```

硬性要求：

- 始终是两栏，最小窗口 960px 下仍保持两栏；
- 每个分面组必须整体留在一个栏位内，不能把同一分面的标题和标签拆到不同栏；
- 栏间距建议 20-24px；
- 分面标题列宽建议 72-80px；
- 标签 chip 允许在本栏内换行；
- 所有 grid/flex 子节点必须有 `min-w-0`；
- 超长标签使用换行或截断，不能撑出水平滚动条；
- 正常 13-20 个标签时不应出现纵向滚动；只有极端大量标签时才允许正文区域纵向滚动；
- 折叠状态仍保持 32px 高标题栏；
- “添加标签”和删除标签的业务行为保持不变。

建议展开高度：标题 32px + 正文 96px，总高约 128px。若实测 128px 仍经常滚动，可把正文上限提高到 112px，但不要使用无限 `height:auto` 挤压媒体舞台。

### 5.3 单行缩略图胶片条规范

- 恢复单行横向排列；
- 外层建议高度 `80px`；
- 缩略图固定 `56x56px`；
- 左右切换按钮保持固定，不随内容滚动；
- 中间缩略图区 `min-w-0 flex-1 overflow-x-auto overflow-y-hidden`；
- 素材超过宽度时只横向滚动；
- 当前素材继续使用强调色边框；
- 点击、上一张、下一张和键盘左右键行为不变；
- 不允许为了“填满宽度”拉伸缩略图。

推荐实现为单行 `flex`，无需保留两行 grid：

```tsx
<div className="flex min-w-0 flex-1 items-center gap-1 overflow-x-auto overflow-y-hidden">
  {items.map(...)}
</div>
```

### 5.4 素材库侧栏规范

目标结构：

```tsx
<section className="flex min-h-0 flex-1 flex-col">
  <div data-sidebar-tag-header className="shrink-0 ...">
    标签标题 + 智能标签/文件属性切换
  </div>
  <div
    data-sidebar-tag-scroll
    className="min-h-0 min-w-0 flex-1 overflow-y-auto overflow-x-hidden ..."
  >
    <TagTree /> 或 <MetadataPanel />
  </div>
</section>
```

硬性要求：

- 标题不能再放进滚动容器；
- 不使用 sticky 补丁；
- 滚动条从标签正文开始，不穿过标题；
- 滚动任意距离，标题上方不得露出“未打标”或其他标签文字；
- 侧栏不得出现水平滚动条；
- `TagTree` 的缩进、标签名和计数必须在 224px 侧栏内正确收缩；
- 激活态、右键菜单、父子折叠和筛选逻辑保持不变。

### 5.5 主色色条 UI 规范

设置页不要再只展示一个看似“打开就会显示”的总开关。建议调整为：

```text
主色色条                         [总开关]
使用本地算法分析素材主色，不调用 AI，不修改原文件

显示位置
[ ] 素材库卡片
[ ] 大图浏览

色条数据：0 / 259 已生成
[生成缺失色条]
```

行为要求：

1. 总开关只控制功能总状态；位置开关必须明确写出实际位置。
2. 当任一显示位置打开，但缺失色板数量大于 0 时，显示明显但克制的状态提示。
3. 点击“生成缺失色条”复用现有 `rescanAssetPalette([], "missing")`，不得复制一套计算逻辑。
4. 生成前说明：全程本地处理、不修改原文件、可取消。
5. 生成过程中显示 `done/total/success/skipped/failed`。
6. 生成完成后自动刷新色板状态和当前素材列表，用户不需要重启或切页。
7. 没有数据时不能生成假色条、默认灰条或品牌色条。
8. RAW/HEIC/损坏图片无法取得真实像素时允许跳过，但必须在结果中显示跳过数量。
9. 视频只有真实 HD 封面时才参与计算，禁止使用通用 UI 占位图计算主色。

色条位置：

- 素材库：紧贴缩略图下沿，使用既有恒定高度槽位；
- 查看器：媒体舞台与标签区之间；
- 有数据时显示，无数据时由设置页/状态提示解释，不在每个卡片上堆错误文案；
- 继续复用 `ColorStrip.tsx`、`HEIGHT_PX` 和 `toPaletteSegments()`。

## 7. 代码开发规范

### 7.1 单一事实源

- 标签分面顺序继续来自 `buildWorkbenchFacets`，不要在 Viewer 写第二份分面表。
- 色条高度继续只来自 `ColorStrip.HEIGHT_PX`。
- 色板计算继续只来自 Rust `services/palette.rs`。
- 色板候选条件继续复用 `PALETTE_CANDIDATE_PRED` 或抽成共享查询函数，不能在状态统计和回算命令里各写一份不同 SQL。
- 外观设置继续通过 `useAppearance()` 消费，不直接读 localStorage 或数据库。

### 7.2 React 规范

- 不在 render 中发起 IPC。
- 计算分组继续使用 `useMemo`，事件使用稳定回调。
- 异步请求必须防止组件卸载后写状态。
- 事件订阅必须在 cleanup 中解除。
- 不用索引作为标签分组 key；分面用 `facetKey`，素材用 `asset.id`。
- 不通过 DOM 查询修改样式，状态由 React 驱动。

### 7.3 Tailwind/UI 规范

- 固定格式控件必须有稳定高度和宽度，防止切换时跳动。
- 两栏使用 CSS Grid，不用手工计算 `50%` 宽度。
- flex/grid 子项需要 `min-w-0`，文本使用换行或 `truncate`。
- 不新增卡片套卡片；标签区和侧栏是工作区，不做浮动大圆角卡片。
- 现有卡片圆角保持 `rounded-md`，不要扩大到营销页式大圆角。
- 不增加渐变背景、装饰色块或无意义阴影。
- 图标优先使用现有 `lucide-react`，陌生图标必须有 `title`/`aria-label`。
- 字号不随 viewport 宽度缩放。

### 7.4 Rust/数据库规范

- 所有数据库读取继续通过 `AppState.db` 锁和 `AppResult`。
- 色板状态查询必须只读，不做隐式修复。
- 大批量色板计算继续在 `spawn_blocking` 中执行。
- 图像解码期间不得持有数据库锁。
- 不能对原素材文件做写操作。
- 不使用通用占位图计算色板。
- 错误信息不暴露用户完整文件路径；日志可记录素材 id 和汇总。

### 7.5 工作区与提交规范

建议按以下独立提交拆分，便于回滚：

1. `fix(viewer): restore single-row filmstrip and use two-column tag layout`
2. `fix(library): separate tag header from sidebar scroll body`
3. `feat(palette): expose palette readiness and refresh completed results`
4. `fix(settings): clarify color strip locations and missing-data action`

不要把前三个问题揉成一次无边界的 UI 重构。

## 10. 禁止方案

后续 AI 不得采用以下看似快速但错误的修法：

- 只把 `ViewerFilmstrip` 高度减小，却保留两行 grid；
- 把每两个缩略图包成一列后声称是“标签两栏”；
- 用 `columns-2` CSS 多栏排版标签正文，因为它可能把同一分面组从中间切断；
- 给 sticky 标题继续叠加更高 z-index 或伪元素遮罩；
- 数据为空时渲染默认灰色/品牌色色条；
- 前端对每张图重新计算主色；
- 开启总开关后静默执行全库“全部重算”；
- 每写入一张色板就刷新一次素材库；
- 直接用 SQL 修改用户设置或批量填充 `palette_json`；
- 为了色条改动或删除现有冷启动虚拟网格保护。

## 11. 完成定义

只有同时满足以下条件，任务才算完成：

1. 缩略图单行、标签两栏，且测试语义已纠正；
2. 素材库标签标题和正文分层，顶部漏字与水平滚动条消失；
3. 软件能解释色条为什么没有数据，并能在界面内生成缺失色板；
4. 色板生成完成后当前界面自动刷新；
5. 新入库后台色板完成后不需要切页或重启；
6. 前端、Rust 测试和生产构建全部通过；
7. 真机在最小、默认和宽屏窗口均无重叠、溢出或文字遮挡。
