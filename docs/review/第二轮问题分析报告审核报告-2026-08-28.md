### FB2-01 Alt+滚轮控制素材框大小

**现状描述核验：全部属实。**

| 断言 | 判定 | 证据 |
|---|---|---|
| `AssetGridView.tsx:35-36` GAP=8 / MIN_CARD=160 硬编码 | ✅ | 原文证实 |
| 列数/行高由宽度反推（:91、:95-100） | ✅ | `estimateSize` 返回正方形格子+GAP |
| 入库页纯 CSS Grid 硬编码 110px（PendingList.tsx:381） | ✅ | 原文证实 |
| 全仓库仅 MediaViewport 一处原生 wheel 监听 | ✅ | grep 证实（:151-159，`passive:false`，altKey 命中） |
| 缩略图请求尺寸常量 `Thumbnail.tsx:10` SIZE=512 | ✅ | 经 `get_thumbnail(assetId, kind, size)` 下发 |
| 缓存键 `${assetId}:${kind}:${size}`（thumbnailCache.ts:24-26） | ✅ | 原文证实 |

**方案审核：方向正确（档位化），三处需要修正。**

1. 【事实修正】**"Ctrl+滚轮被 WebView2 抢去页面缩放、所以 Alt 是技术上更正确的选择"这一论据不成立。** Chromium/WebView2 中 Ctrl+滚轮属于可取消的 wheel 事件：以 `{ passive: false }` 原生监听并对 `e.ctrlKey` 调用 `preventDefault()` 即可完全阻止页面缩放——这正是 Leaflet/Mapbox 等地图库拦截 Ctrl+滚轮的标准做法（MDN wheel 事件文档明确"若事件被取消，则不执行滚动或缩放"，Ctrl+wheel 按 pinch-zoom 处理且可取消）。既然 FB2-04 已经要在网格层挂原生 passive:false 监听，同时支持 Alt（用户点名）与 Ctrl/Cmd（行业惯例）的边际成本为零。**结论：Alt 保留没问题，但"只能选 Alt"的论证应删除，建议双键支持。**
2. 【设计缺口】**缩略图尺寸分级表对视频不生效。** 后端图片缩略图按请求尺寸独立缓存（`thumbnails/hd/{id}_{size}.webp`，尺寸参与文件名，请求 1024 会真生成 1024 图）；但**视频 hd 封面文件名固定为 `{id}_cover.jpg`（thumbnail.rs:148-153），尺寸不参与缓存键，先到的尺寸决定内容**。也就是说给 240–380px 格子请求 1024px 时，视频封面不会变清晰（返回的还是先前的 512 文件），原报告"512 在 380px 格子上 2× DPR 会糊"的问题对视频依然存在。需在后端把视频封面缓存键纳入尺寸，或明确接受视频封面不上采样。
3. 【实现细节】档位写入 settings（`app_settings` JSON）如果每次滚动档位变化都立即 `save_settings`，会产生高频落库；应采用"会话即时生效 + 防抖/失焦持久化"（与主题 `applyTheme` 即时预览 + 保存落库的模式对齐——原报告自己引用了 `SettingsPage.tsx:357`，但没有把防抖说清楚）。

其余要点（rAF 节流、`scrollToIndex` 锚点、Alt 手势需补可发现入口、`Ctrl+=/-` 决策点）均合理。`scrollToIndex(index, {align:"center"})` 在动态测量下有轻微过冲风险，验收标准已含"锚点不跳"，可接受。

### FB2-02 设置→外观：素材框比例与填充方式

**现状描述核验：全部属实，包括那处"隐藏缺陷"，且本审核独立复核了其完整机制链。**

关键复核（原报告缺陷 A）：`PendingList.tsx:67` 的 LazyThumb 根节点 `clsx("relative overflow-hidden ...", className)` 与调用处 `:216` 传入的 `"absolute inset-0"` 在同一元素上并存；已构建产物 `dist/assets/index-Dmb4mwhS.css`（tailwindcss v4.3.3）中 `.absolute{position:absolute}` 在字节偏移 7426、`.relative{position:relative}` 在 7476——**`relative` 靠后、级联胜出**，与原报告判断一致。由于 `position: relative` 不脱离文档流，该 div 参与卡片布局；其内部 `<img>`（`:73-76`）为 `h-full w-full object-cover`，父级高度 auto 时 `height:100%` 解析为 auto，图片按固有比例渲染——**卡片高度 = 预览图固有比例**（视频预览为 16:9 封面帧 → 16:9 扁条），与截图 1 症状吻合。原报告的机制链成立。

- 一个补充：`smart` 模式同一行内混两种观感、`matchDominantColor` 依赖 FB2-08 色板——原报告已如实披露代价，批次安排（2 与 3 相邻）自洽。

**"陷阱"的精确化**：完全未知的 key（如 `foobar`）经 `key_for_legacy_name` 的 `_ => "custom"`（tag_facets.rs:393）实际**会**落到 custom，warning 与行为一致（测试 ：970-981 也断言 custom）；真正踩坑的路径是"**映射到已知稳定 key、但该分面不在 valid_keys**"——典型即 `color`（或中文「色彩」「色调」）在 color 分面停用后原样落回 `:131`。因此 §12 决策点 4"未知 key 丢弃还是 custom"实际拆成两个独立问题：(a) 已知但停用 → 必须改（丢弃或 custom，二选一）；(b) 完全未知 → 现行为已是 custom，只需对齐 warning 文案。原报告把两者混为一谈，修复范围与测试改造面（:938/:970/:984 三个用例确以 color 为 valid_keys 成员，§11 所列正确）不受影响，但实施者应知道 (b) 无 bug 可修。

**迁移设计修正**：原报告 V16 计划把 color 分面 `status` 置 `deprecated`。**这与 V13 的迁移方向相反**：V13（migrations.rs:672-707）把 status CHECK 放宽为 `active|inactive|deprecated` 的同时，**将存量 `deprecated` 行统一改写为 `inactive`**（:695 `CASE WHEN status='deprecated' THEN 'inactive'`），且现行代码层只有 deactivate→`'inactive'`、restore→`'active'` 两条写路径，没有任何代码再产生 `deprecated`。在 V16 里重新引入 `deprecated` 会制造第三种状态语义。**建议改为 `enabled_for_ai=false` + `status='inactive'`**，效果等价（保留标签、可搜索、可手动编辑、不再 AI 生成），且与现有生命周期模型一致。

**算法选型核验：成立。** kmeans_colors（okaneco）官方文档证实：提供 Hamerly 优化与 `Sort::sort_indexed_colors`（结果按簇像素占比排序、自带 percentage），配合 palette 的 Lab/Oklab 使用——与原报告选型理由一致；MMCQ（Color Thief 系）不产出占比的判断也符合其算法结构。k-means 在 Lab 空间 + 缩略图尺度 + rayon 并行的性能估算（整库秒级）合理。"实施时 pin 版本"有 `rawler = "=0.7.2"` 先例支撑。

**遗漏的三个设计点（原报告未提）：**

1. **色相环绕**。"按颜色筛选"的查询编译示例 `dominant_hue BETWEEN 200 AND 250` 对蓝/绿成立，但红色跨越 0°（约 345°~15°），必须编译为双区间 `OR`，否则"搜红色素材"静默漏掉一半。`query_expr.rs` 接入时需要显式处理环绕语义，验收标准应加一条红色/品红用例。
2. **点击非主色分段的查询列未定义**。色条交互设计"点击某段 → 以该色搜索"，但索引列只有 `dominant_hue/sat/lum` 三列（对应 palette[0]）；点击第 2~N 段时没有可命中的索引列。需要三选一：只允许点击主色段；或把前 N 色的 hue 也落列（列数膨胀）；或对非主色段降级为解析 `palette_json` 全表扫描（259 项可行，大库不行）。应在设计阶段定案，否则实现时必然临时拍板。
3. **色板取材的"已生成好的 512px 缩略图"不准确**。hd 512 缩略图是**按需生成**的（入库只产出 256px placeholder，thumbnail.rs:20-21,94-104）；存量回填时多数素材并没有现成 hd 文件，`decode_thumb` 要么现场生成（解码原图，与"不碰原图"矛盾）要么改用 256px placeholder（对下采样到 ~100×100 的取色完全够用）。建议明确：入库挂点用内存中的 placeholder；回填用 placeholder 文件优先、缺失再生成。

**色条 UI、设置开关、与 FB2-02 联动、实施批次（先色板后摘除 AI，避免能力空窗）——均合理，无需改动。**

| 8 | `Ctrl/Cmd + =/-` 快捷键 | 加（可发现性）；同时按 R3 把 Ctrl/Cmd+滚轮也接上，与 Alt 并存 |

1. **根因判定**：原报告 8 个问题中 7 个的根因定位被完整证实（FB2-01 的"现状"描述、FB2-02 的类冲突机制、FB2-03 的四重根因、FB2-04/05 的高度链、FB2-06 的反馈环、FB2-07 的四问题中三个、FB2-08 的七处绑定与硬编码），定位能力值得信任；唯一被证伪的是附录 F（临时目录泄漏），以及 FB2-01 中"Ctrl 不可行"的选型论证。
