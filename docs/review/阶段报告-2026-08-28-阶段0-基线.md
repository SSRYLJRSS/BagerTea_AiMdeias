### 当前源码 fact（§6.2 ~ §6.3）

#### offsetX/offsetY 逐处标记（§6.2）
全仓 `rg "offsetX|offsetY"` 仅命中 `src/components/viewer/MediaViewport.tsx`，且**全部为状态字段名/数据字段，不是事件属性读取**：

| 位置 | 类型 |
| --- | --- |
| `MediaViewport.tsx:18-19,23` | `ViewState.offsetX/offsetY` 状态字段 + `INITIAL_VIEW` |
| `MediaViewport.tsx:57,138,148-149` | `dragStart` ref 的起点偏移数据 |
| `MediaViewport.tsx:92-94,215` | 缩放/渲染时读取*状态字段*（`v.offsetX`/`view.offsetX`） |

**结论**：源码中**没有** `event.target.offsetX` / `currentTarget.offsetX` / `nativeEvent.offsetX` 读取（§6.3 扫描零命中）；Viewer 已改用 `clientX/clientY + getBoundingClientRect`。本阶段禁止以"dist 里有 offsetX 字符串"判定旧 bug（§2.11），dist 是 08-27 产物，与当前源码不同步。

#### PageErrorBoundary（§6.4）
- 已存在 `src/components/common/PageErrorBoundary.tsx`：class 边界，state 记录 `hasError/error/componentStack`；提供「重新加载」(onReset) 与「返回素材库」(onBack)。
- `src/App.tsx:85` 已按页面包裹（`key={page}`），5 页共用。

## 关键结论（影响后续阶段）
1. **FB-01 证据**：当前源码 Viewer 已用 rect 坐标、无事件 offsetX 读取——用户报告的缩放 TypeError 更可能来自运行时竞态/旧包，阶段 1 按指导书 §7 补**代际保护 + 坐标契约纯函数 + temporaryZoom 状态机 + §7.5 素材级错误恢复 UI + 测试**，而不是推翻重写。
2. **FB-02 证据**：`ollama_installer.rs:812-828` `start_service_inner` 确为 `cmd.spawn()` 丢弃 Child、无 `OLLAMA_KEEP_ALIVE`；`ollama_cmd.rs:372` ping 短路存在但不落 ownership；无任何 stop/退出钩子（详见 FB-02 调研报告）。
3. **FB-03 证据**：videoTagging 单事实源已立（settings → DB → batch），但前端无「已开启/未开启」旁注、`ai_start_batch` 无视频预检、`ai_cloud.rs:760-761` 注释失实、文案用旧路径「在线打标」且前后端不一致。
4. **FB-05 证据**：概念层协议完全缺失；collect_tag_dictionary 每分面 LIMIT 30 无缓存；color 迁移 V11 已存在待补测试；FilterChips/FilterPanel 为死代码。

6. **FB-07 证据**：`SettingsPage.tsx:283` `max-w-xl` 为小框化唯一源头；导航 160px；保存栏非 sticky。
