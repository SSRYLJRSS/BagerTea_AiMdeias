## 3. 详细问题分析

### 3.1 素材库视频悬浮播放位置不符合需求

#### 用户现象

- 鼠标悬停视频时，希望视频在原素材显示框的位置播放。
- 播放框可以比原卡片稍微放大，但不希望尺寸过大。
- 不希望预览框被移动到卡片下方。

#### 当前代码

`MediaPreviewPopover` 默认把浮层放到触发器下方：

```ts
let top = trigger.top + trigger.height + margin;
```

位置：`src/components/media/MediaPreviewPopover.tsx:26`

只有当下方空间不足时才切换到上方：

```ts
if (top + popover.height > viewport.height - margin) {
  top = trigger.top - popover.height - margin;
}
```

位置：`src/components/media/MediaPreviewPopover.tsx:27-29`

视频内容区域还使用固定高度：

```tsx
<div className="relative h-64 w-full ...">
```

位置：`src/components/media/VideoPreviewContent.tsx:56`

#### 根因

当前实现是独立的 `position: fixed` 浮层，而不是卡片内部覆盖层。布局策略是“下方优先、上方避让”，与“在原显示框位置稍微放大”的需求不同。

#### 修改建议

建议将视频悬浮预览改为卡片内部的覆盖播放层：

```text
卡片容器（relative）
├── 原缩略图
└── hover 播放层（absolute，覆盖卡片）
    └── video
```

尺寸建议使用原卡片尺寸或原卡片的 1.2～1.4 倍，避免固定 `420px` 宽度和 `h-64` 高度。若确实需要放大，应以卡片中心为锚点，不能默认移动到下方。

### 3.2 视频悬浮预览存在额外延迟和类型误判风险

#### 当前代码

悬浮触发器本身有 300ms 进入延迟，视频组件又额外等待 250ms：

```ts
const t = setTimeout(() => setMode("video"), 250);
```

位置：`src/components/media/VideoPreviewContent.tsx:26-29`

素材卡片通过 `durationMs` 判断视频：

```ts
const isVideo = asset.durationMs != null;
```

位置：`src/components/library/AssetCard.tsx:55`

#### 根因

实际播放需要等待约 550ms 才可能开始。若导入时视频时长没有成功读取，`durationMs` 为 `null`，视频会被当作图片处理，完全不会进入视频预览逻辑。

#### 修改建议

视频类型应优先根据 MIME 判断：

```ts
const isVideo = asset.mimeType.startsWith("video/") || asset.durationMs != null;
```

`durationMs` 应只用于显示时长，不应作为唯一类型判断依据。视频播放生命周期应绑定 hover active 状态，鼠标离开立即暂停并清理实例。额外的 250ms 延迟应删除或缩短，避免与悬浮触发延迟叠加。

### 3.3 “全部确认”按钮在有建议时消失

#### 用户现象

AI 已经生成了标签建议，但“全部确认”按钮消失，只能逐张确认。对于几百张图片，这使批量写入流程不可用。

#### 当前统计逻辑

```ts
pending: pending.filter((s) => Object.keys(s.suggestedTags).length === 0).length,
withSuggestions: pending.filter((s) => Object.keys(s.suggestedTags).length > 0).length,
```

位置：`src/pages/AiTaggingPage.tsx:142` 附近。

按钮条件：

```tsx
{stats.pending > 0 && !running && (
  <Button>全部确认（{stats.pending}）</Button>
)}
```

位置：`src/pages/AiTaggingPage.tsx:381-385`

#### 根因

代码把“待生成建议”和“待确认建议”混成了两个统计项，但按钮使用了错误的 `stats.pending`：

- `status = pending` 且 `suggestedTags` 为空：待生成建议。
- `status = pending` 且 `suggestedTags` 非空：待确认建议。

AI 生成建议后，前者变成 0，后者增加，但按钮仍然只检查前者，因此按钮消失。

#### 后端关联问题

后端 `confirm_all_pending` 查询：

```sql
WHERE batch_id = ?1 AND status = 'pending'
```

位置：`src-tauri/src/db/ai.rs:496-500`

该查询没有排除 `suggested_tags` 为空的项目。空建议也可能被标记为已确认并增加批次 confirmed 计数，但实际上没有写入任何标签。

#### 修改建议

前端增加清晰的三个统计：

```text
待生成建议 = pending && suggestedTags 为空
待确认建议 = pending && suggestedTags 非空
已确认 = confirmed
```

“全部确认”按钮使用“待确认建议”数量：

```text
全部确认（待确认建议数）
```

后端批量确认也只处理非空建议，避免空建议被错误计数。

这是 P0 级问题。

### 3.4 历史批次撤销可能误删后续标签

#### 当前流程

前端历史批次按钮调用：

```ts
undoTagBatch(batchId)
```

位置：`src/pages/AiTaggingPage.tsx:208-216`

后端读取该批次所有流水：

```sql
SELECT asset_id, tag_id, op, actor
FROM tag_ops
WHERE batch_id = ?1
ORDER BY id DESC
```

位置：`src-tauri/src/db/tag_ops.rs:77-88`

遇到 `add` 时直接删除关联：

```sql
DELETE FROM asset_tags
WHERE asset_id = ?1 AND tag_id = ?2
```

位置：`src-tauri/src/db/tag_ops.rs:101-104`

#### 根因

撤销只按 `asset_id + tag_id` 删除，没有检查当前关联是否仍然属于原批次。典型风险：

1. AI 批次 A 添加标签 X。
2. 用户删除 X。
3. 用户手动重新添加 X。
4. 用户撤销批次 A。
5. 当前实现会把第 3 步重新添加的 X 也删除。

此外，撤销后批次的 `confirmed` 数量没有归零，也没有 `undone` 状态，历史列表仍会显示“撤销”。

#### 修改建议

撤销删除必须带来源批次约束：

```sql
DELETE FROM asset_tags
WHERE asset_id = ?1
  AND tag_id = ?2
  AND source_batch_id = ?3
```

同时建议增加明确的批次撤销状态，例如 `undone`，保证：

- 同一批次只能真正撤销一次；
- 用户后续重新添加的标签不会被误删；
- UI 能显示“已撤销”；
- 撤销后的统计与按钮状态一致。

### 3.5 工作台强制显示不需要的分面

#### 当前代码

固定基础分面包含：

```text
subject
scene
purpose
style
color
composition
lighting
people
technical
custom
```

位置：`src/stores/tagStore.ts:73-85`

`buildWorkbenchFacets` 无条件把全部基础分面加入：

位置：`src/stores/tagStore.ts:115-128`

`enabledForAi` 只影响 AI 提示词，不影响工作台显示。`Workbench` 又直接遍历所有 `panelFacets`：

- `src/components/ai/Workbench.tsx:109-125`
- `src/components/ai/Workbench.tsx:263-297`

#### 与需求的差异

- 风格/氛围
- 色彩
- 构图/视角

- 用途

#### 根因

代码将“基础分面恒显”作为固定规则实现，没有把“参与 AI”与“显示在工作台”拆成两个独立配置。

#### 修改建议

建议增加 `visibleInWorkbench` 配置；如果暂时不扩展数据结构，至少先使用明确的工作台显示白名单。`enabledForAi` 不应继续承担工作台显示职责。

### 3.6 色彩、光线、时间标签缺失或归类错误

#### 6.1 默认配置没有独立 color 分面

默认分类包含：

### 3.7 普通单击已选素材不会取消选择

#### 当前代码

```ts
if (e.shiftKey) {
  rangeTo(index, orderedIds);
} else if (e.ctrlKey || e.metaKey) {
  toggle(asset.id, index, true);
} else if (!selected.has(asset.id)) {
  toggle(asset.id, index, true);
}
```

位置：`src/components/library/AssetGridView.tsx:78-86`

#### 实际行为

- 第一次普通点击：选中。
- 再次普通点击已选素材：什么都不做。
- Ctrl/Command 点击：才会切换。

#### 修改建议

普通点击应实现真正的切换：

```text
未选中 -> 选中
已选中 -> 取消
```

同时需要同步修改现有测试。当前测试明确固化了“再次普通点击保持选中”的旧行为，因此测试本身也与用户需求冲突。

### 3.8 Shift 多选只能追加，不能取消范围

当前 `rangeTo`：

```ts
const next = new Set(s.selected);
for (let i = lo; i <= hi; i++) next.add(orderedIds[i]);
```

位置：`src/stores/selectionStore.ts:36-43`

它永远追加，不会删除。如果重复选择同一范围，选中状态不会取消。

另外，`rangeTo` 结束时没有更新 `anchorIndex`，连续 Shift 操作仍然围绕旧锚点，容易产生与“最后一次点击为锚点”不一致的结果。

#### 修改建议

建议明确规则：

- 范围内全部已选：取消整个范围；
- 范围内有未选：补选整个范围；
- 操作完成后更新 `anchorIndex` 为当前 index。

也可以保留系统文件管理器的范围选择语义，但必须补充覆盖测试，确保重复 Shift 操作有确定结果。

### 3.9 Shift 操作时周围文字可能被选中

`AssetCard` 内层设置了 `select-none`：

位置：`src/components/library/AssetCard.tsx:68`

但 `HoverPreviewTrigger` 外层包装器没有设置 `select-none`，文件名仍是实际文本节点：

位置：`src/components/library/AssetCard.tsx:96-100`

在 Shift 点击、拖动或浏览器范围选择时，外层文本仍可能参与选中。

#### 修改建议

- 将 `select-none` 放到 `HoverPreviewTrigger` 外层。
- 对文件名、角标设置 `user-select: none`。
- 卡片点击时必要情况下调用 `preventDefault()`。
- 保证卡片整体是唯一选择交互元素，文本不参与浏览器选择。

### 3.10 视频打标提示“未开启”的原因

后端判断非常明确：

```rust
if is_video && !cfg.video_tagging {
    return Err(AppError::msg(
        "视频 AI 打标未开启（设置 → AI 打标 → 视频 AI 打标）",
    ));
}
```

位置：`src-tauri/src/services/ai_cloud.rs:725-730`

设置页开关位置：

- `src/pages/SettingsPage.tsx:294-295`

开关修改后必须点击底部“保存设置”，否则后端仍然读取旧值。由于设置页可能白屏，用户无法完成这一步，于是形成：

```text

  -> 无法开启 videoTagging
  -> 视频批次启动时报“视频 AI 打标未开启”
```

建议在启动视频批次前，将当前配置状态显示在打标页，并提供直接跳转设置的入口；保存成功后重新读取设置，避免前端显示值与后端配置不一致。

## 4. 设置页白屏分析

### 4.1 当前已有的加载失败处理

`settingsStore` 会把 `get_settings` 失败写入 `loadError`：

- `src/stores/settingsStore.ts:26-34`

`SettingsPage` 在 `loadError` 存在时显示错误和重试入口：

- `src/pages/SettingsPage.tsx:85-103`

这只能处理设置接口请求失败，不能处理组件渲染阶段异常。

### 4.2 白屏的结构性原因

`App.tsx` 没有页面级 Error Boundary。只要 `SettingsPage` 或子组件出现未捕获异常，整个 React 树都可能卸载，用户看到的就是白屏。

设置页依赖多个复杂组件和异步接口：

- `LocalModelGroup`
- `ModelSelect`
- `TagManageDialog`
- `ollamaInstallStatus`
- `getDataDir`
- `structuredClone(settings)`

位置：`src/pages/SettingsPage.tsx:5-12`、`src/pages/SettingsPage.tsx:50-70`

### 4.3 修改建议

1. 在 `App` 或设置页外层加入页面级 Error Boundary。
2. 对 `settings.ai`、`settings.aiFacetConfigs`、`settings.customDownloadSources` 做运行时兜底。
3. 将“设置加载失败”和“子组件渲染失败”分成不同错误提示。
4. 在开发模式下记录 WebView 控制台堆栈，确认本次白屏的第一条异常。
5. 在设置页增加最小可用降级视图，即使 Ollama 检测失败，也不能阻塞在线设置和视频 AI 开关。

当前静态排查可以确认“缺少错误边界会把运行时异常表现为白屏”。要精确确认此次白屏的具体第一条异常，还需要实际运行时控制台堆栈。

## 5. 建议修改顺序

### 第一阶段：恢复基本可用性

1. 修复“全部确认”按钮条件。
2. 给设置页增加 Error Boundary。
3. 确保 `videoTagging` 修改后保存并能被 AI 批次读取。
4. 将视频类型判断改为 MIME 优先。
5. 给视频打标失败提供明确的设置跳转提示。

### 第二阶段：修复打标数据正确性

1. 将“待生成”和“待确认”统计分开。
2. 后端批量确认排除空建议。
3. 增加工作台分面显示控制。
4. 暂时隐藏用途、可用性/技术特征、自定义。
5. 增加独立 `color` 默认配置。
6. 将 AI 返回协议改成稳定 facet key。

### 第三阶段：修复撤销和素材选择

1. 撤销只删除 `source_batch_id = batchId` 的关联。
2. 增加批次 `undone` 状态或等价幂等标记。
3. 普通点击已选素材时取消选择。
4. Shift 范围选择支持取消，并更新锚点。
5. 统一禁止卡片周围文本选择。

### 第四阶段：调整视频悬浮预览

1. 播放层覆盖在原卡片位置。
2. 尺寸与原卡片相近，仅做轻微放大。
3. 删除额外的 250ms 播放延迟。
4. 统一 hover 进入、离开时的播放和暂停。
5. 增加加载失败、编码不支持和双击打开完整播放器提示。

代码修改后建议至少补充以下自动化测试：

### 视频预览

- 视频 MIME 存在但 `durationMs = null` 时仍识别为视频。
- hover 激活后视频在卡片覆盖层播放。
- 鼠标离开后视频暂停并卸载。
- 播放失败时回退封面并显示错误状态。

### AI 批量确认

- 有非空 `suggestedTags` 的 pending 项时显示“全部确认”。
- 全部确认不处理空建议。
- 全部确认后批次 confirmed 计数与真实写入数量一致。

### 批次撤销

- 撤销只删除当前批次写入的关联。
- 后续手动重新添加的同一标签不会被删除。
- 重复撤销返回 0，并且 UI 显示已撤销。

### 分面

- 默认工作台不显示用途、技术特征、自定义。
- `color` 有独立 AI 提示配置。
- 稳定英文 facet key 能正确回写。
- 未知 AI key 会产生 warning，不会静默吞到 custom。

### 素材选择

- 普通点击：选中/取消切换。
- Ctrl/Command 点击：多项切换。
- Shift 范围重复操作：按明确规则选中或取消。
- Shift 点击不会选中文件名和角标文本。

### 设置页

- `get_settings` 失败显示重试界面。
- Ollama 检测失败不阻塞在线设置。
- 任意设置子组件异常时显示错误页而不是白屏。
- 打开、修改、保存视频 AI 开关后，重新启动批次能读取新值。

## 7. 最终结论

当前问题不是单个样式错误，而是状态语义、数据来源和 UI 交互三方面同时存在不一致：

```text
设置页白屏
  -> 无法开启视频 AI 打标
  -> 视频批次提示未开启

AI 生成建议
  -> 统计把“待确认”误当成“待生成”
  -> 全部确认按钮消失

标签配置
  -> 工作台固定显示全部基础分面
  -> 用途/技术特征/自定义出现
  -> color 默认配置缺失
  -> 中文分类不稳定时被归到 custom

批次流水
  -> 撤销不检查来源批次
  -> 可能删除用户后续重新添加的标签

素材选择
  -> 普通点击不取消
  -> Shift 只能追加
  -> 文本选择未完全隔离
```

建议优先处理 P0 问题：设置页白屏、全部确认按钮、视频 AI 开关链路。之后再处理撤销数据安全、标签分面正确性、选择交互和悬浮播放视觉表现。
