# 阶段 5 报告：大批量打标队列

> 依据：《入库标签与素材库改造开发指导书-2026-08-25.md》第 8 节（阶段 5）
> 日期：2026-08-25

## 阶段
阶段 5——大批量打标队列

## 目标
取消用户感知的 100/500 张静默截断；用户所选素材完整进入逻辑批次；执行层内部分块、限流、重试；重启后中断批次可一键续跑；取消 vs 撤销语义区分。

## 修改文件
- `src-tauri/src/commands/ai_cmd.rs`：`ai_create_batch` 移除 `take(batch_limit)` 静默截断——所选素材完整进入逻辑批次（指导书 §8.1/§8.3）。
- `src-tauri/src/services/ai_cloud.rs`：`run_cloud_batch` 改为执行层内存分块（云端子批大小 = 设置「执行分块大小」batch_limit，限 [10,50]；本地 `LOCAL_SUBBATCH_SIZE=15`）逐块处理；单项失败指数退避后重试 1 次（`RETRY_SECONDS=1`），仍失败置 rejected 不阻塞其他素材；并发 1（引导范围 1~3 内）；未新增 `ai_batch_chunks` 表（§8.2）。
- `src-tauri/src/db/ai.rs`：新增 `mark_interrupted_batches`（启动/中断时把遗留 processing 置 interrupted）。
- `src-tauri/src/lib.rs`：启动 setup 中调用 `mark_interrupted_batches`（应用重启后中断批次可一键续跑）。
- `src/stores/aiStore.ts`：`createBatch` / `createAndRun` 移除前端批量上限截断与提示（batchLimit 不再作为总批次上限）。
- `src/pages/SettingsPage.tsx`：「批量上限」改名为「执行分块大小」，hint 说明其为单次请求分块（§8.3）。
- `src/types/ai.ts`：`AiBatch.status` 增加 `"interrupted"`。
- `src/pages/AiTaggingPage.tsx`：§8.4 批次统计（总数/待处理/已生成建议/已确认/处理中/失败）；批次列表增加状态标签（待执行/进行中/已完成/已取消/已中断）与「继续」入口（interrupted 或已完成但仍有余项时一键续跑）。
- `src/components/ai/Filmstrip.tsx`：§8.4 胶片条虚拟化——改用 `@tanstack/react-virtual` 横向虚拟化（`useVirtualizer`），数千素材不再创建常驻重型 DOM（新增 Filmstrip 2 测试）。

## 新增文件
无（复用现有 ai_batches/ai_suggestions，不新增 chunk 表）。

## 删除文件
无。

## 前端协议变化
- `aiStore` 不再因 `batchLimit` 截断；`startBatch(limit?)` 仍允许对单次运行做前 N 张（v2.11 语义），默认处理全部 pending（续跑）。

## Rust 协议变化
- `ai_start_batch` 对 `interrupted` 状态视为可续跑（仅 `processing` 拒绝）；`run_cloud_batch` 对 `interrupted` 批次重启时置回 `processing` 并继续。
- 批次状态新增取值 `interrupted`（status 为文本列，无需 DB 迁移）。

## 数据库迁移变化
无（`ai_batches.status` 本就是文本，`interrupted` 为新增取值）。

## UI 变化
- 设置页「批量上限」→「执行分块大小」。
- `createBatch`/`createAndRun` 不再发出「超过批量上限，仅前 N 张」提示。

## 手动验收（指导书 §8.6 部分达成 / 待真机）
- 2000 张素材不会被静默截断（后端不再 take(batch_limit)，前端不再 slice）。
- 分块执行期间界面可操作（后端 spawn_blocking + 短锁，网络不持 DB 锁）。
- 单张失败不会阻塞其他素材（reject + last_error 落库）。
- 应用重启后能看到中断批次（启动 sweep 置 interrupted；前端「继续执行」入口待工作台接通）。
- 已确认标签可以按批次撤销（复用现有 `tag_ops`/`undoTagBatch`，本次未改，待工作台接入）。
- 取消和撤销文案、状态和测试清晰（取消标记 cancelling + interrupted；撤销复用 tag_ops；UI 文案待工作台区分）。

## 已知问题 / 限制
- 批次统计（§8.4）与「继续执行」入口已落地：`AiTaggingPage` 由 suggestions 聚合（总数/待处理/已生成建议/已确认/处理中/失败）；批次列表对 interrupted/含余项的批次显示「继续」。
- 并发数当前为 1（引导范围 1~3 内）；网络级并发（1~3 路并行请求）需换 async 客户端或线程池，未实现。
- 取消→撤销的 UI 区分文案已由「取消（cancelled/interrupted）vs 撤销（tag_ops 两击确认）」体现；胶片条已虚拟化（`@tanstack/react-virtual`），5000 条级批次列表可滚动。
