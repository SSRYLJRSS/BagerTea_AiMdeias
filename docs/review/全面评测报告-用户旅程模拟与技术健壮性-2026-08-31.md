## 一、评测概述

### 1.1 评测背景

本项目定位为**开发版本 = 长期软件基础**，即当前代码库不是一次性演示品，而是后续持续演进的底座。因此本次评测将**架构稳定、运行流畅、无 Bug** 置于最高优先级，任何改动建议都以不破坏底座稳定性为前提；功能扩张类建议一律标注为「需用户拍板」，不在评测中替用户做取舍。

### 1.2 评测范围与方法

本次评测由两条独立工作线交叉构成：

1. **端到端代码走查 + 用户旅程模拟**：通读前端页面/组件/工具（`src`）、后端命令/服务/数据层（`src-tauri\src`）与核心文档（PROJECT_PLAN / PROGRESS / HANDOVER / PRD），按 12 个真实使用环节逐一模拟用户旅程，记录断点与缺口。
2. **技术健壮性 + 本地模型专项审查**：全量阅读打标链路（ai_cloud.rs / tag_facets.rs / ai.rs / ai_cmd.rs / ollama_setup.rs / settings.rs）、迁移与数据层（migrations.rs / mod.rs / assets.rs / ai_connections.rs）、启动与状态（lib.rs / state.rs / main.rs）、配置文档（A2/A3）与前后端 Ollama 封装，并交叉核对测试文件清单。

静态代码走查的已知边界：无法覆盖真机交互（视频 Range 播放、3 万素材性能等文档中标注「真机走查待做」的项），性能类结论以文档与代码机制为准。

### 1.3 总体结论

**项目工程底座（分层、短锁模式、迁移幂等、解析容错、自愈重试、人工确认闸门）明显高于同类水平，阻断级缺陷为零。** 真正的短板集中在两处：**本地小模型的提示词工程**（无受控词表、无结构化输出约束、无 system/few-shot、分面描述被采集却不进提示词）与**发布版日志出口**（tracing 只写 stdout，发布版无窗口可见）。体验层的主要断点集中在首启引导缺失、去重入口被隐藏、GPS 数据「存而不用」等低成本可修复项；完全缺失的候选功能（备份/收藏评级等）均属功能取舍，需用户拍板后再排期。

## 三、本地模型（Ollama）打标专项审查【最高优先】

### 3.1 现状优点（先说已做对的）

- **稳定英文 facetKey 作为 JSON 键**，中文名仅作说明，并有旧中文 key 归一映射与「未知 key 归 custom + warning、停用分面丢弃」的校验链（`ai_cloud.rs` L142-170 `parse_categorized_checked`；`tag_facets.rs` L534-557 `key_for_legacy_name`）。
- **解析容错做得细**：剥 ```json 围栏（L298-307）、截取 `{...}` 片段、扁平数组收「未分类」、标签 ≤20 字且每分面 ≤5 个（L120-122）。
- **本地模型专项自愈**：退化输出检测（@@@@/Latin-1 乱码，L177-194）+ `keep_alive=0` 卸载重载后重试（L455-472），引用 ollama#8235/#17587，为业界验证过的恢复手段。
- **人工确认闸门完整**：AI 结果只落 `ai_suggestions`（pending），确认才写 `asset_tags`；候选项明细支持逐条 accepted/modified/rejected；来源标记 manual/ai_cloud/ai_local（`db/ai.rs` L376-491）。
- **上下文无爆仓风险**：每张图一次请求（非多图拼 prompt），提示词体积只随分面数线性增长。

### 3.3 模型配置链路（A2/A3）缺口

**总体可靠**：`api_root()` 剥 `/v1` 有单测；ping（2s 超时，连不上不报错）；nvidia-smi 探针避开 AdapterRAM 32 位坑（A2 文档 §3.3，ollama_setup.rs L126-158）；推荐档位合理（≥12GB 推 qwen2.5vl:7b，否则 3b，未知显存诚实预期，L162-210）；pull 流式进度+取消+120 分钟墙钟；A3 一键安装多源降级+断点续传+静默安装+ownership（External 永不停）设计完整。

**缺口**：

1. **视觉能力检测 = 纯模型名启发式**（`model_supports_vision` ai_cloud.rs L252-286），且**只用于视频批次预检**（ai_cmd.rs L140-150）；纯图片批次不检查 → 本地挂纯文本模型（如 llama3）时，图片照发、图像被忽略、批量产出幻觉或空结果。Ollama 原生 `/api/show` 返回 `capabilities`（含 vision），可做权威检测，未使用。
2. **批次启动不预检「模型是否存在」**。只有 `test_connection` 校验模型在列表中（ai_cloud.rs L966-983），`ai_start_batch` 不调用 → 模型名写错时 100 张图 = 200 次必败请求逐条 rejected，无 fast-fail。
3. **批次级无连续失败熔断**（run_cloud_batch L1263-1302：单条失败退避 1s 重试 1 次后继续，服务整体不可用时仍逐条消耗）。
4. **`local_model_tier` 死配置**：设置字段定义了但后端无任何消费点（settings.rs L86-87 全库仅 2 处引用，均在定义处）。
5. **`LOCAL_SUBBATCH_SIZE=15` 分块无实际行为差异**（L1263 双层循环，chunk 间无 lease 延长/限流动作），注释自承「连续批次由 lease 延长是 L3 目标态」——代码与注释不符，风险低。

### 3.4 可直接采用的提示词结构建议（针对 qwen2.5vl 3b/7b、llava 级小模型）

```
[system]
你是素材库打标员。严格只输出一个 JSON 对象，禁止输出任何其他文字、解释或代码围栏。
标签必须用中文，2-6 个字，不带标点和空格。不确定就留空数组，禁止猜测。

[user]
## 任务
为这张图片输出：一句话中文描述 + 分面标签。

## 分面定义（key 必须原样使用）
- subject 主体/对象：画面中可观察到的主要对象（可多选，1-5个）。优先从候选词选择：{top-N 候选}
- scene 场景/地点：…（可多选，1-3个）。候选词：{…}
- style 风格/氛围：…（单选，最多1个）
…（每个分面 = key + 中文名 + description + 规则 + hint + 候选词）

## 输出格式
{"description":"<≤20字，不以『这是一张』开头>","tags":{"subject":[…],"scene":[…]}}

## 约束
1. 每个标签只归一个分面；无合适标签给空数组。
2. 标签优先复用候选词；候选词没有且非常确定时才新造。
3. single 分面最多 1 个；多选分面不超过标注上限。
4. 不输出文件质量、摄影建议。

## 示例
输入：<示例图> → {"description":"夜晚树下多人合影","tags":{"subject":["人物","树"],"scene":["夜景","户外"],"style":["胶片感"]}}
```

### 3.5 配套改造清单（按性价比）

1. 打标请求对本地档案启用 `response_format:{"type":"json_object"}`（复用现成 TextJsonTier 第 2 级即可，零新代码量级）。
2. `build_prompt` 拼入 `description`（一行代码级修复，先于词表注入）。
3. 每分面注入 Top-N（如 15 个）高频已有标签作为候选词（`tags` 表按 facet_key+使用次数取，上下文增量可控）。
4. 解析端强制 single/max_items 裁剪，超量保留前 N 并记 warning。
5. 让模型输出 `confidence`（0-1）写入 `ai_suggestion_items.confidence`，审核界面低置信标红。
6. 批次启动前对本地档案做：ping + `/api/show` 视觉能力 + 模型存在性三检（图片批次也检）。

## 四、稳定性缺陷清单

## 六、体验断点清单（按严重度分级）

### 高

1. **去重面板 UI 入口被隐藏**：后端 `dedup_scan` + `DupDialog` 完整，但 `GridToolbar` 不渲染入口（`GridToolbar.tsx:24`「暂隐藏」），用户在界面上找不到已交付的功能。
2. **空库/首次启动零引导**：默认页空态为纯文字「没有符合条件的素材」（`AssetGridView.tsx:321`），不区分「库为空」与「筛选无结果」，无导入/配置 CTA，新用户旅程第一步就断。
3. **数据库无备份手段**：单机唯一副本 + 只有重置（`reset.rs`）没有备份，误操作「重置数据」不可逆。

### 中

4. **导入失败明细不可见**：只显示 `errors[0]` 且单行截断（`ImportPage.tsx:272-274`），批量导入失败多个文件时无法定位。
5. **GPS 数据「存而不用」**：入库解析、DB 存储、后端可查询（`search_query.rs:106`），但信息面板不显示、超级搜索构建器无定位字段（`QueryBuilder.tsx:28-31`）、无地图——半成品状态浪费了已做的 V18 回填。
6. **旋转不持久**：查看器旋转仅视觉（`MediaViewport.tsx:93`），竖拍图修正后关闭即还原。
7. **库内无「用默认程序打开」**：右键菜单只有复制路径/打开文件夹（`AssetGridView.tsx:299-308`），入库清单却有外部打开（`ImportPage.tsx:285`），能力不一致。
8. **搜索状态易失**：超级搜索条件不持久化（无任何 localStorage），切页往返需重建条件。
9. **断网/离线无显式状态**：云端打标与 AI 搜索失败仅透传错误文案，无网络层归因提示。

### 低

10. 高清缩略图生成失败静默（`Thumbnail.tsx:71`），个别黑图无重试/提示入口。
11. 「关于」页只有静态版本号，无日志查看入口（tracing 仅落文件——实际当前发布版连文件也没有，见 S1——普通用户不可达）。
12. 导入中断后无显式续传任务（靠重导+去重隐性恢复，用户无感知）。
13. 打标页「无 API 配置」提示为纯文字，无一键跳转设置（`AiTaggingPage.tsx:474-477`）。

> 分级说明：高级 = 已交付能力不可达或新用户旅程直接中断；中级 = 功能可用但排障/效率明显受损或既有投入未释放；低级 = 边缘感知与文案级问题。高级 3 项均为低成本修复，建议优先消化。

## 八、实施优先级总表（P0-P3）

> 分级口径：**P0** = 影响核心功能可用性/数据安全且改动小，立即施工；**P1** = 一个迭代内应完成的高价值修复；**P2** = 中期消除隐患/释放既有投入；**P3** = 长期/按需，含待拍板的候选功能。
>
> 合并两份材料优先级结论。冲突处注记：旅程材料将「备份/收藏评级」列为高优先**功能缺口**，技术材料将其排除在稳定性优先级之外——本报告取保守立场：备份/恢复在「数据风险」维度列为 **P1 建议项**，但因属功能取舍需用户拍板，不占用稳定性施工通道。
