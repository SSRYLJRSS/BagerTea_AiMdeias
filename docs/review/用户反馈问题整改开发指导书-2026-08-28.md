## 1. 总体目标

完成以下闭环：

```text
Viewer：图片放大/拖拽/切图不崩溃，异常可重试或返回素材库
入库：视频在自己的小框内静音自动播放，离开释放；素材库保持无 hover 媒体
搜索：红色建筑拆为主体建筑 + 颜色红色，形成 AND 条件
搜索 UI：多条件时条件区收缩，滚动上恢复，到底部可快速编辑
设置：右侧充分利用宽屏，视频 AI 开关路径清楚且和后端一致
本地 AI：按需启动，自动卸载，应用拥有的服务可停止，外部服务不误杀
```

## 4. 通用施工规范

### 4.1 分层

```text
React 页面/组件 -> stores / api -> Tauri commands -> services -> db/filesystem/external process
```

页面不拼 SQL、不管理进程；command 只做校验、短锁读取、任务启动和事件转发；service 处理耗时工作；DB 负责事务和事实源。

### 4.2 TypeScript

- 所有 Props、API 响应和 store 状态显式类型化。
- 异步错误使用 unknown，统一转成人类可读消息。
- DOM 使用 useRef；异步回调执行前检查节点和代际。
- 清理 timer、listener、AbortController、pointer capture、video src。
- 列表素材 key 使用稳定 asset.id，禁止用 index 作为身份。
- 复杂逻辑提取纯函数测试，不把状态机塞进 JSX。

### 4.3 Rust

- 外部输入先校验；SQL 全部参数绑定。
- 外部进程必须有超时、退出码、stderr 摘要、kill/wait 清理。
- 网络请求设置连接和总超时。
- Mutex 只包住查询/写入，不包住 IO/网络/解码。
- serde 字段和前端 camelCase 对齐。
- 错误消息包含原因、影响和可执行动作。

### 4.4 UI

遵守 docs/UI_DESIGN_SYSTEM.md：黑白灰高级感、主题变量、主 CTA 墨黑实心、普通动作幽灵/文字按钮、危险色只用于危险场景、普通区块使用细分隔线、控件具备 focus 和中文 aria-label。动画优先 transform/opacity，避免高频 height 重排。验收 1920、1440、1366、1024、768px 和窄屏。

## 7. 阶段 1：Viewer 缩放和上游异常

### 7.1 目标行为

- 双击、Alt+滚轮、放大拖拽均不抛异常。
- 快速切图、关闭 Viewer、图片重试时，旧回调不修改新素材。
- 现有 PageErrorBoundary 继续提供重试和返回，不新建第二套边界。

### 7.2 坐标契约

提取唯一坐标函数：

```ts
type StageRect = Pick<DOMRect, "left" | "top" | "width" | "height">;

function pointerInStage(clientX: number, clientY: number, rect: StageRect) {
  return {
    x: clientX - (rect.left + rect.width / 2),
    y: clientY - (rect.top + rect.height / 2),
  };
}
```

要求：

1. 只使用 clientX/clientY 和 stageRef.getBoundingClientRect()。
2. 禁止读取 SyntheticEvent 的 offsetX/offsetY 或 target.offsetX。
3. ref 缺失、宽高为 0、坐标非 finite 时安全返回。
4. 双击、wheel、触摸缩放统一调用同一 reducer/函数。

### 7.3 代际保护

建议使用 const generation = useRef(0)。在 assetId、图片源、重试、关闭/卸载时递增。原生 listener、图片 onLoad/onError、Promise 回调捕获 generation，执行前不一致则丢弃。

### 7.4 Pointer 状态机

```text
idle -> panning -> idle
idle -> temporaryZoom -> idle
```

pointerup、pointercancel、卸载都释放 capture；scale 范围 0.2~8；恢复 1x 时 offset 归零；dragStart 为空时 pointermove 直接返回。

### 7.5 错误恢复 UI

不要新建第二套错误页。Viewer 局部错误时沿用现有边界视觉：

```text
当前素材暂时无法显示
可能是文件损坏、路径不可用或媒体解码失败。
[重新加载当前素材] [返回素材库]
```

重新加载当前素材必须重新获取 URL/高清图并重置 Viewer 状态，不能只清空 error。

### 7.6 测试

- 坐标函数正常 rect、0 宽高、缺失 rect。
- 1x->2x->1x、0.2x 和 8x 边界。
- wheel 锚点误差 <=1px。
- 快速切图后旧回调不改新素材。
- ref null、pointercancel、卸载均不抛异常。
- 真机 WebView2 复现一次，不能只依赖 jsdom。

## 8. 阶段 2：Ollama 生命周期与内存

### 8.1 L1 低成本止血

修改 src-tauri/src/services/ollama_installer.rs 的 start_service_inner：

- 启动应用自己的 ollama serve 时注入 OLLAMA_KEEP_ALIVE，默认建议 2m，常量化。
- 保留代理环境变量。
- 外部已有服务不重启、不改环境。
- 增加命令构造测试和日志，不记录密钥。

Ollama 原生 generate/chat 支持 keep_alive: 0 卸载模型。参考：https://docs.ollama.com/api/generate 和 https://docs.ollama.com/api/chat。

### 8.2 L2 ownership

当前 cmd.spawn() 丢弃 Child。改为保存 Child/pid 和 ownership：

```rust
enum ServiceOwnership {
    External,
    AppOwned { pid: u32, started_at: i64 },
}
```

规则：

- 启动前 ping；已有服务标记 External。
- 应用启动成功后保存 pid/Child，防重复启动。
- Windows 优先 Child kill/wait；必要时经校验使用 taskkill /PID <pid> /T。
- 应用退出、明确关闭、安装重启只停止 AppOwned。
- 外部服务永不由应用杀掉。

### 8.3 L3 Runtime Manager

后续目标态，不阻塞 L1/L2：

```text
idle -> starting -> ready -> busy -> grace_period -> unloading -> stopped
                                           -> error
```

维护 ownership、active_requests、active_model、last_activity_at、idle timer、memory budget 和状态事件。请求默认单并发，批量排队。

### 8.4 keep_alive 请求

- 本地原生请求明确传 keep_alive，不依赖默认值。
- 连续批次由 lease 延长驻留；空闲后调用空 prompt/messages + keep_alive: 0。
- 验证 done_reason=unload 或等价信号。
- /v1 兼容端点不保证支持 keep_alive，卸载用原生根地址。
- ai_cloud.rs 现有异常自愈卸载保留，但不能代替正常生命周期。

### 8.5 设置 UI

位置：设置 -> AI 设置 -> 服务管理 -> 本机服务。普通用户看到：

```text
模型空闲后释放内存  2 分钟
应用空闲后停止服务  5 分钟
同时处理请求        1（推荐）
当前状态            未运行/运行中/模型已卸载
当前占用            RAM/VRAM/模型磁盘大小
```

PID、ownership、最近活动时间放高级折叠区。

### 8.6 测试

应用启动不进入本地 AI 不启动 Ollama；首次请求只启动一次；连续请求复用；空闲卸载；AppOwned 可停止；External 不停止；失败可读。使用 mock/fake child，禁止误杀用户外部服务。

## 9. 阶段 3：视频 AI 设置、预检和文案

### 9.1 配置事实源

```text
settingsStore.settings.ai.videoTagging

 -> run_cloud_batch 最终校验
```

### 9.2 设置 UI

冻结路径：设置 -> AI 设置 -> 自动打标 -> 视频 AI 打标。

开关旁显示已开启/未开启；修改后显示未保存；保存后显示已保存并回读设置；Ollama 探测失败不得阻塞该字段。

### 9.3 批次预检

前端和 src-tauri/src/commands/ai_cmd.rs 都要有预检：

```text
批次无视频 -> 正常启动
有视频 + 开关关闭 -> 阻止，提供打开设置
有视频 + ffmpeg 不可用 -> 阻止或明确降级
有视频 + 本地模型不支持视觉输入 -> 提示更换模型
条件满足 -> 启动
```

后端最终校验必须保留。修正 ai_cloud.rs 中命令层已预检的失实注释，只有实现存在后才能保留。

### 9.4 错误文案

统一：视频 AI 打标未开启。请打开“设置 -> AI 设置 -> 自动打标 -> 视频 AI 打标”，保存后重新开始批次。

区分未开启、未保存、ffmpeg 缺失、模型不支持图片输入、抽帧失败、服务不可达。

### 9.5 测试

设置加载失败时开关仍可显示；未保存启动有提示；保存后前后端一致；含视频批次关闭时前后端均阻止；图片批次不受影响；不同失败原因显示不同文案。

## 10. 阶段 4：入库页视频卡片内播放

### 产品范围

只改 PendingList。素材库 AssetCard 继续禁止 video、fixed 预览层和 hover 媒体。施工前用 rg 确认 Popover 旧组件消费者；没有消费者才删除。

### UI 结构

```text
PendingItem (relative)
  ├── 封面/占位图 absolute inset-0
  ├── 视频层 absolute inset-0，仅 active 时挂载
  ├── 角标
  └── 文件名/错误原因
```

禁止 position: fixed、max-width: 420px、max-height: 70vh 的独立大浮层。

### 播放规则

- hover intent 250~350ms 后挂载，快速扫过不创建实例。
- muted、playsInline、preload=metadata。
- 默认原卡片尺寸；若产品确认放大，最多 1.2~1.3 倍且以中心为锚。
- 播放失败退回封面并提示双击打开。
- 离开、卸载、入库开始时 pause、清理 src 和 listeners。
- 同时最多 1 个视频播放；触摸设备使用点击/双击。
- 双击进入 Viewer；视频控件阻止冒泡。

### 测试

PendingList 视频 hover 后在原项内出现 video；离开暂停并卸载；快速抖动不创建多个实例；编码失败有封面提示。AssetCard 测试继续断言无 video/fixed dialog。

## 11. 阶段 5：超级搜索原子意图和词典

### 11.1 语义契约

```text
红色建筑
  建筑 -> subject（或词典最合适主体分面）
  红色 -> color
  关系 -> AND
```

不能要求存在红色建筑复合标签。

### 11.2 中间协议

在 super_search_ai.rs 内部增加概念层，模型不输出 id/SQL：

```rust
struct SearchConcept {
    text: String,
    role: String,
    facet_hint: Option<String>,
    confidence: Option<f32>,
}
struct SearchConceptIntent {
    concepts: Vec<SearchConcept>,
    relation: String,
    unresolved: Vec<String>,
}
```

可先编译到现有 SearchIntent，以兼容前端。

### 11.3 本地解析顺序

1. 规范化繁简、全半角、空白和同义词。
2. canonical name 精确。
3. alias 精确。
4. 前缀/包含。
5. token overlap 或轻量 embedding 候选。
6. 按 facet hint 过滤。
7. 高置信自动选，中置信展示候选，低置信进入全文 search 并 warning。

优先级：exact > alias > prefix > token overlap > semantic similarity。

当前 collect_tag_dictionary 每分面 LIMIT 30 不能作为长期方案。短期增加热门词/别名缓存；中期按 concept 查询候选；长期用本地索引。

### 11.4 color 存量迁移

不能只改默认设置。新增版本 migration：

- INSERT OR IGNORE 创建 color facet。
- 缺失 color 的 ai_facet_configs 补默认，不覆盖用户 hint。
- 不删除/重命名旧 style 数据。
- 兼容映射集中在 normalizer。
- 未知 facet key 必须 warning。

### 11.5 颜色三档

```text
档1：color 标签（红/红色/鲜红）
档2：缩略图 HSV/Lab 主色（入库/后台计算）
档3：主体颜色（区域检测/视觉模型，标记为推断）
```

没有主体区域模型时，不把全图主色伪装成建筑颜色。

### 11.6 查询和 UI

精确 facet 优先，FTS/BM25 和向量只做召回/补充。AI 解析后显示可编辑 chips：

```text
主体：建筑 ×   颜色：红色 ×   关系：全部满足
```

未命中显示具体词和候选；用户改 chip 不重新调用 AI。至少用 30 条中文查询建立离线集，记录 Precision@10、Recall@50、零结果率、改写率，再调权重。

参考：Sage 的公开混合方案结合 caption、向量、BM25 和 reranker：https://sagecontinuum.org/labs/image-search

### 11.7 测试

覆盖红色建筑、红色的建筑不要夜景、蓝色汽车、同义词、未知词 warning、停用分面、历史查询、请求乱序和旧结果丢弃。

## 12. 阶段 6：筛选区滚动收缩和快速编辑

### 12.1 目标布局

```text
标题栏固定 40px
结果滚动容器
  ├── sticky 摘要条（搜索框/激活 chips/结果数）
  ├── 详细条件面板
  ├── 虚拟化网格
  └── 底部编辑条或右侧抽屉
```

只能有一个主滚动容器，不能嵌套两个独立滚动条。

### 12.2 方向状态

```ts
type FilterChromeState = "expanded" | "collapsed";
```

- scroll listener passive。
- rAF 合并事件。
- 累计移动超过 15px 才切换。
- 下滚收起详细条件，上滚恢复。
- 只动画 transform/opacity。
- 输入 focus、打开抽屉、键盘 Tab 进入时强制展开。
- 隐藏前不能让焦点停在不可见控件。

### 12.3 到底部编辑

可选底部 sticky 编辑条或右侧抽屉/窄屏 bottom sheet。必须有应用、清除全部、结果数反馈。打开编辑时背景结果不重新布局。

### 12.4 数据一致性

沿用 superSearchStore.requestSeq 丢弃旧响应；筛选改变时明确是否回顶部；分页稳定排序；loadMore 有上限和重试；虚拟 item key 用 asset.id。

### 12.5 测试

多条件超过一屏仍能浏览；上下滚动按方向收缩/恢复且不闪；到底部可编辑；应用后无重复/串页；focus 时可见；1366/768px 只有一个主滚动条。

## 13. 阶段 7：设置页宽屏布局

当前缺口：SettingsPage.tsx 的 max-w-xl 导致右侧空间浪费。

推荐：

```text
左侧导航 220~260px
右侧 flex-1
  ├── 内容最大宽 1040px（复杂模块可满宽）
  ├── 分区标题
  ├── 标签/说明列
  ├── 控件列
  └── sticky 保存栏
```

| 宽度 | 规则 |
| ---: | --- |
| <720px | 单列、导航可折叠、保存栏底部固定 |
| 720~1100px | 标签/控件两列，占满右侧 |
| >1100px | max 1040px，服务/模型/日志可双栏 |

取消无意义框中框；日志、模型列表、危险操作才使用边框。Field 增加 stacked/wide 变体。保存栏显示保存中、已保存、未保存、失败。验收 1440px 不再小框化；125% Windows 缩放无横向滚动；复杂 hint 不挤压控件。

## 19. 优秀案例借鉴与适用边界

外部案例只用于验证设计方向，不能替代当前项目的代码、数据和性能基线。执行 AI 必须把下面的“采用点”落到本项目已有分层中，并记录未采用项的原因。

| 案例/资料 | 可借鉴做法 | 本项目落地 | 明确不照搬 |
| --- | --- | --- | --- |
| Ollama Generate/Chat 官方 API | 每次原生请求显式传 `keep_alive`；空闲用 `keep_alive: 0` 卸载 | 阶段 2 的 L1/L2；请求 service 统一构造参数，finally 做卸载 | 不假设 `/v1` 兼容端点支持全部 Ollama 字段 |
| SnapSearch | 文本索引与视觉索引分开，查询时融合；索引 recipe 变化时告警而非静默重建；进度分阶段反馈 | 超级搜索以 FTS/标签分面为硬过滤，向量作召回/补充；记录 facet/schema 版本；批任务发阶段事件 | 不引入 FAISS、MiniLM、OCR 等新大型依赖，除非另立需求评审 |
| localOllamaRAG | BM25 + 向量召回后再融合/重排；模型角色按任务拆分；设置是单一持久化事实源 | 保留 SQLite/FTS5，先实现原子概念和 AND 过滤；设置从 store 到 DB 到 batch 一条链 | 不在本轮引入跨项目的 RAG、reranker 或多模型编排 |
| Sage 混合图像检索说明 | caption、向量、BM25、reranker 组合可提升召回与精度 | 将其作为长期演进路线；本轮先保证标签/颜色精确命中和可解释 chips | 不能用语义相似度覆盖明确的标签条件 |
| React/MDN 指针文档 | 用 `clientX/clientY` 配合 `getBoundingClientRect()`；处理 pointercancel 和 capture | Viewer 统一坐标函数、代际保护、清理 capture | 不以产物中出现 `offsetX` 字符串作为验收依据 |
| 搜索结果页 sticky/filter UX 实践 | 详细筛选区收起，摘要条保持上下文，快速编辑不打断结果浏览 | 阶段 6 的单主滚动容器、sticky summary、底部编辑条/抽屉 | 不制造嵌套滚动容器或高频 height 动画 |

调研结论：精确结构化条件必须先过滤，语义模型只负责理解和召回；本地模型生命周期必须有显式 ownership 和空闲策略；所有长任务都需要可观测进度和可清理资源。这三条是本轮跨模块实现的共同原则。
