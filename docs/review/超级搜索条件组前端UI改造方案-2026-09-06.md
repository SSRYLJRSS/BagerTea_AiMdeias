## 〇、总览

横排三张卡片大架构保留，按条件的三种「硬度」分工：



| 卡片       | 硬度  | 不满足会怎样   | 卡片内部形态                                |
| -------- | --- | -------- | ------------------------------------- |
| **必须满足** | 硬门槛 | 直接不出现    | 连接词分段（全部 / 任一 / N 项）+ 可嵌套条件组          |
| **优先满足** | 软排序 | 照样出现、排后面 | **有序清单，拖拽排序，越靠上越优先；无且 / 或、无权重、无匹配开关** |
| **排除**   | 硬否定 | 直接剔除     | 连接词分段（命中任一 / 全部命中），扁平不嵌套              |

两条贯穿全案的硬规则：



1. **一条条件严格只占一行**（字段 + 值同一水平线，下方不得出现第二行控件）。

2. 机器参数（含子标签、按词查、匹配模式、多标签任一 / 全部）**全部给合理默认且默认不可见**，收进标签选择浮层的「高级」折叠里。

## 一、前端现状盘点（事实）



* `SuperSearchPage`：AI 搜索框 + `FilterChips` + 折叠三胶囊（必须 N / 优先 N / 排除 N）+ Chevron；展开渲染 `QueryBuilder`；下方结果网格。

* `QueryBuilder` 现为 `md:grid-cols-3` 横排三卡，已部分落地递归组（VLeaf/VGroup、addGroup、MAX\_GROUP\_DEPTH、OpSegmented）。

* 数据层已具备：`QueryExpr=and/or/not/leaf` 递归树；`SearchPlanV3={filter,mustNot,should[],minimumShouldMatch}`；`types/queryExpr.ts` 已预留可嵌套 `BuilderRow(group)`；chips / 删除 / 计数 / 诊断本就按树路径递归。

### 现存问题



* **P-a 一条标签条件竖排 5 层**：①当 + 字段 ②只读 "是"+ 已选 chip ③「含子标签」整行下拉 ④「按词查（可选）」整行下拉 ⑤内嵌 "搜索标签 + 别名 + 长列表" 把卡片撑高；优先区还多一个「一般偏好」权重下拉。

* **P-b「含子标签 / 仅当前 / 同时满足」混合下拉**：把 "标签层级范围" 与 "多标签任一 / 全部" 两个正交维度塞进一个三选一。

* **P-c 诊断裸数字**：直接显示 `+110/−N`，无说明。

* **P-d 混合 AND/OR 旧扁平模型只读**：遇嵌套降级 "复杂条件（N 项）"。

* **P-e 优先区过载且自相矛盾**：优先是 "可以没有"，却出现权重三档、匹配开关、"至少 N 项才显示"（>0 即变硬门槛，与软排序矛盾）。

* **P-f 配完无总览**：缺一句人话回显。

## 二、总体布局



* 宽屏三卡横排（`grid-cols-3`），窄屏堆叠；等宽同高。

* 卡统一结构：`卡头（标题+硬度小标签+人话副句+右侧连接词控件）→ 条件/组列表 → 卡底添加按钮`。

* 用硬度小标签 + 颜色区分：必须 = 实心强调色「硬门槛」、优先 = 虚线中性「软排序」、排除 = 中性灰「硬否定」。

* 面板最下方加一条**实时人话预览**（§6.4）。

## 三、必须满足区（硬门槛）

### 3.1 卡头



* 标题「必须满足」+ 小标签「硬门槛」+ 副句「不满足就不显示」。

* 右侧分段三态：**全部满足（且，默认）/ 满足任一（或）/ 至少 N 项**（选 N 出现数字框，1… 条目数）。

* 下方白话随状态变化：全部都要满足 / 任意一条即可 / 至少满足 N 条。

### 3.2 递归条件组（解决 AND/OR 混合）



* 根组即卡片本身；每组底部：**+ 条件**（叶子行）、**+ 条件组**（嵌套子组）。

* 子组 = 浅底圆角缩进卡片，自带连接词分段 +「删除本组」；同级组之间画圆形「且 / 或」徽标，随父组连接词变化。

* 嵌套软上限 3 层，到层隐藏「+ 条件组」并提示；后端不限。

* 空组丢弃、单子组折叠、相邻同连接词拍平、重复去重，复用 `normalizeExpr`。

* 任意 QueryExpr 树 100% 递归还原为可编辑结构，删除 "复杂条件只读" 主分支；边角 `NOT(整组)` 渲染为 "整组取反" 只读小块（极罕见），`NOT(单叶)` 仍为行内取反可编辑。

### 3.3 行首连接词

每组首行前缀「当」，其后按该组连接词显示「并且 / 或者」，各组独立计数。

## 四、优先满足区（软排序・极简有序清单）

### 4.1 定位

优先条件也是去匹配的搜索条件，但**不设门槛**：命中往前排，不命中照样出现、排后面。它不是 "按时间 / 大小排序"，而是 "最好有这些特征" 的软匹配。

### 4.2 卡片形态（最终拍板，不做任何复杂开关）



* 卡头：标题「优先满足」+ 虚线标签「软排序」+ 副句「越靠上越优先，可拖动；一条不中也照样显示，只是排后面」。**右侧无分段控件。**

* 每行：`拖拽手柄 + 序号(1/2/3…) + 字段 + 值 + ⋯ + ×`，**严格一行**。

* 第 1 名序号强调色；手柄拖拽（或上移 / 下移按钮兜底）改顺序。

* **没有**行首 "当 / 并且 / 或者"、**没有**权重三档、**没有**模糊 / 精确开关、**没有**"至少 N 项才显示"、**没有**"含子标签 / 按词查"（同 §6 收进浮层高级）。

* 卡底仅「+ 添加优先条件」。

### 4.3 排序机制（用户只管顺序，后台自动）



* 用户心智：排第一的条件命中的图尽量最前；第一条打平再比第二条，依次往下。

* 数据映射（无感）：`should[]` 顺序 = 拖拽顺序；提交时**按位置自动生成递减权重**，UI 不编辑；`minimumShouldMatch` **恒 0**（保证不中也显示）。后端现有 should 加分 + 融合排序直接支持。

* 示例（优先：1. 竖构图 2. 黄金时刻）：两条都中→最前；只中第 1→其次；只中第 2→再次；都不中→**仍在结果、垫底**。

### 4.4 与必须区不重复

同一标签放必须 = 不满足不显示；放优先 = 都显示、命中靠前。字段清单相同，区别只在硬度；行尾 ⋯「移到必须 / 排除」即调整硬度。



***

## 五、排除区（硬否定）



* 卡头：标题「排除」+「硬否定」+ 副句「命中就不显示」；右侧两态：**命中任一（或，默认）/ 全部命中（且）**（放开现在写死的 OR；不给 N 项）。

* 一期扁平不嵌套（allowGroups=false）。

* 行内不设取反，避免双重否定。



***

## 六、单条条件行的微观设计

### 6.1 【硬规则】一条条件严格只占一行



* 定稿：`[行首连接词(仅必须区)][字段][值（自适应占满）][⋯][×]` **全部同一水平线，下方不允许第二行任何控件**。

* 现状 5 层逐项处置：


  * **删只读 "是"**：字段「包含标签」已含 "包含" 语义，不再单设运算符格。

  * **删「含子标签」整行下拉**：默认含子标签（选父标签自动带子孙），不提问；要关进浮层 "高级"。

  * **删「按词查（可选）」整行下拉**：手动条件不显示 termQuery（AI 专用），收进浮层 "高级"。

  * **内嵌搜索长面板改为点「＋选择」才弹出的 portal 浮层**，选完即关、不撑高卡片。

  * **优先区删「一般偏好」权重**（拖拽排序替代）。

* 其他类型同样一行：素材类型 `当 [素材类型][图片▾]⋯×`；数值 `当 [文件大小][大于▾][值]⋯×`（运算符与值内联同行）。

* 标签选很多时值区最多显示约 2 个 chip +「+N」收拢，不因此另起控件行。

### 6.2 运算符：能省则省，需要时与值内联同一行



* **标签类不设独立运算符格**：字段即「包含标签 / 不包含标签」（字段列表两项，或 ⋯ 菜单切换）；主行不出现第二个下拉。

* "多标签命中任一 / 全部" 不进主行、不与组连接词撞词：默认**命中任一**，"全部命中" 放浮层 "高级"。

* 文本：包含 / 不包含 / 等于 / 为空；数值日期：等于 / 大于 / 小于 / 介于；枚举：等于 / 属于任一。运算符与值**内联同一行**。

* 行内否定由 "不包含" 类运算符统一推导。

### 6.3 标签值：主行只有 chip +「＋选择」，其余进浮层



* 主行只显示已选 chip（单个可 ×）+「＋选择」虚线按钮，**再无别的东西**。

* 点「＋选择」弹 portal 浮层（浮最上层、不撑行、不被裁切、点外部即关）：

1. 顶部搜索框 + 分面分组勾选列表（现有能力保留，改为浮层）；

2. 底部**默认收起**的「高级：子级标签 / 按词匹配 ›」，展开才有：☑同时匹配子级标签（默认勾）、命中任一 / 全部命中、termQuery + 匹配模式（精确 / 别名 / 前缀 / 包含 / 纠错）；

3. AI 回填的按词查在主行只显示可删小胶囊「词：xx ✕」，不常驻输入框。

* 即：含子标签、多标签关系、按词查、匹配模式**全部合理默认且默认不可见**，普通用户只经历 "点选择→勾选→关闭"。

### 6.4 实时人话预览（兜底）

面板底部浅灰提示条，随配置实时生成，例如：

> 将显示：同时含【人物】和【海边】、或同时含【狗】和【草地】的素材；排除含【夜景】的；优先依次考虑【竖构图、黄金时刻】。
> 递归组、排除、优先顺序都要在句中体现；用户读这句话即可判断对错。

### 6.5 诊断数字收敛



* 平时不显示裸 `+N/−N`。

* 零结果时肇事叶子红字「这条把结果筛空了，点此移除」（保留 zeroing 逻辑）。

* 想看命中量：行尾 ⓘ hover 显示「单独命中 N 项・与其余条件交集 N 项」。

## 七、数据与状态映射（事实源不变）



* **必须 / 排除**：视图组树 ⇄ `QueryExpr` 递归互转（and/or/not/leaf 全覆盖），仍是 `plan.filter/mustNot` 唯一事实源。

* **优先**：`plan.should` 有序数组；拖拽 = 重排；weight 按位置自动生成、UI 不编辑；minimumShouldMatch 恒 0。

* **持久化**：仍只存 `SearchPlanV3` 到既有 localStorage 键；视图每次由 plan/expr 派生，沿用签名比对防回跳，不引入第二事实源。

* **跨区移动**：`moveConditionBetweenZones` 保留，叶子可在三卡间搬移（= 改硬度），按目标区规则参与。

* **chips / 计数 / 删除 / 诊断**：均已递归；诊断匹配由单层 \[index] 改为 "根→组→行" 下标链；折叠三胶囊计数不变。

## 八、完整操作示例（海边人像 或 草地狗；排除夜景；竖构图优先）

目标：`(人物 且 海边) 或 (狗 且 草地)`，排除夜景，竖构图、黄金时刻越靠前越好。



1. **必须卡**：分段切「满足任一」→ 两次「+ 条件组」。子组 1（组内全部满足）放 人物、海边 / 海滩；子组 2 放 狗、草地 / 草坪。选标签在浮层内勾选，底部 "匹配子级" 默认勾。

2. **排除卡**：保持「命中任一」，加 包含标签 = 夜景。

3. **优先卡**：「+ 添加优先条件」放 竖构图、黄金时刻；想让竖构图更优先就拖到第 1 行。全程不选任何权重 / 开关。

4. 底部预览句实时回显；结果按优先命中条数与顺序排序，未中优先的图也在、排最后。

* 对照：只找 "所有狗的图"，必须卡默认 "全部满足" 加一行 包含标签 = 狗 即可，三步完成，不建组、不碰优先。

## 九、分阶段落地（每阶段可独立上线）



* **P1 条件行减负（见效最快、纯展示、做减法）**：严格一行化、删 "是"、删含子标签 / 按词查 / 权重外露控件；标签值改 portal 浮层（高级折叠）；诊断收敛；加底部人话预览。

* **P2 必须区递归组 + 排除两态**：递归互转、子组增删改、3 层上限、删只读、补 "至少 N 项"、诊断 /chips/path 适配多层；排除放开 任一 / 全部。

* **P3 优先区有序拖拽清单**：删权重 / 匹配 /min 入口；拖拽手柄 + 序号；提交按位置自动 weight、min 恒 0；跨区移动保留。

> P1、P3 都是做减法、风险小、观感提升最直接，可先排；P2 是表达力核心。

## 十一、验收清单



1. 全 AND / 全 OR / 至少 N 项：必须区分段即得。

2. 混合 `(A且B)或(C且D)`：根 "任一"+ 两个 "全部" 子组，可增删改、刷新完整还原、不再只读。

3. **每条条件严格一行**：无第二行 "是"、无含子标签下拉、无按词查下拉、无内嵌长面板、优先区无权重下拉。

4. 标签行主行只有 chip+「＋选择」；含子标签 / 任一全部 / 按词查只在浮层 "高级" 里，且有默认值。

5. AI 产出任意嵌套树：直接渲染为可编辑组 / 行。

6. 排除区可切 命中任一 / 全部命中，行内无双否定。

7. 优先区无且 / 或、无权重、无匹配开关、无 "至少 N 项"；拖拽改顺序后排序随之变化。

8. 清空全部优先条件不影响结果 "是否出现"，只影响先后；优先两条都不中的素材依然在（min 恒 0）。

9. 底部人话预览随编辑实时正确，覆盖组、排除、优先顺序。

10. 平时无裸 +N/−N；零结果标红肇事条件可点除；hover 看完整命中说明。

11. 空组 / 单子组 / 相邻同连接词 normalize 后无空分组、无多余包裹、无重复。

12. 嵌套下零结果诊断能精确标到对应行；跨区移动后按目标区硬度正确参与，三卡计数与折叠胶囊一致。

## 十二、明确不做（已否决 / 砍掉，防止加回来）



* ❌ 一条条件占两行及以上；只读 "是" 占位格。

* ❌ 主界面外露「含子标签」下拉（默认含，收进浮层高级）。

* ❌ 主界面外露「按词查 / 匹配模式（精确 / 别名 / 前缀 / 包含 / 纠错）」（AI 专用，收进浮层高级）。

* ❌ 「含子标签 / 仅当前 / 同时满足」混合三选一下拉（拆成浮层内两个直白控件）。

* ❌ 内嵌常驻标签搜索面板（改为点「＋选择」弹浮层）。

* ❌ 优先区权重三档、模糊 / 精确开关、"至少 N 项才显示"（改拖拽顺序，权重后台自动，min 恒 0）。

* ❌ 优先区行首 "当 / 并且 / 或者" 与任何连接词分段。

* ❌ 裸诊断数字 `+N/−N`。

* ❌ 把 "优先" 折叠成 "排序偏好" 或与字段排序混为一谈：优先是软匹配条件，保留独立卡片。

* ❌ 排除区 "至少 N 项"、排除区嵌套子组（一期）。
