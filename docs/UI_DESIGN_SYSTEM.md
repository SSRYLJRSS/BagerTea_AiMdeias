# Bagertea UI 视觉与开发规范

## 设计目标

Bagertea 是摄影素材管理与 AI 打标工作台。界面应保持安静、克制、专业，让图片和标签内容成为视觉中心。避免使用普通后台常见的大量卡片、鲜艳色块、强阴影和过度圆角。

核心气质：暖灰画廊、墨黑工具、低饱和状态色、清晰的信息层级。

## 颜色

所有界面必须优先使用 `src/styles/theme.css` 中的变量，禁止在业务组件中新增无语义的灰色硬编码。

- `--color-bg`：页面基础背景。
- `--color-surface`：次级区域和安静的选中背景。
- `--color-surface-raised`：输入框、弹层和需要抬升的表面。
- `--color-surface-hover`：列表悬停和明确选中背景。
- `--color-text`：主要信息。
- `--color-text-secondary`：说明、日期、计数等次要信息。
- `--color-text-tertiary`：占位和极低优先级内容。
- `--color-accent`：主操作按钮，保持墨黑体系。
- `--color-status`：当前项、待确认和进度提示，只做小面积强调。
- `--color-danger`：删除、失败等危险状态，不用于普通的拒绝按钮默认态。

## 间距和几何

- 页面主要区块间距：16px。
- 区块内部间距：12px。
- 紧凑列表行高：32–36px。
- 侧栏宽度：素材库 224px，打标控制栏 252px。
- 控件圆角使用 `--radius-control`，列表项圆角使用 `--radius-item`。
- 不使用胶囊形主按钮；标签、状态角标除外。
- 阴影仅用于悬浮操作条和弹层，普通区块用细分隔线组织。

## 字体与清晰度

- Windows 桌面端优先使用 `Segoe UI` 和 `Microsoft YaHei UI`，保持系统原生 ClearType 渲染。
- 根字号为 15px；高密度工具界面的普通正文约 13px，辅助信息约 11–12px。
- 不全局启用灰度 `antialiased`，避免 WebView2 中的小号中文笔画发灰、发糊。
- 小号文字必须使用 `--color-text-secondary` 或更高对比度颜色；`--color-text-tertiary` 只用于日期、数量和占位信息。
- 正文默认使用 400 字重，区块标题和选中项使用 600；避免用极细字重制造层级。

## 信息层级

页面应遵循“页面 → 区块标题 → 内容 → 辅助信息”的层级。区块标题统一使用 `.ui-section-title`。不要为每个区块创建带圆角、边框和阴影的卡片。

## 侧栏

- 导航项统一使用 `.ui-nav-item` 和 `data-active`。
- 选中态必须同时包含：浅暖灰背景、较深文字、左侧 2px 状态线，不能只依赖颜色。
- 标签数量固定右对齐；父子级通过缩进和文字权重区分。
- 长列表使用细滚动条，轨道透明，不显示系统上下箭头。
- “管理、撤销”等辅助操作默认低强调，只在悬停或确认阶段增强。

## 打标工作台

固定阅读顺序：主图 → 缩略图轨道 → EXIF/状态 → 标签编辑区 → 确认操作区。

- 主图占据剩余空间，是页面视觉中心。
- 缩略图紧邻主图，当前项使用深色边框，状态由右下角小圆点补充表达。
- 标签分类名称固定宽度，标签内容自适应换行。
- “确认写入”是单张打标唯一主按钮；“拒绝”使用次按钮，默认不使用红色实心。
- 已确认状态以文字状态呈现，不伪装成可点击按钮。

## 控件与按钮

- 输入框和下拉框使用 `.ui-control`。
- 主按钮：深色实心，仅用于当前区域最重要的动作。
- 次按钮：透明或浅背景，用于取消、刷新、拒绝、恢复等。
- 危险按钮：仅用于不可逆操作，默认避免大面积红色。
- Focus 状态必须可见，不得通过 CSS 移除键盘焦点反馈。

## 开发约束

1. 新页面先复用主题变量和基础类，再考虑增加组件样式。
2. 同一语义状态不得在不同页面使用不同颜色。
3. 选中、禁用、错误不能只依赖颜色，必须配合文字、形状或透明度。
4. 保证 1366px、1920px 和窄窗口下无内容重叠；空间不足时优先折行或滚动，不缩小正文到不可读。
5. UI 调整不得改变现有业务数据流；结构重排应通过组合组件完成。
