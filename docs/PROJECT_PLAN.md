## 二、项目目标与成功标准

### 2.1 业务目标

1. 摄影/设计素材**集中托管**：总库/分库文件管理，入库即落库、可改名
2. **找得到**：3 万素材规模下滚动流畅、中文搜索即输即得、标签树导航
3. **打得快**：AI 云端打标 + 人工确认流，标签可自定义分类体系
4. **拿得出**：本地导出（未来网盘导出）

### 2.2 质量目标（每次交付必须满足）

| 维度 | 红线 |
|---|---|
| 稳定性 | `cargo test` 全绿 + `tsc --noEmit` 零报错 + `vite build` 通过，三关缺一不交 |
| 性能 | 缩略图解码走全局 imaging 引擎；JPG 320px 解码 ≤ 5ms；3 万素材滚动不卡（见 [PERFORMANCE.md](PERFORMANCE.md)） |
| 可维护性 | 分层解耦（commands→services→db），单文件单职责；**文档先行铁律**：先改文档再改代码 |
| 一致性 | UI 黑白灰、主 CTA 黑色实心/其余幽灵文字按钮；文档与实现不一致时以文档修正流程对齐 |

## 五、协作与维护机制

1. **文档先行铁律**：任何偏离文档的实现决策，先记 PROGRESS.md 决策日志 + 改 PRD，再动代码
2. **单一事实来源**：每类信息只有一份权威文档（见 [README.md](README.md) 文档地图），禁止多头维护
3. **版本节奏**：PRD 修订号随老板走查反馈递增（当前 v2.12）；决策日志只追加不修改
4. **交接保障**：[HANDOVER.md](HANDOVER.md) 覆盖环境搭建→启动→发布→应急全链路，新人按此可独立上手
